# Запись жестов, передача управления сценарию и видеостена

16 октября 2026. Установлен веб `f7b6f6c130e2a76bdbc1d065a861d3ed186edf42`
на 3015 и Tuna. API `27f3a61f` и APK `1.2.79-dev /10279` сохранены.
[Машиночитаемая приёмка](STUDIO-RECORDING-HANDOFF-DELIVERY.json).
[Общий план новых требований](../../design/CLIENT-STUDIO-PLATFORM.md).

## Исправлено и установлено

- Передача ввода сценарию сохраняет существующий прямой video/control peer,
  пока приходит native RELEASE. Ранее `taskHandoffId` выключал media peer раньше
  подтверждения и уничтожал маршрут этого подтверждения.
- Известный неподдержанный, прерванный или отменённый жест не останавливает всю
  запись. UI показывает отдельное сообщение, предыдущие действия сохраняются,
  последующие можно записывать. Неопределённый результат Android по-прежнему
  останавливает запись; команды не повторяются.
- Пауза после pointer-жеста отсчитывается от локального UP, отдельно от ACK.
  Сохраняются положительные интервалы от 1 мс; прежний явный предел 60 с остаётся.
  Это точность записанного расписания, а не гарантия фактического времени Android.
- Панель записи/проверки закреплена. Выбор другого устройства сбрасывает прокрутку
  списка, чтобы экран Android не оставался выше панели. На 390×844 нет
  горизонтального переполнения; кнопки доступны при прокрутке очереди.
- Видеостена больше не заполняет область пустыми слотами. Колонки ограничены
  фактическим числом выбранных устройств. Меню потока убрано с миниатюр;
  стену можно развернуть целиком, сохраняя смонтированные peer.

## Что проверено

Полный exact-source frontend CI выполнен локально: **172 набора /2529 тестов**,
0 ошибок и пропусков. Проверки типов, transport/package probes прошли.
На GitHub опубликован и прочитан обратно статус `Sphere Local / Frontend regressions`,
ID `56528836454`. Hosted Actions для этих коммитов не запускались; все прежние
workflow автоматически перенесёнными не объявляются.

Linux image содержит 26 страниц и 72 client assets. Замена только UI сохранила
45 остальных контейнеров, API, OTA-каталог и предыдущий UI image. Docker archives
не создавались.

На PH011 по обоим адресам выполнено из настоящего Chrome:

1. Завершён прямой свайп с native DOWN/MOVE/UP и подтверждением APK.
2. Кривой жест выполнен, явно пропущен форматом записи; запись продолжилась.
3. Следующий клик записан: в очереди два подтверждённых действия.
4. После Stop создано одно контролируемое задание Start→Sleep1500→Home→End.
   Все четыре шага завершились успешно; native RELEASE получен. До и после
   задания ровно один media peer, прямое видео сохранилось.
5. Проверены закреплённые кнопки и геометрия desktop1440×1000/portrait390×844.

В видеостене одновременно получены кадры PH030/PH025/PH011/PH010 напрямую.
При выбранных 8×8 отображаются четыре устройства, без пустых слотов и кнопок
поверх картинки. Native control OPEN не отправлялись. Fullscreen занял1000px
при viewport1000px; изменение представления не создало новых peer.
Скриншоты desktop/fullscreen/portrait просмотрены. Проверка portrait использует
изменение размера desktop Chrome, не физический телефон или mobile IME.

Все пять временных сценариев архивированы, их версии и задания сохранены для
аудита. Собственные браузерные контексты закрыты; пользовательские вкладки
не обновлялись и не закрывались.

## Воспроизведённые открытые дефекты

**Другой управляющий клиент блокирует сценарий.** На UI `f1a958ad` один клиент
открыл Studio, второй — прямой поток с native READY. Задание создано, но Android
вернул `device_input_busy`, status failed. Видео у обоих осталось direct.
Причина в исходниках: `DagRunner.execute` требует discrete input reservation,
пока другой shared participant держит continuous input. Это не исправляется
сохранением media peer. Android source/API в финальной поставке не менялись;
общий арбитраж viewer/task остаётся **P0**, а не принятой функцией.

**PH025 потребовал повтор ICE.** При запуске стены первая попытка истекла:
142 requests, 0 responses, 0 succeeded pairs; повторная дала direct video.
Поэтому для четырёх окон создано пять media peers. Нельзя заявлять соединение
с первой попытки или отсутствие всех reconnect. Физическая причина потери
ответов не установлена; адреса и кандидаты остаются в приватном отчёте.

**Полные траектории не реализованы.** Текущий формат экспортирует прямой
монотонный свайп/hold до10с и1024точек. Кривые и out-and-back не заменяются
ложным прямым свайпом; они явно пропускаются. Нужны новый action contract,
native path executor и capability gate старых APK.

**Стена пока принимает полноценное видео.** Это поставка компоновки, не
0.2–1FPS preview. Понижение общего encoder ради стены сломало бы качество
другого полноэкранного зрителя; нужен отдельный preview producer на APK.

Открыты также запуск несохранённого графа, rich XPath/pixel/crop bundles,
синхронизация аккаунта, AI authoring gateway, универсальные игровые ресурсы,
файловый менеджер, VPN provider matrix и hot plugin lifecycle. Они собраны
с критериями в общем плане. Исторические41открытый пункт не закрыты этой
поставкой. Нагрузка20клиентов, физический hotspot, длительный SLA и gameplay
не приняты. APK79 ранее подтверждён по хешу на четырёх доступных устройствах;
17offline не обновлялись в этом этапе.
