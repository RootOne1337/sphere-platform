# Общая временная шкала записи и повтора · APK82

Установлен APK `1.2.82-dev / 10282` (Android source `e3a34b2e`) на четырёх включённых устройствах, package SHA и завершённые OTA подтверждены. UI/API `15ce2b62` работают на3015/Tuna; их код и контейнеры в этой поставке не менялись. [Машинный отчёт](POINTER-TIMELINE82-DELIVERY.json), [формат и правила](../../operations/POINTER-PATH-RECORDING.md).

## Изменение

APK81 уже сохраняет весь DOWN/MOVE/UP одним `pointer_path`, но запускал отдельный native helper для каждого жеста. Его startup/cleanup и относительная пауза после ACK удлиняли промежутки между жестами.

APK82 переиспользует один helper для последовательных path/sleep. Межжестовая пауза отсчитывается от запланированного UP; ACK и служебная обработка DAG не прибавляются к ней заново. У каждого жеста собственный downTime. Во время паузы передаётся только heartbeat, без дополнительных касаний. Другое действие завершает эту серию до использования другого адаптера.

Результат содержит timeline_offset_ms, start_lateness_ms и helper_reused. Конец задания, отмена и ошибка закрывают helper до возврата ручного ввода. Неизвестное освобождение блокирует новый ввод; опоздание более100мс останавливает серию, просроченные точки не исполняются пачкой. При явной паузе между нодами idle helper закрывается; пауза внутри пути/его timed gap прерывает серию.

В трёх случаях record сохранены ровно две траектории и один sleep. Второй native результат подтверждает переиспользование helper и точный плановый offset: длительность первого пути плюс сохранённая пауза. У двух зрителей сохраняются direct media peers, кадры продолжают приходить, после задания возвращаются manual READY и подтверждённый Home. Ошибок страниц не было. Собственные сценарии архивированы, контексты закрыты; скриншоты записи и восстановленного видео просмотрены.

До установки82 отдельная проверка на PH030 с APK81 и свежим вебом также записала62 и25точек (14001/5958мс), пауза1517мс. Это отдельное доказательство работоспособности recorder в этом сеансе; оно не заменяет проверку нового executor82 и не опровергает прежние пользовательские сбои.

## Проверки и поставка

- 196 целевых Android тестов без failures/errors.
- Полная свежая сборка: dev и enterprise по1250tests,0failures/errors,3skipped; lint и assemble прошли. Подпись сверена с пилотным baseline, производные build-выходы не переиспользовались.
- Backend/Frontend код не менялся: прежние exact-source проверки15ce —4178passed/11skipped/551subtests, coverage82,01%;174frontend suites/2558tests, типы и packaged probes. Они не выдаются за новый запуск на другом source.
- КанарейкаPH011 проверена до выдачи OTA остальным. Все четыре текущих installed package hashes совпали с новым подписанным артефактом. Offline устройства исключены; обычный Android release-канал сохранён.

Проверки выполнены локально с GitHub commit statuses. При этом прежние hosted workflow тоже запускались автоматически: обнаружено, отключены восемь активных YAML-workflow, все девять теперь неактивны, три незавершённых запуска отменены. Предыдущее утверждение об отсутствии hosted запусков было неверно; [исправление и границы CI](HOSTED-ACTIONS-DISABLED.md). Автоматическая локальная очередь на каждый push и полный перенос CI ещё не приняты.

## Границы

Опоздание измеряется перед native send, а не до реакции приложения/нового видеокадра. Запись хранит предложенные браузером точки; DOWN/UP подтверждены, промежуточные MOVE могут объединяться транспортом. Это не доказательство одинакового состояния игры при повторе.

Конечные проверки PH011/PH030 не являются SLA для всех сетей и нагрузки. Джиттер под нагрузкой, мультитач, запись игровой клавиатуры, rich XPath/pixel/crop evidence и остальной продуктовый backlog остаются открытыми. Нейромодель не скачивалась и не запускалась.
