# Холодный запуск управления: согласованные сроки браузера и APK78

16 октября 2026. Дополнение к [разбору PH030](PH030-STARTUP78-RECOVERY.md).

## Проблема и изменение

APK78 устранил постоянную блокировку после startup-отказа без единой попытки ввода.
При этом у браузера оставался собственный предел ожидания 6 с. Root pipe может
израсходовать 5 с на READY, 2 с на cleanup и до 250 мс на reap; известный отказ
ещё не успевал вернуться, когда браузер уже закрывал control participant.

UI `982b2240` ждёт startup до 8 с, продолжая keepalive каждые 500 мс. Это отдельный
режим до native READY: клики и клавиши в нём не допускаются. Интервал остаётся
меньше lease 1500 мс старого APK. Перед deadline остаётся максимум 15 keepalive
квитанций в очереди из 32, поэтому первый DOWN/UP после позднего READY помещается.

После READY keepalive снова идёт каждые 250 мс; сроки native ACK для рабочих команд
сохранены: 500 мс legacy и 1250 мс shared. Срок idle ACK, ограничение очереди,
capture/session binding, запрет replay и строгая обработка UNKNOWN не ослаблены.
Это устранение преждевременного закрытия в браузере, а не измерение причины
первоначальной задержки app_process/su на PH030.

## Проверки и поставка

262 целевых теста проверили поздний READY, известный отказ после полного native
бюджета, отсутствие ввода до READY, вместимость первого клика и прежние рабочие
deadlines. Полный локальный frontend CI: 172 suites / 2511 tests, без failures/skips,
плюс TypeScript, action contract и проверки транспорта/упаковки. Результат привязан
к точному commit `982b22408d941d6db8e10927bcdd2dc17664ba3c` в GitHub.

Новый локальный путь упаковки проверен 31 Python-тестом, включая существующий
hosted admission. Образ построен из canonical Git context с Linux-зависимостями,
проверен в отдельном read-only контейнере: 26 страниц, 72 JS/CSS-ресурса. Архивы
Docker не создавались, hosted Actions не запускались.

Установленный образ: `sha256:393cc549abbf676a4f042700ee5f02845dda3e9ce08754d635c46b3fdbe724ba`.
UI обновлён на 3015 и Tuna; API `27f3a61f`, APK78 и остальные 45 контейнеров
сохранены. Каталог OTA не изменён, предыдущий UI image оставлен для rollback.

Браузерные результаты и точные конечные границы —
[INPUT-STARTUP-WEB-DELIVERY.json](INPUT-STARTUP-WEB-DELIVERY.json).
Локальный двухклиентный прогон прошёл: 12 одновременных раундов, четыре системные
кнопки у каждого, 30 с наблюдения, кнопка у оставшегося участника. На обоих адресах
прошла отдельная доставка native READY с задержкой около 7,25 с: до неё opening,
после неё ready и подтверждённый Home без смены peer или повтора команды.

**Tuna two-client soak не прошёл.** Клики и кнопки подтвердились, затем оба peer
пересоздались после SIGABRT Android APK78 в RateUtilizationTracker, 02:46:09 UTC.
Это не успешная общая приёмка туннеля. [Нативный инцидент и кандидат APK79](NATIVE-HEADROOM79-INCIDENT.md).
Проверки используют отдельные обычные Chrome contexts; пользовательская вкладка
PH030 не перезагружается принудительно. Загруженный ранее JS меняется при обычном
обновлении вкладки, а не при одной замене контейнера UI.

## Что остаётся открытым

Физическую причину первого root READY timeout ещё нужно измерить. Контролируемая
задержка доставки READY в браузере проверяет lifecycle, а не скорость реального root.
Общий тест 10–20 клиентов, смена физической сети и универсальный latency SLA этим
этапом не приняты. Состояние APK: четыре completed OTA78, три проверенных package
SHA, PH030 — completed/версия/native READY с отдельным непроверенным package hash;
17 выключенных устройств не обновлены.

Headless 0.2 остаётся capture/native-idle транспортом без модели и игрового ввода.
Этот UI-only этап не добавляет профиль удержаний, multitouch, GPU benchmark или
gameplay acceptance. Полный автоматический перенос всех workflow в локальный CI
также не объявляется завершённым.
