# APK79: нативный поток и совместное управление

16 октября 2026. Конечная поставка после [измеренного SIGABRT APK78](NATIVE-HEADROOM79-INCIDENT.md).
Точная машиночитаемая [квитанция](NATIVE-HEADROOM79-DELIVERY.json) содержит хеши сборки,
установленных пакетов, приватных исходных проверок и состав действующих контейнеров.

## Что исправлено

Внутренний RateUtilizationTracker SDK аварийно завершал процесс при регрессе своего времени
на 42 мкс. APK79 включает поддерживаемый legacy путь bitrate utilization во всех direct
PeerConnectionFactory. Адаптация битрейта сохраняется; capture/RTP timestamps и сроки
подтверждения действий не изменены. Команды не повторяются. Причина регресса времени
ещё не доказана; конечный прогон подтверждает результат обхода этого аварийного участка.

Source `9c9ef56cd3ef487b4fa19010ff9b8b5a68748445`, Android tree `116c866ff2f8e893365554bd570f4d4c2abc2105`.
APK `1.2.79-dev /10279`, SHA256 `31c61aa8d38ea9f46074138e0cdd55bbbffac49e63320681954cd1a7e3576942`.
Подпись совпадает с прежним pilot пакетом. Зависимость WebRTC 146.7.0 сохранена;
точные upstream исходники и переключатель разобраны в документе инцидента.

## Проверка на PH011

Два отдельных обычных Chrome-контекста, один с настоящими CDP touch events:
12 раундов одновременно с mouse-клиентом. У каждого DOWN/UP есть applied либо явный
interrupted при перехвате новым нажатием; неизвестные результаты не скрывались.
Назад, Домой, Недавние и Меню получили по 4 native APPLIED на клиента.
После закрытия первого клиента второй подтвердил пятый Home.

Оба адреса прошли конечную проверку: локально 30 с наблюдения после команд, через Tuna 300 с.
В каждом клиенте оставался один основной peer, кадры продолжали приходить,
управление оставалось READY. Серверных input-команд и page errors не зарегистрировано.
PID APK до и после каждого прогона совпал; сохранённый logcat охватывает начало окна,
связанных native fatal событий в нём не найдено.

PH030: существующий пользовательский сеанс наблюдался без создания второго viewer и без команд; из 15 срезов 5 показали direct video/control READY. Конечное окно READY подтверждено: да. Сначала наблюдались idle_receipt_timeout и native_startup_busy, затем новый viewer-сеанс достиг READY. Версия JS вкладки и отсутствие пользовательского F5 отдельно не подтверждены; быстрое автоматическое восстановление не принято.

Дополнительно headless worker 0.2 проверен на APK79 без браузера: за 15 с декодировано 873 кадра,
выбрано 75 RGB-наблюдений (4,999 Гц), server→worker media с запуска — 0 байт.
Native admission, 49 idle ALIVE и CLOSE подтверждены. Кадр Android 960×540 просмотрен визуально.
Это проверка транспорта; pointer/key/text worker не отправлял, inference не выполнялся.

## Что остаётся открытым

- Первопричина внутреннего SDK clock regression и холодной задержки root READY.
- PH030 после OTA сначала потерял управление; следующий viewer-сеанс заработал. Причина задержки восстановления и роль reload ещё не установлены.
- Длительная нагрузка 10–20 клиентов, физическая смена сети, доказанный LAN/localhost маршрут и latency SLA.
- Доставка на 17 выключенных устройств; версия и completed OTA не приравниваются к прочитанному package hash.
- Модель, игровой профиль/multi-touch, headless action executor, GPU benchmark и gameplay.
  Модель не скачивалась и не запускалась. Headless admission не доказывает выполнение игровых действий.

Исторический неудачный Tuna-прогон APK78 и его красный runtime status сохранены.
Общая production-приёмка этим документом не объявляется.
