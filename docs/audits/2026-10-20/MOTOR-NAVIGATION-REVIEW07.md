## Сделано в коде

Worker0.6.1 добавляет `acceptedResultTiming` для shadow и opt-in stick policy:
число принятых ответов по полным1-с окнам, минимальное число в окне, ведущую/конечную
тишину и интервалы результатов, возраст исходного receiver frame при ответе.
Первый валидный offer начинает измерение; stale/foreign/expired результаты в него не входят.
Percentile tail ограничен128 значениями; lifetime min/max не теряются после вытеснения.
Закрытие замораживает время до очистки provider. Это не меняет input authority или сроки ввода.

Добавлены7 отдельных timing tests и1 integration assertion test policy lifecycle.
Проверки различают средние5Гц с пустой секундой, полный/неполный bucket, warm/trailing gap,
предел памяти, заморозку, clock reversal, недопустимые числа и исключение позднего ответа.
Один прежний real-time integration test в повторе получил6 вместо требуемых7 ответов
за1.8с. Его окно увеличено до2.6с, минимум повышен до8; добавлена проверка медианного
интервала<320мс, отличающая исправный цикл от прежних400мс. Проверка единого DOWN/MOVE/UP,
CLOSED и max receiver age400мс сохранена. Игровые deadlines не увеличивались.

Итог:153 motor tests и Ruff прошли. Отрицательный промежуточный прогон сохранён отдельно
в локальных evidence; он не засчитан как успешная проверка.

после этого изменены только проверки неправильных чисел/обратного времени, версия и tests.
Полный153-test прогон относится к итоговому коду; GPU benchmark не называется запуском
последующего Git commit, которого в тот момент ещё не существовало.

## Уточнения по готовности

- 5Гц — разумная начальная **проверяемая цель** для малой скорости, а не гарантия вождения.
  Удержание между кадрами уже предусмотрено, однако strict5-per-complete-second не выполнен.
- NitroGen не получает явную цель; локальная P2P использует нулевой text embedding.
  Поддержка текста upstream не означает готовый goal path в нашей stdio-v1.
- Маркер за препятствием не задаёт проходимый путь. Нужны GPS polyline/локальное восприятие,
  прогресс, speed/lookahead, obstacle/recovery skills и vehicle input calibration.
- 20мс RTT не отменяют capture/inference/sampling delay. При5Гц до200мс может уйти только
  на ожидание наблюдения; автоматическая адаптация модели к пингу не подтверждена.
- 2–3Гц требуют отдельного профиля: текущий executor допускает≥4Гц и имеет короткие TTL.
- Source/action clocks, native multi-touch/gamepad, ownership/ACK failures PH030 и длительная
  стабильность остаются открыты. PH025 video-only успех не закрывает эти gates.

## Источники и следующий этап

Повторно проверены upstream NitroGen/P2P, их issues, Cradle navigation skill, реальные
GTA driving проекты с разграничением pixel/native и real-time/paused inference.
Компактные Qwen3.5-2B/Gemma4E2B/FastVLM добавлены к прежнему shortlist для редкого semantic
planner. Они не скачивались и не запускались; NVIDIA3070M/5050Laptop здесь не измерены.
Проверены официальные Amnezia split-tunnel ограничения; настройки сети не изменялись.
Прямые ссылки, конкретные выводы и очередь N1–N6 собраны в разделе22 единого документа.

Приоритет: устойчивость ownership/ACK и временные контракты → cadence на нужной GPU →
vehicle controls → GPS-route baseline → препятствия/recovery → повторяемые A→B испытания.
Веб5cbb/API15ce/APK83, настройки VPN, игровые аккаунты и backend не обновлялись этим этапом.
