## Что добавлено в основной код

[`NavigationSupervisor`](../../../motor_worker/navigation.py) — ограниченный supervisory layer:

- Проверяет receiver freshness, epoch/порядок наблюдений, native readiness и scene contract.
- При известном расстоянии оценивает его уменьшение; движение камеры не заменяет прогресс.
- Без расстояния может обнаружить неподвижный фон, но не доказывает достижение цели.
- При supplied fallen state ждёт подтверждённого standing; после6с без него останавливается.
- Выдаёт operation ID для осмотра камеры, затем допускает один calibrated low-obstacle jump
  либо detour по уже оценённой свободной стороне. Unknown geometry не разрешает эти действия.
- Ждёт подтверждения операции; unknown outcome не повторяет. Бюджет восстановления ограничен.
- Потеря метки означает остановку, не автоматическое «прибыл».

Это не classifier падения, не распознавание зданий и не законченный navigation executor.
Scene/low obstacle/free side пока должны поступать из проверенного perception adapter либо
от оператора. Автоматическое подключение этих директив к waypoint runner ещё требуется.

[`PointerSequence`](../../../motor_worker/pointer_sequence.py) задаёт конечные последовательные
жесты: два DOWN/UP с интервалом либо один camera drag с release. Caller сохраняет exact native
ACK, freshness и cleanup; reservation не повторяется при неизвестном результате.
Задержавшийся tap не проигрывается догоняющей очередью. Перед сменой пальца движение освобождается.

Новый optional [`requirements-motor-vision.txt`](../../../requirements-motor-vision.txt)
фиксирует OpenCV headless4.13.0.92, совместимый с установленным NumPy2.4.4; `pip check` прошёл.
Sensor использует feature tracking по фону, исключая HUD/контролы/центрального персонажа.
Отсутствие достаточной текстуры даёт unknown. Это не оценка глубины или семантики препятствия.
[API optical flow](https://docs.opencv.org/4.13.0/dc/d6b/group__video__track.html).

## Текущее native-ограничение

`RootTouchBridge` создаёт MotionEvent с pointerCount=1. `SharedPointerArbiter` допускает несколько
участников, но держит один native pointer и отменяет его при takeover. Поэтому несколько peers
не являются способом получить stick+camera+jump одновременно.

Доступные сейчас последовательные операции полезны для калибровки/осмотра, но не заменяют
новый capability-negotiated multi-contact protocol, root pipe/executor, coordinated cleanup
и совместимые изменения клиента/APK. Статус multi-touch остаётся открытым.

## Что проверено и почему нет положительного game-теста

Полный motor suite:122 теста прошли, в том числе проверки задержанного/неизвестного ACK,
неповторяемых tap edges, ложного прогресса камеры, missing target, fallen timeout, unknown free side,
bounded recovery и optical flow на синтетическом смещении/двигающемся avatar mask. Ruff прошёл.

На PH011 native PNG показал явное сообщение об отключении игры за бездействие. Выполнены два
полных закрытия/открытия с паузами более20с, затем один reboot Android через Sphere и запуск игры.
Данные игры не очищались. Остальные эмуляторы не перезапускались. Прямой поток после reboot вернулся.

Black Russia осталась на «Подключение к серверу»; native screenshot совпал с этой сценой в потоке.
Причина загрузки не локализована. В guest world мы не вошли, поэтому прыжок/камера/обход не приняты
по живому результату. Root game log не дал диагностического объяснения; raw logs оставлены локально.

Подготовленный private calibration runner проверяет присутствие run-button HUD по reference image.
Self-test отличил настоящий gameplay HUD от loading. Последующий6-с read-only guard опыт подтвердил
прямые кадры/native ALIVE/CLOSED, ноль физических действий и ноль серверных media bytes. У него
physical execution был явно выключен; это не положительная калибровка прыжка или камеры.

Следующая проверка требует активного игрового мира: сначала отдельные double tap и camera drag
с видео до/во время/после, затем проверенная классификация сцены и низкого препятствия, integration
recovery executor и маршрут с контролируемым препятствием. Здания, транспорт, отдельная GPU/LAN,
multi-touch и автономный gameplay остаются непринятыми.
