# Обычная подготовка новой записи без ручного исправления

Проверка 29 октября 2026 года. Критерий пользователя: новая запись проходит
обычный путь веба, сервер сам восстанавливает камеры и готовит ориентиры.
Успешная отдельная экспериментальная реконструкция этого не доказывает.

## Как проверяется первый запуск

`scripts/pilot/check_route_first_run.py` поднимает настоящий production HTTP
handler в отдельном loopback-порту с отдельным каталогом заданий. Клиент один
раз создаёт задание, передаёт пять исходных файлов блоками по 1 MiB и один раз
вызывает `/start`, как `TeachingReconstruction`. Дальше разрешены только GET.
`/navigation/prepare` клиент не вызывает: это обязанность монитора сервера.

Используются обычный AMD-интерпретатор реконструкции и тот же CPU-интерпретатор
экспорта, что у локального сервиса. Маска определяется исходным объявлением
скрытого HUD. Нет ручного выбора модели, принятия экспериментальной ревизии,
исправления поз, подстановки маршрута или журнала клавиш.

До и после успеха сравниваются SHA пяти исходных файлов, ключевых модулей
рецепта, геометрии и квитанции. Требуются все выбранные камеры, отсутствие
резких обратных скачков и выбросов скорости, одна автоматическая попытка
навигации и её статус `ready`. Любая неопределённость остаётся отказом.
Повторное использование каталога намерения запрещено. Проверка не подключается
к Android и не посылает управляющих команд.

Сбой чтения с кодом 503 допускает только повтор GET. Создание, передача,
`start` и подготовка не повторяются. Завершённый отказ по качеству сохраняется:
тест больше не подменяет его отменой уже закончившейся задачи.

## Найденные ошибки и изменения

1. `SparseRoute` запрещал любой соседний шаг меньше `1e-6` единицы SfM. У
   `fuflo228` такие шаги действительно есть в начале: около `2e-7` и `9e-8`
   в двух разных реконструкциях. Это корректный случай паузы перед движением,
   а не основание отклонять весь проход. Теперь сохраняются все ракурсы и их
   исходные времена; полностью неподвижный маршрут по-прежнему недопустим.
2. Поиск ближайшего участка и пеший pursuit пропускают неподвижные сегменты
   при делении и выборе цели. Масштаб коридора рассчитывается по движущимся
   шагам. Паузу нельзя использовать для обнуления этого масштаба. Все ограничения
   свежести, PnP, неоднозначности, остановки и подтверждения финиша сохраняются.
3. Любой файловый `PermissionError` мог стать HTTP 403. Теперь только отказ по
   origin/Host/capability возвращает 403, а отказ файловой системы — 503 с
   фиксированным сообщением без раскрытия пути. Причина единичного старого 403
   в реальном прогоне не установлена; новый контракт проверен инъекцией отказа.
4. Бюджет измеряемых видеотреков увеличен с 960 px / 1000 углов до
   1280 px / 2000 углов. Размеры меньше исходника не увеличиваются. Извлечённые
   RGB, запись, обычные игровые окна и runtime RootSIFT 960×540 не меняются.
   Проверка LK вперёд/назад, идентичности треков и разрыва видео остаётся прежней.

Остановка персонажа в записи не означает, что автоматизация должна ждать то
же число секунд. Управление остаётся обратной связью по свежей позе, без макроса.

## Отброшенные эксперименты

Проверялись восстановление пропущенных камер по существующим 3D-точкам,
закреплённые позы с дополнительной триангуляцией, инициализация со стороны
конца и выбор углов по 8×4 областям изображения. Уменьшение порога PnP само
по себе не восстановило весь хвост. Обратная инициализация не получила
подходящей начальной пары.

Распределение треков по сетке используется, например, во фронтенде
[OpenVINS TrackKLT](https://docs.openvins.com/classov__core_1_1TrackKLT.html).
Однако наш конкретный вариант на реальном `fuflo228` ухудшил результат до
99/155 камер и двух компонент вместо 149/155. Он удалён из обычного алгоритма,
даже несмотря на успешные синтетические тесты. Эти пробы не приняты как
улучшенные данные и не подменяют основную геометрию.

## Границы подтверждения

`ready` означает, что данные подготовлены для проверки, а не пройденный живой
маршрут. В этой проверке нет независимого положительного нового геймплея,
измеренной ошибки в метрах, карты столкновений или гарантии A→B. Наличие полного
видео не делает все его позы наблюдаемыми: нужны устойчивые соответствия и
параллакс. Неудачные участки нельзя объявлять правильными, сгладив линию.

Первый запуск на двух сохранённых видео проверяет повторяемость общего
обработчика. Он не доказывает идеальную реконструкцию любой будущей записи.

Это количество **выбранных опорных ракурсов**, а не отдельных поз каждого
видеокадра. Видеотрекер проходит все 1387 и 915 исходных кадров соответственно.
Больше точек и меньшая внутренняя ошибка не доказывают метрическую точность.

Финальный пеший запуск сам подготовил 4096 runtime-ориентиров на интервале
0–50,349 с, без пропусков начала и конца. Минимум в опорной окрестности —
61 точка при требовании 24, ноль пустых ракурсов и временных выбросов.
Подтверждены один клиентский `/start`, ноль `/navigation/prepare`, одна
автоматическая попытка; исходные файлы и 13 ключевых модулей рецепта не менялись.

Финальный скутерный запуск также автоматически экспортировал 4096 ориентиров.
Отказ на начальной паузе устранён, но путь всё ещё не принят: восстановление
заканчивается на 31,791 с при конце записи 33,258 с. Последние 1,467 с не
охвачены; две последние опорные окрестности содержат 16 и 8 точек вместо 24.
Статус — `route_map_has_unobserved_sections`, а не падение десериализации и
не ошибка памяти. У этой завершённой попытки нет ни одного файла `CANCEL`.
Качество исходной записи этим отказом не признано плохим: недостаточны связи,
которые извлёк **текущий алгоритм**. Весь этот проход остаётся открытой задачей.

Запуски выполнены в изолированных хранилищах теста. Их результаты не выданы
за выбранные пользователем старые попытки в библиотеке. Старые геометрии и
исходники не перезаписываются. Новые задания веба используют обновлённый
обработчик. Главный API на `127.0.0.1:3342` обновлён: health 200, запрос без
ключа 403, SHA существующих геометрий и исходных манифестов сохранены.
Установленный веб `route-temporal-20261029-v5` не менялся.

Проверки исправлений: 78 pytest и 73 unittest прошли. В pytest остаётся прежнее
предупреждение `Unknown config option: asyncio_mode` при отключённых плагинах.
Проверены паузы в начале, середине и конце, сохранение времён, отсутствие
деления на ноль, отклонение полностью неподвижной карты, прежние условия
остановки, HTTP-доступ и сохранение причин завершённого отказа.

Итоговые измерения и привязки находятся в
[`first-run-automation-delivery.json`](first-run-automation-delivery.json).
