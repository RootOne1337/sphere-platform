## Подтверждённые проблемы

| До изменения | Основание | Исправление |
| --- | --- | --- |
| «Сессия создана» равнялась сегодняшней дате | `new Date()` в JSX; API не предоставлял начало сессии | Даты создания аккаунта и последнего входа берутся из `GET /auth/me`; отсутствующие даты остаются неизвестными |
| Email всегда считался верифицированным | Безусловный VERIFIED; в `UserResponse` нет признака подтверждения email | Убрано неподтверждённое утверждение |
| Вкладка MFA показывала «не настроено» после загрузки даже при включённой защите | Локальный шаг всегда начинался со `status`, вёрстка не учитывала серверный флаг | Текущее `mfa_enabled` читается из `/auth/me`; ошибка обновления отделена от предыдущего снимка; изменения заблокированы без подтверждённого профиля |
| Ошибка списка API-ключей выглядела как отсутствие ключей | `data = []`, отсутствие `isError` | Пустой ответ, загрузка, отказ API и неверный формат ответа имеют разные состояния; предыдущий список сохраняется с предупреждением |
| Создать ещё один ключ можно было сразу после успешного создания первого | Форма создания оставалась рядом с одноразовым значением | После receipt форма заменяется выдачей ключа; синхронный guard и `retry: false` не допускают двойной отправки/автоповтора |
| Отзыв ключа и отключение MFA выполнялись сразу по клику | Прямой `mutate()` | Диалог объясняет область и последствия; отмена не вызывает API; ошибка сохраняет диалог |
| Copy показывал успех до завершения Clipboard API | Promise `writeText()` не ожидался | Успех только после fulfilled write; отказ отображается без ложного «Скопировано» |
| Пустой массив permissions назывался full-access | Неподтверждённое толкование серверного массива | UI показывает полученные scopes либо «Список разрешений пуст» |

## Итоговое поведение

Страница использует общие токены Sphere, карточки и Radix tabs/dialogs: три русскоязычных раздела,
адаптивные строки профиля, карточки ключей с датами использования/истечения, перенос длинных
идентификаторов, подписи полей, клавиатурная навигация и встроенные ошибки действий.
Сводка различает личный профиль и ключи организации. Список ключей запрашивается только при
открытии соответствующего раздела. Профиль опрашивается раз в минуту; время успешного HTTP-ответа
показывается отдельно от времени входа пользователя.

Существующие backend endpoints сохранены: `/auth/me`, `/auth/api-keys`, `/auth/api-keys/{id}`,
`/auth/mfa/setup`, `/auth/mfa/verify-setup`, `/auth/mfa`. Права проверяет сервер.
Новые ключи используют прежние значения permissions/expiry по умолчанию; новый редактор scopes
не добавлен. Установка TOTP секрета подтверждается шестизначным кодом; Redis pending secret
в backend живёт 300 секунд. При выходе из вкладки setup-данные очищаются из UI.
Одноразовый API-ключ очищается при закрытии диалога; secret-bearing mutations имеют `gcTime: 0`
и сбрасываются после завершения просмотра. Секреты не записываются в storage или документацию.

Это собственная реализация Sphere на текущих компонентах. Исходники/ресурсы AdminCN и Studio Admin
не копировались; прежние [лицензионные сведения](../../design/previews/admincn-sphere-2026-09-28/THIRD-PARTY-NOTICES.md) сохранены.

   новых полей каталога/мониторинга и `/health/build`.

4. Принимать реальные изменяющие действия и streams отдельно от read-only browser render.
   Масштаб 20–30, затем 500–1000 устройств не подтверждается этими UI-тестами.
