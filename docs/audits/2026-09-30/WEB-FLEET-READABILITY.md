## Подтверждённый дефект

Авторизованный браузер на `3012/devices` со сборкой `80e981e3` и настоящим pilot API
показал свежий `last_heartbeat` рядом с Online, но прочерк в «Последнем сигнале»:
эта колонка читала только `last_seen`. Android/model/agent помещались в одну
обрезанную строку; состояние и heartbeat тоже обрезались. При отсутствии
`connected_since` UI без основания называл сессию подтверждённой.

## Изменение

- Модель и имя отделены от самостоятельной колонки Android / агент; версия агента
  видна без наведения. Повторный префикс `Android Android 9` нормализован.
- Состояние показывает длительность только по валидному `connected_since`.
  Если начало не сообщено, UI прямо сообщает об этом и не выдумывает uptime.
- «Heartbeat / контакт» использует валидный `last_heartbeat` первым. Если его нет,
  показывает `last_seen` с отдельной подписью «Контакт». Это разные источники,
  общий контакт не выдаётся за heartbeat. Нет валидной даты — нет данных о сигнале.
- Возраст пересчитывается раз в 15 секунд; абсолютное время имеет дату и UTC.
  Некорректные и слишком будущие timestamps не считаются доказательством сигнала.
- Основная ширина колонок — 934 px; строки — 84 px с виртуализацией. Доступ,
  игровой сервер и теги доступны через русскоязычное меню колонок и скрыты
  по умолчанию, чтобы главные сигналы помещались на обычном desktop.
- Выбор строк, сортировка, инспектор и контекстные действия используют прежние
  handlers/API. Новых запросов на устройство или измерений ping/FPS не добавлено.

## Открытые границы

Старый backend `40357ca` не сообщает новые метаданные live-каталога и build SHA.
Источник счётчиков подписан отдельно; обновление UI не добавляет эти API-поля.
Свежий heartbeat не доказывает доставку видео, выполнение команды или непрерывный
uptime. Ещё нужны глубокий инспектор, корреляция task/run/log/stream, долговременная
история метрик, проверка permissions каждого действия и нагрузочный acceptance.
Колонки не сохраняются между перезагрузками; это отдельное улучшение предпочтений.
