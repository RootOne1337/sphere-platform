# Браузер и API для двух проверок веб-аудита

В отдельном сеансе Edge `157.0.4341.46` веб на `127.0.0.1:49498` отправлял запросы своего origin. Next.js dev перенаправлял `/api/*` на FastAPI в `127.0.0.1:49499`. В браузере API не перехватывался. Использована подготовленная ранее временная копия веба. SHA-256 двух страниц и общих файлов запроса, сессии и прав совпали с рабочими исходниками.

| Проверка | Наблюдение |
|---|---|
| WEB-10, `/stream` | Фикстура сообщила о пяти устройствах, четыре на первой странице. Нажатие «Вперёд» сформировало `GET /api/v1/devices?page=2&per_page=4`. В Edge запрос завершился `net::ERR_ABORTED`. FastAPI зафиксировал только запрос первой страницы. Индикатор остался `1 / 2`, пятое устройство не появилось. |
| WEB-14, `/tasks/[id]` | Реальный обработчик capabilities вернул роль `viewer` с `script:read` и без `script:execute`. Веб показал активную кнопку «Остановить задание». После нажатия реальная проверка разрешения в обработчике остановки вернула `403` и `Permission denied: script:execute`, интерфейс вывел этот текст. FastAPI получил одну попытку остановки, зависимость БД не вызывалась. |

Фикстура предоставляла синтетическую сессию и данные чтения, а к FastAPI подключены текущие обработчики capabilities и остановки задачи. Внешние HTTP и WebSocket приложения блокировались. Рабочий API, парк, PostgreSQL, Redis и доставка команды на Android в этом запуске не участвовали. Для WEB-14 результат браузера относится к карточке задания. Журнал и оркестрация проверены в jsdom.
