# Итоговая оценка эксплуатационной готовности Sphere Platform

11 ноября 2026 года. Выполнены три прохода по приоритетным рабочим сценариям и заключительные прогоны. Проверки основной платформы привязаны к срезам исходников в карточках. Последний проверенный HEAD — `9752ea74`. Сценарии Route Studio, затронутые параллельными изменениями, проверены отдельно. [Индекс и версия](README.md#основание), [протокол закрытия](CLOSURE.md).

## Вывод

**Основа платформы работоспособна в проверенных сценариях. Текущий штатный профиль Enterprise Production приёмку не проходит.** В изолированной среде применяются все 30 миграций, проходят выбранные проверки API и восстановления очереди, открываются все 29 веб-страниц на тестовом API, обе Android debug-конфигурации проходят JVM-прогоны. Эти результаты подтверждают отдельные сценарии и показывают, что исправления можно проверять воспроизводимо. Локальный pilot и review UI оставались `healthy` на более ранних образах. Это наблюдение статуса контейнеров конкретной установки. [Миграции и API](BACKEND-DATA.md), [веб](evidence/web-browser.md), [Android JVM](evidence/android-jvm.md).

Влияние существенное. При стандартной чистой поставке API останавливается на проверке PostgreSQL-ролей. При отказе сети и повторных действиях возможны запуск просроченной команды, отправка результата до commit и повтор исполнения. При обычной работе подтверждены HTTP 500 на создании и завершении сессии, конфликт назначения аккаунта и постановка pipeline на выведенное из эксплуатации устройство. Условия и последствия в реестре воспроизводятся раздельно. Частота в действующей установке и число затронутых устройств не измерялись. [Production startup и восстановление](OPERATIONS.md#ops-10), [сессии](BACKEND-DATA.md#be-01), [очередь и callback](BACKEND-DATA.md#be-19), [жизненный цикл устройства](BACKEND-DATA.md#be-23), [повтор из веба](WEB.md).

Заключительная проверка подтвердила, что с вручную настроенной ограниченной ролью API запускается и отвечает на девять штатных запросов. В той же конфигурации фоновая автооркестрация пропускает включённые настройки из-за отсутствующего tenant context. Отдельный синтетический restore сохранил PostgreSQL, Redis и содержимое объекта MinIO. Эти результаты уточняют конкретные блокеры штатной поставки и рабочих сценариев. [Runtime-роль](evidence/backend-closure-observations.json), [BE-25](BACKEND-DATA.md#be-25), [restore](evidence/restore-closure.json).

## Порядок разбора перед приёмкой

| Приоритет | Что мешает | Чем закрывать приёмку |
|---|---|---|
| 1. Чистая поставка и восстановление | Production launcher передаёт API bootstrap-роль. Восстановление владельцев и прав может обрываться на существующей роли. Ошибочный backup может завершаться успешно. | Собрать и поднять точную версию из чистого окружения. Разделить запуск под runtime-ролью и миграцию. На отдельной копии проверить владельцев, grants, данные, артефакты и реальные входы после восстановления. [OPS-07](OPERATIONS.md#ops-07-старый-backup-скрипт-завершает-неудачный-redis-backup-с-кодом-0), [OPS-10–12](OPERATIONS.md#ops-10) |
| 2. Целостность выполнения | Не все пути уважают дедлайн, выключение планировщика, деактивацию pipeline и снятие устройства с эксплуатации. Batch может зависнуть после терминального отказа. Callback может опередить commit. | Для каждого отказа записать до/после в БД и наблюдаемый транспорт. Проверить гонки, перезапуск, отсутствие публикации просроченного, итог batch и согласованность callback с commit. [BE-15](BACKEND-DATA.md#be-15), [BE-18–23](BACKEND-DATA.md#be-18) |
| 3. Подтверждённый результат для оператора | HTTP-ответ и сохранённое состояние расходятся. Веб допускает повтор при неизвестном исходе, показывает ложный успех удаления или действия, которые роль не может выполнить. При истечении Redis прогресс превращается в 0%. | Пройти запуск, остановку, повтор, удаление и чтение результата по ролям. Для потерянного ответа проверить повтор по идентификатору и сверку итоговой записи. [BE-02](BACKEND-DATA.md#be-02), [BE-24](BACKEND-DATA.md#be-24), [веб](WEB.md) |
| 4. Возврат управления после отказа | При остановке и быстром перезапуске Android-сервиса возможны продолжение старого DAG и отсутствие нового цикла WS. OTA и VPN имеют отдельные незакрытые случаи подтверждения результата. | Установить идентифицированный APK на выделенное устройство и эмулятор. Проверить разрыв соединения, смену сети, teardown/restart, ACK и фактические состояния OTA, MediaProjection, ввода и VPN. [Android](ANDROID.md) |
| 5. Интеграции и пределы работы | Discovery, PC Agent и n8n расходятся с контрактами. Допустимый большой пакет VPN блокируется на ingress. Preview Compose не проходит рендер. | Изолированные сквозные проверки с PC Agent, n8n, S3, управляемой потерей DNS/TLS/туннеля и восстановлением под оговорённой нагрузкой. [Интеграции](INTEGRATIONS.md), [OPS-13–14](OPERATIONS.md#ops-13) |
