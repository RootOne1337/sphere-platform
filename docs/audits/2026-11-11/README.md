# Sphere Platform — производственный аудит от 11 ноября 2026

Проверяем эксплуатационную пригодность Sphere Platform по исходникам, контрактам и наблюдаемому поведению. Для подтверждённой проблемы фиксируем путь пользователя или оператора, ожидаемый и фактический результат, причину, условия проявления, последствия и уровень доказательства. Материалы этого каталога служат входом для отдельной работы по исправлениям.

## Результат аудита

Зафиксировано **79 карточек по 77 группам проблем**. Ручное завершение сессии и Discovery разобраны с обеих сторон интерфейса. [WEB-03](WEB.md#web-03--завершить-присваивает-нули-и-null-ранее-записанным-показателям-сессии), [BE-13](BACKEND-DATA.md#be-13), [INT-01](INTEGRATIONS.md#int-01-запрос-discovery-завершается-до-вызова-pc-agent), [BE-09](BACKEND-DATA.md#be-09).

**Технический аудит завершён. Штатный профиль Enterprise Production не проходит приёмку.** Вывод и приоритеты изложены в [итоговой оценке](ASSESSMENT.md). Результаты заключительных прогонов и условия, которые остаются открытыми, приведены в [протоколе закрытия](CLOSURE.md).

## Условия полного покрытия

Для веб-действия требуется связать видимость, роль, условие доступности, событие и обработчик с API или локальным эффектом. Полное наблюдение включает выполнение на тестовых данных, проверку изменения состояния, сообщения при отказе, отмену, повтор и восстановление после потери соединения. Для Android дополнительно фиксируются версия APK, режим установки, версия Android, разрешения, переходы между передним и фоновым режимами и тип устройства.

Для сервисов нужны наблюдения штатных и аварийных переходов, рестарта во время записи, согласованности PostgreSQL, Redis и объектов, задержек и лимитов под нагрузкой. Для инфраструктуры нужны проверяемые сборки, изоляция окружений, цепочки DNS/TLS/TURN, тесты сбоев и восстановление до оговорённых RPO/RTO. Матрицы разделов показывают, какие из этих свидетельств собраны.

## Продолжение аудита

1. Воспроизвести чистую поставку и полное восстановление на стенде с образами и APK одного снимка. Проверить владельцев, runtime-роли, данные приложения и доступ к артефактам после старта.
2. Проверить критичные пользовательские действия с фактическим readback. Начать с запуска, остановки, повторной отправки, смены соединения, rollback и отрицательного исхода команды.
3. На выделенном Android и эмуляторе пройти teardown, возврат управления, системные разрешения, stream, VPN и OTA. На сетевом стенде проверить восстановление после потери PostgreSQL, Redis, S3, DNS, туннеля и TURN.
4. Расширять проверку ролей, экранных состояний и контрактов по матрицам после сценариев с потерей данных или незапрошенным выполнением.
