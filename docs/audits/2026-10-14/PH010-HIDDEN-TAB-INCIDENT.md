# PH010: ввод после возврата из фоновой вкладки

Срез от 2026-10-14 04:36 Asia/Yekaterinburg (23:36 UTC предыдущего дня).
Пользователь сообщил о сбое при просмотре через туннель. Устройство уже подтвердило
APK70 / 10270; веб и API на момент среза ещё были UI103d8532 / API3538b650.

В последних двух пользовательских сеансах видео оставалось прямым, ICE connected,
одна попытка peer, RTT около 1 мс, частота декодирования около 57 FPS. Последние ACK
управления были 4–5 мс. APK не сообщил ошибок ввода, запуска или неизвестного
освобождения; нативный обработчик был idle. Последний fence браузера — `surface_hidden`,
pending=0, offered=acknowledged, палец не удерживался. Это не доказательство
неизменности содержимого экрана: свежесть захвата и получение кодированных кадров —
отдельные величины. Старый snapshot продолжал показывать cached refresh кадров.

Код подтверждает гонку: скрытие вкладки завершает media peer, прежде чем возвратится
CLOSE его участника. Браузер сохранял старый fenced controller и не открывал ввод
на новом подключённом peer, даже когда никакого действия не ожидалось.

Исправление веба допускает повторное присоединение только для shared v2 participant,
который до завершения был ready, не удерживал палец и не ожидал результат действия
или клавиши. Требуется другой авторизованный peer session. Старые callbacks и
participant уничтожаются, новый OPEN ещё обязан получить собственный native READY.
Серверный viewer при этом не меняется, движения и команды не повторяются.

Потерянный UP, удерживаемый палец, неподтверждённая клавиша, native failure или
неизвестная cleanup не удовлетворяют этому условию. Существующая Android admission
по-прежнему отказывает при недостоверном состоянии общего injector.

Регрессия воспроизводит потерю CLOSE receipt при скрытии страницы и замену peer:
новый OPEN остаётся opening до собственного READY, viewer socket остаётся один,
прошлые действия не отправляются. Дополнительные негативные тесты закрывают границы
неопределённых действий. Живой переход реального браузера между фоном и экраном
не считается подтверждённым одним тестом с моделированием DOM visibility.

Исправление установлено в UI `37543bb2` на 3015 и Tuna. Регрессии потокового ввода:
663 теста в 34 наборах, без ошибок. Реальный браузер проверяет потерю RTC и новое
native READY на отдельном PH011, чтобы не управлять открытыми пользовательскими
сеансами PH010/PH030. PH028 не использован для этой приёмки: на проверяемом пути
его ICE не устанавливался.

Реальное переключение `document.hidden` пока не принято. Запуск обычного Chrome,
переключение вкладки и минимизация окна в среде автоматизации оставляли страницу
видимой; подмена DOM visibility не использовалась. Успешное восстановление после
принудительного закрытия RTC не доказывает физический background/foreground сценарий.
Снимки хранятся локально в ограниченном приватном отчёте.
