# APK75: подтверждение клавиатуры по действующему IME

Статус этого документа — подготовка исходников. APK75 ещё не установлен и не принят
на устройствах. Веб и API04cf101 обслуживают3015 и Tuna; APK74 установлен только
на PH011, APK73 — на PH030. Последняя полная принятая рассылка остаётся APK72.

На PH011 / Android28 воспроизведено расхождение: `ime set` подтверждает выбор нашей
службы, `dumpsys input_method` показывает её в `mCurMethodId` и привязку, но
`settings get secure default_input_method` для текущего пользователя0 возвращает
прежний IME. Это не гипотеза о сети: служба действительно выбирается, а APK74
ошибочно отменяет активацию по устаревшему зеркалу settings. Диагностический опыт
завершён восстановлением прежней клавиатуры; пользовательский текст не собирался.

APK75 читает действующий выбор у службы ввода. Разные значения для нескольких
пользователей или неизвестный формат не дают разрешения на смену IME. Полный dump
существует только во время ограниченной команды, не сохраняется и не логируется.
Включённые IME проверяются через `ime list -s`. Перед изменением сохраняется
восстановление; при неопределённой очистке маркер остаётся и блокирует новый lease.
Если локальный пользователь выбрал другую клавиатуру, его выбор сохраняется.

Команды конфигурации используют существующий BoundedProcessRunner: закрытый stdin,
параллельное ограниченное чтение stdout/stderr, общий deadline и очистка при отмене.
Вводимый текст, композиция и клавиши продолжают идти через тот же WebRTC control
actor; shell получает только фиксированные команды настройки IME. Отказы настройки
пишут только фиксированную фазу, без dump, адресов, идентификаторов или текста.
Отмена worker больше не поглощается и выполняет восстановление вне отменённого
контекста. Завершившийся worker не отключает новую активацию того же участника.

Сфокусированная проверка:35 тестов,0 ошибок/отказов, включая stale settings,
перехват выбора локальным пользователем, отказ durable save, неопределённое
восстановление, отмену, повторный OPEN после known startup refusal и границы
native keyboard/process cleanup. Нужны полный signed build и фактическое сравнение
текста Android с вводом браузера, а также fullscreen, несколько клиентов и reconnect.

Это не закрывает серверную full keyboard,20+ участников, работу без broker,
TURN/mobile/WAN acceptance и весь перенос hosted CI. Эти пункты остаются открытыми.

Семантика активного выбора сверена с
[Android9 InputMethodManagerService](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/pie-release/services/core/java/com/android/server/InputMethodManagerService.java).
Контур Unicode опирается на
[Android InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection).
