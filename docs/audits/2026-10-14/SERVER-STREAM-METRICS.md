# Метрики серверного видеомаршрута

Подготовлено 2026-10-14; установку и живую приёмку подтверждает отдельная квитанция.

Прежний `DeviceStream` всегда передавал `rtt=null` в компактную строку, когда видео
шло по серверному WebSocket. Отсутствие цифры не доказывало отсутствие связи.
ACK Android показывался отдельно и только при готовом непрерывном управлении.

В новом вебе и API добавлен ограниченный `stream_link_probe` / `stream_link_result`.
API объявляет поддержку после аутентификации просмотрщика. Один ожидающий запрос,
не чаще одного раза в пять секунд в видимой вкладке, использует существующий watchdog.
Сервер отвечает не чаще одного раза в секунду на просмотрщика. Сообщение содержит
только целый sequence; ввод, видео, IP, токены и часы не сохраняются и не пересылаются
в APK. Этот механизм не переподключает стрим и не меняет владельца ввода.

При таймауте, уходе вкладки в фон, остановке socket, backpressure или разрыве
монотонного таймера значение становится неизвестным. Возраст годного среза
ограничен 15 секундами. История сохраняет только `server_link_rtt_ms` и
`server_link_sample_age_ms` в прежнем ограниченном диагностическом сеансе.

Три показателя имеют разный смысл:

| Подпись | Измерение | Чего не доказывает |
| --- | --- | --- |
| RTT сервера | Круговое время браузер ↔ сервер, включая очереди и обработку | Связь с APK, выполнение ввода, полную задержку картинки |
| RTT прямого канала | Выбранная ICE-пара WebRTC | Выполнение касания или полную задержку картинки |
| ACK действия/связи Android | Подтверждение конкретного нативного действия/heartbeat, по указанному маршруту | Полную задержку картинки |

В режиме просмотра без управления серверный RTT также измеряется. Новый APK для
этого замера не требуется. Совместное нативное управление и системные кнопки
поставляются отдельно в APK70 и согласованном API/вебе.
