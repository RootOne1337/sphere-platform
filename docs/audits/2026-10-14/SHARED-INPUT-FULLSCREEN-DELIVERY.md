# Совместный прямой ввод, APK69 и полноэкранный режим

**Установлено:** веб `103d8532`, API `3538b650`, APK `1.2.69-dev /10269`.
Один веб обслуживает 3015 и Tuna. Это конечная проверка указанной конфигурации,
а не приёмка всех аппаратных вариантов, сетей или enterprise SLA.

[Замороженный протокол](SHARED-INPUT-FULLSCREEN-INSTALLED.json) ·
[Текущий реестр](../../operations/WORK-STATUS.md).

## Что изменилось

APK, серверная резервация и клиент поддерживают до десяти отдельных прямых peers.
Каждый получает видео и `sphere-control-v2` на одном WebRTC-соединении. Захват,
аппаратный encoder и root input pipe общие. Новый DOWN другого участника сначала
подтверждённо отменяет прежний жест; старые MOVE/UP не возвращают владение. Закрытие
вкладки очищает её участника.

Живая проверка выявила ещё одну причину отказа второго клиента: прежний веб открывал
эксклюзивный v1 input pipe раньше готовности совместного media peer. Отказ перезапускал
соединение, хотя ICE/DTLS уже работали. Веб теперь дожидается согласования возможностей
APK и готового совместного endpoint. Отсутствие ввода не объявляется сетевой неисправностью.
[Реализация и история проверки](../2026-10-13/SHARED-DIRECT-INPUT.md).

Fullscreen использует браузерный Fullscreen API, сохраняет video/canvas и текущий peer.
Панель Android открывается наведением/фокусом или отдельной кнопкой 44×44 px. На узком
экране окно текста выходило за левую границу; исправлена привязка к viewport и устранены
родительские CSS-эффекты, менявшие систему координат. Панель ограничена по высоте и
может прокручиваться внутри. При неподдерживаемом fullscreen поток продолжает работать.

## Фактическая доставка

На всех 15 доступных эмуляторах завершилась адресная OTA APK69, устройства сообщили
10269. На 14 прочитан и проверен SHA установленного `base.apk`. У PH030 подтверждены
точная OTA-команда и новая версия, но чтение установленного хеша запрещено активным
вводом; работающий пользовательский сеанс не прерывался.

PH021/023/024/026/027/029 офлайн. Их обновление остаётся открытым: новый grant им не
создавался, автоматическая очередь для возвращения не объявлена работающей. Обычный
глобальный канал Android сохранён. Публикация canary и адресная OTA не означают, что
старый офлайн-агент автоматически подписался на canary-канал.

Последний APK скачан браузером через оба адреса: **57 786 356 байт**, SHA-256
`2708e0b794ddfacc72d1f340da91fb4c13cb6a845acf297a3fba8b65f99bfb32`.
Измерения — 1153 мс через 3015 и 6498 мс через Tuna. Это измерения двух конкретных
скачиваний, не обещание такой скорости всем клиентам. Локальный alias LATEST указывает
на тот же подписанный APK; данные эмуляторов не очищались.

## Проверки и их границы

- Десять отдельных контекстов обычного Chrome с независимым нормальным входом:
  реальные жесты, подтверждённый takeover и закрытие одного с 30-секундной проверкой
  девяти оставшихся. Пакеты касаний не пересылались через сервер; у каждого оставался
  один peer. Точный результат, FPS и время открытия сохранены в протоколе.
- Native fullscreen, 1440×1000 /390×844 /844×390 через 3015 и Tuna. Реальные браузерные
  mouse/touch события получили native подтверждения. Video/canvas и peer сохранились
  после смены геометрии и выхода. Проверены границы окна текста и кнопки 44×44 px.
- Полный frontend CI для точного источника, **2358 тестов**, типы и сборка. APK69:
  два профиля по 1168 тестов, без failures/errors, по три skipped; оба lint и подписанные
  сборки. Android CI для точного источника APK завершён успешно. API CI353 завершён
  успешно после повтора инфраструктурно отказавшего PostgreSQL job; образ из первоначально
  успешного packaging job проверен по исходному attempt и authenticated CI log.
- OpenAPI установленного API совпадает с сохранённой схемой: 149 paths /188 operations.
  SQL migration не выполнялась. При каждой замене сохранены остальные 45 контейнеров.

`applied` для касания означает принятие InputDispatcher через WAIT_FOR_RESULT.
Количество presented frames проверено отдельным пассивным requestVideoFrameCallback.
Ни network RTT, ни native ACK не являются измерением появления результата на экране.
Никакие неизвестные команды не повторялись; адреса кандидатов, typed contents и сетевые
секреты в публичном протоколе отсутствуют.

Автоматизированные touch события в Chromium не заменяют настоящий телефон. Новая
версия ещё требует phone/hotspot, физических network-switch и emulator-input проверок,
20+ участников, ресурсных бюджетов/JNI и длительной нагрузки.

## Что ещё не готово

Fullscreen **не включает физическую клавиатуру**. Текущие Home/Back/Recents/Menu и
ограниченный ASCII text path ещё используют сервер. Native keys, Unicode/IME,
composition/paste, held-key cleanup и звук не приняты.
[Контракт клавиатуры и план приёмки](DIRECT-KEYBOARD-PLAN.md).

Прямой media/input peer ещё зависит от серверного grant/lease: модель автономного
сеанса не подключена к runtime. Пропадание Интернета при сохранённом localhost/LAN
ещё не является проверенной автономностью. TURN и все NAT/VPN/hotspot комбинации
не гарантированы.

CI полностью локально **не перенесён**. Локальная trusted очередь и GitHub statuses
работали в предыдущей приёмке, но hosted packaging/security/Linux и release gates
остались. Повторные Android/API jobs для неизменных деревьев отменены с отдельными
проверенными статусами повторного использования источника; они не выданы за новые
прогоны. [Аудит CI](../2026-10-13/CI-COST-AND-LOCAL-RUNNER.md).

Продолжение установки при предупреждении NTFS выполнено в рамках явного разрешения
пользователя. Предупреждение сохранено в протоколах, остальные ресурсные проверки
не отключались. Старые замороженные протоколы APK68 и прежних установок сохранены.
