# Исправления после продуктового аудита

Дата: 5 октября 2026, Asia/Yekaterinburg. Ветка PR #19.

[Замороженный аудит](ENTERPRISE-PRODUCT-AUDIT.md) и [исходный план из 50 работ](ENTERPRISE-PRODUCT-BACKLOG.json)
сохраняют доказательства исходного состояния `c3937a1`. Этот документ отдельно фиксирует
изменения, проверки и установку. Source-fixed не означает live-accepted или production-ready.

Первый пакет закрывает пять подтверждённых дефектов EP-001…EP-005 в описанной ниже
области проверки. Дополнительно исправлен кеш каталога сценариев, выявленный при живой
записи. EP-006 и остальные 44 работы исходного плана сохраняют открытые критерии;
добавление отдельных колонок не закрывает все требования EP-011/EP-012.

Проверка архива после первых исправлений выявила зависимость валидатора от байтов
текущей Windows working copy: исходная inventory содержит смешанные LF/CRLF, а Git — LF.
Исторические hashes и сам аудит сохранены. Добавлен отдельный
[manifest Git blobs](ENTERPRISE-PRODUCT-SOURCE-MANIFEST.json), построенный из `c3937a1`,
и integrity check теперь проверяет эти неизменяемые объекты и frozen OpenAPI.
Исходные checkout-byte hashes не объявляются воспроизведёнными после редактирования.

## Первый блок: канонический граф сценария

EP-002 / EP-003: **SOURCE_FIXED / CONTRACT_VERIFIED / BROWSER_API_VERIFIED**.

Причина: редактор принимал/отправлял словарь `nodes` с `type/links`, а сервер и APK
используют массив `{id, action, on_success, on_failure, retry, timeout_ms}`.
Нативная пауза APK читает `action.ms`; условие читает `action.code` либо нативный
`check/params`, а не `condition_expr`. UI теперь использует эти имена напрямую.

- [Адаптер графа](../../../frontend/lib/dag/export.ts) принимает DAG 1.0; экспортирует
  массив и сохраняет все параметры действия, корневые name/description/timeout,
  исходный entry, success/failure и обе ветки condition. Циклы опроса сохраняются.
- [Редактор](../../../frontend/app/%28dashboard%29/scripts/builder/page.tsx) показывает
  специализированные узлы и общий узел для остальных известных действий. Полный JSON
  параметров доступен для чтения. Общий узел пока не является полной формой создания
  всех действий: каталог действий и source editor остаются следующими этапами Studio.
- Удалённая связь не восстанавливается из скрытого JSON; неоднозначный fan-out,
  неизвестное действие, дубликаты id, недостижимые шаги и неверные диапазоны блокируют запись.
  Backend Lua safety и проверки параметров APK продолжают действовать.
- Ветки ошибок доступны на канве. Повторы и таймаут отдельного шага редактируются.
  Новые id используют UUID; расположение канвы не отправляется в исполняемый граф.
- Existing-resource read остаётся fail-closed. Отсутствующая версия, архив, другой id
  или ошибка чтения не превращаются в новый шаблон. PUT содержит
  `expected_current_version_id`; HTTP 409 сохраняет граф на экране и не повторяется.
- Кнопка «Создать сценарий» создаёт запись, а «Сохранить версию» сохраняет её.
  Это не запуск сценария и не отправка команд устройству.

Проверки: Jest regression graph/load ownership, TypeScript; дополнительный Node → Python
probe проверяет реальный `DAGScript.model_validate`, равенство roundtrip после серверной
нормализации и совпадение 32 action types с backend. Ни БД, ни Android этим probe не вызываются.
55 тестов graph/load проверяют контракт, маршруты, ошибки чтения, владение записью,
конфликт версии и поведение каталога. В браузере открывался существующий четырёхшаговый
граф; показывались полный shell JSON, retry и timeout. Создан отдельный Start→End,
сохранён через PUT и прочитан обратно из настоящего API. Это проверка чтения/записи
сценария, не выполнение произвольных 32 действий на Android.

Живая проверка выявила ещё один дефект: запись создана сервером, но при возврате каталог
показывал прежние 14 записей из свежего React Query cache до ручного refresh. Исправление
помечает `['scripts']` как stale после подтверждённого POST/PUT и до навигации; отказ записи
не инвалидирует каталог. Это дополнительный дефект вне исходных 50 работ, выявленный
live-проверкой; подтверждённые create/update и дальнейшая повторная приёмка записаны ниже.

На UI `4367d41` повторное сохранение с новым именем сразу отобразило его в каталоге,
без кнопки «Обновить». Сервер вернул канонический массив из двух узлов. Повторная запись
неизменного графа не размножила версии: осталась одна версия. Только этот owned canary
архивирован с `expected_current_version_id`; версия и граф сохранены для восстановления.
Задания не создавались, команды Android не отправлялись.

## Второй блок: таблица устройств

EP-001 / EP-004: **SOURCE_FIXED / REGRESSION_VERIFIED / BROWSER_VERIFIED**.

- Колонки и сортировка сохраняются в `sphere.fleet.table.v1` на этом браузере.
  Гидратация после mount не затирает настройки значениями по умолчанию.
  Отдельная команда сбрасывает вид/сортировку. Имя устройства всегда остаётся видимым.
- Формат версионирован, вход ограничен 8192 символами, незнакомые колонки/направления
  сортировки отбрасываются. Ошибка/переполнение localStorage сохраняет рабочий вид в
  памяти и показывает, что настройки временные. Credentials, строки устройств и
  выбор целей команд не сохраняются. Между вкладками обрабатываются storage events.
- Модель читается из `device_model`, затем из legacy `model`; fallback появляется
  только при отсутствии обоих значений. Общее правило убирает пробелы и применяется
  также к карточке, двум device picker, HUD сетки и сортировке страницы потоков.
  Модель видна прямо в списке выбора. Pending local search использует то же поле,
  а после debounce фильтр выполняет API по колонке БД `Device.model`, которую REST
  возвращает как `device_model`. Сортировка потоков остаётся локальной для страницы,
  она не объявляется глобальной сортировкой всего каталога.
- Добавлены необязательные Android ID, CPU Android и RAM Android. CPU/RAM — последний
  отчёт Android, не измерение процесса APK и не доказательство свежего heartbeat.
  Ноль сохраняет значение ноль; null/NaN/неверные значения подписаны как отсутствующие.
- Виртуализация и внутренний горизонтальный scroll сохраняются; страницы по-прежнему
  получает каталог API. Локальный auto-reset не изменяет серверную страницу.

23 frontend regressions проверяют модель, remount/F5-equivalent, колонки/сортировку,
отсутствие сохранённых выбранных устройств, сброс, повреждённые/слишком большие данные,
отказ хранилища, реальные/неизвестные CPU/RAM. Ещё четыре consumer regressions проверяют
поля модели в двух picker, pending поиск, сортировку страницы и HUD без запуска потока.
Прямая F5 проверка установленного UI сохранила «Доступ», CPU Android, RAM Android
и сортировку имени по возрастанию. На ширине 390 px документ не переполнялся;
таблица сохраняла внутренний горизонтальный scroll. Сохранение поиска/групп/локаций,
ширины/закрепления колонок, пресетов и account sync — открытая часть EP-011/EP-012.

## Третий блок: число шагов в выборе сценария

EP-005: **SOURCE_FIXED / REGRESSION_VERIFIED / BROWSER_VERIFIED**.
Три script picker в создании pipeline/расписания и редактировании расписания используют
общий `getScriptStepCount`/`formatScriptStepCount`. Текущий DAG-массив даёт реальное
число шагов; если DAG/legacy count отсутствует, выводится «Шаги не указаны», а не пустые
скобки или ноль. Проверен настоящий schedule form; создание/запуск не выполняются тестом.
В браузере форма создания pipeline показывала 2 шага canary и реальные 4/14 шагов
существующих сценариев. Форма отменена; pipeline/расписание не создавались.

## Границы установки и живой приёмки

Установленный frontend **`6ff6bc28ceb0adf6fda0c4aa933546ae3e3a7dc0`**;
receipt **2026-10-05 02:33:28 UTC / 07:33:28 UTC+5**.
Рабочий адрес: [review UI на 3015](http://127.0.0.1:3015/devices).
Контейнер `sphere-review-20261002-review-ui-1` healthy после адресной установки;
API `c1a6e79a`, gateway, Tuna и остальные 45 контейнеров сохранили identities/image/StartedAt.
APK в этом пакете не пересобирался и не переустанавливался. Публичный frontend
на 18080 не объявляется обновлённым этой локальной установкой.

Клиент и сервер показывают разные commit SHA: здесь это намеренная установка
frontend поверх существующего API. Совместимость подтверждена конкретными GET/POST/PUT
и серверным валидатором, не равенством значков версии и не всеми 178 operations.
Прежние образы UI сохранены для отката; системная очистка и массовая ротация не проводились.

Во время проверки каталог показывал 19 устройств / 14 online / 5 offline.
Это конечный readback, не доказательство непрерывной доступности, FPS или нагрузки
500–1000 устройств. Ночное ограниченное окно диска/ОЗУ продолжает отдельный сбор;
сборки Docker — известные записи на диск и должны учитываться при его разборе.

На итоговой сборке в реальном picker запрос модели `OnePlus` дал один результат
`auto-ph-010 / OnePlus HD1910`; zero selected и кнопка запуска disabled.
Форма отменена. На странице потоков выбран model sort; реальные модели отображаются
в отсортированном порядке текущей страницы. Просмотр видео не запускался.
После загрузки `6ff6bc2` F5 сохранил те же колонки и ascending sort. Console errors
в конце этих browser flows — пустой список. Временный viewport reset выполнен.

Ни сохранение сценария, ни 1185 frontend-тестов не закрывают живое выполнение
автоматизации, конфликт двух операторов в браузерах или нагрузочный/длительный soak.
