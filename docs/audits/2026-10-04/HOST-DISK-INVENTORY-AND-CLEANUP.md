## Ответ на вопрос о размере проекта

Текущая рабочая папка Sphere занимает **7,996 GiB логических данных**, включая
локальные зависимости, сборки, историю Git, APK и частные результаты проверок.
2240 файлов, отслеживаемых Git, занимают **23 150 453 байта / 22,08 MiB**.
Это измерение текущих файлов, а не полный размер истории репозитория.
Docker хранит образы, слои сборки, контейнеры и тома отдельно от этой папки.
Его VHD обслуживает также другие проекты; весь VHD нельзя приписать Sphere.

| Область рабочей папки | Логический размер | Состав / статус |
|---|---:|---|
| `.local-pilot` | 3,882 GiB | Исследования, APK, OTA, зависимости инструментов и квитанции; сохранены |
| `frontend` | 2,407 GiB | `node_modules` 0,891 GiB; `.next` 0,803 GiB; `.next-audit` 0,709 GiB |
| `android` | 0,633 GiB | Исходники, Gradle и результаты сборки; сохранены |
| `.git` | 0,542 GiB | История и объекты; сохранены |
| `.venv-audit` | 0,313 GiB | Среда проверок; сохранена |
| Остальные файлы и каталоги | около 0,219 GiB | Документы, тесты, кэши анализаторов и прочее |

Строки таблицы — непересекающиеся области. Размер отслеживаемых файлов входит
в размер рабочей папки и не прибавляется к нему. Распределение — снимок обхода,
не атомарная транзакция: фоновые приложения могут изменять файлы во время него.

## Покрытие инвентаризации

Read-only обход C: продолжался **304,422 секунды** и проверил метаданные
**5 038 969 файлов / 830 315 каталогов**. Содержимое личных файлов не читалось.
6142 reparse points пропущены; зарегистрированы 123 ошибки доступа/обхода.
Следовательно, это доступная область C:, а не доказательство чтения каждого
защищённого системного каталога. `Temp` в PowerShell расположен на том же C:.
Другого доступного файлового тома этот срез не обнаружил.

Сумма логических размеров не равна физически занятому месту: hard links
не дедуплицированы, sparse/compressed allocation для всех файлов не измерена,
часть служебных областей недоступна. Вложенные категории нельзя складывать.
Для 14 крупнейших файлов отдельно вызван Windows `GetCompressedFileSizeW`;
ошибки сохранены без подмены нулём.

## Крупные потребители вне рабочей папки

| Область | Логический размер | Ограничение / действие |
|---|---:|---|
| Docker `docker_data.vhdx` | 218,610 GiB | Размещённые байты также 218,610 GiB; не compact, не delete |
| LDPlayer | 39,432 GiB | Диски и файлы эмуляторов; рабочие экземпляры не менялись |
| Модели и данные одного приложения ИИ | 38,960 GiB | Чужие пользовательские данные; не удалялись |
| Windows | 54,503 GiB | Логическая сумма с недедуплицированными hard links; не оценка безопасной очистки |
| `pagefile.sys` | 41,430 GiB | Файл Windows; allocation API вернул sharing violation, размер не изменён |
| `hiberfil.sys` | 18,875 GiB | Файл Windows; allocation API вернул sharing violation, режим гибернации не изменён |
| Android AVD | 18,460 GiB | Логическая сумма; присутствуют sparse images, не обещает такой объём освобождения |

Например, один старый audit AVD `userdata-qemu.img` имеет длину **6 GiB**, но
физически размещает только **107 937 792 байта / 102,94 MiB**. Удаление такого
файла нельзя представлять как освобождение 6 GiB. Полная карта личных каталогов
и имена файлов остаются в частном локальном inventory, не публикуются в Git.

## Что очищено в этом этапе

Использованы штатные команды с явно проверенными каталогами download cache:

```powershell
npm.cmd cache clean --force --cache 'C:\Users\dimas\AppData\Local\npm-cache'
& .venv-audit/Scripts/python.exe -m pip --cache-dir 'C:\Users\dimas\AppData\Local\pip\cache' cache purge
```

Обе команды завершились с кодом `0`. pip сообщил удаление 1538 файлов и 7805
каталогов. npm очистил скачанные package entries; **`_npx` сохранён**:
в нём находятся отдельные установки CLI/MCP, а не только архивы скачивания.
Их оставшийся логический размер — около 4,300 GiB. Среды Python и `node_modules`
не удалены. Общие uv/pnpm/Go/Gradle caches не очищались этим этапом.

| Измерение | Байты | GiB |
|---|---:|---:|
| C: free перед package cleanup | 39 413 653 504 | 36,707 |
| C: free после, 17:48:59 UTC | 44 487 598 080 | 41,432 |
| Наблюдаемая прибавка свободного места | 5 073 944 576 | 4,726 |
| C: free при guard, 17:49:46 UTC | 44 485 566 464 | 41,431 |

Прибавка — фактическое изменение свободного места на томе в этом окне.
Она не является точным бухгалтерским размером удалённых данных: фоновые
приложения продолжают работать, размеры каталога и cluster allocation различаются.
До очистки свободное место уменьшилось с ранее записанных 43 638 882 304 байт
до 39 413 653 504; **владелец этого отдельного изменения не установлен**.
VHD и pagefile в измеренных срезах не увеличили длину. Этот эпизод не объявлен
доказанной утечкой Sphere или следствием read-only обхода.

Дополнительно подготовлен точный план удаления двух build cache directories:
`frontend/.next/cache` и `frontend/.next-audit/cache`, суммарно **879 748 887 байт /
0,819 GiB**. Автоматическая проверка отклонила запуск с причиной **«blocked by
policy»** до выполнения команды. Эти каталоги **не удалены**; другим способом
отказ не обходился. Нельзя включать этот объём в результат очистки.

Предыдущая адресная очистка 31 Next cache / 8,21 GiB, 19 git-archive contexts и
53 unused images остаётся отдельным историческим результатом. Удаление images
освободило блоки внутри Linux, но не уменьшило Windows VHD; размеры shared
image/build-cache layers не суммируются как уникальные физические байты.

## Проверка сохранности и границы результата

После cleanup сверены **все 46 running/stopped контейнеров**: идентификаторы,
image ID и время запуска совпадают с планом до удаления. В 17:50:12 UTC API через
3015 сообщил **`c1a6e79`, 19 записей / 14 online, APK 10244**. Android-команды,
APK/OTA rollout, рестарт API/UI/Tuna и удаление томов не выполнялись.

Resource guard прошёл: доступная RAM 19 578 286 080 байт, Windows commit
53 811 834 880 / 95 153 381 376 байт. Это конечная проверка допуска, не длительное
доказательство отсутствия утечки. Восьмичасовой ограниченный sampler предыдущего
этапа продолжает собирать данные; его нагрузка и этот metadata scan учитываются
при дальнейшем анализе. Завершение sampler здесь не заявляется.

В этом этапе не менялся код приложения, поэтому повторная тяжёлая компиляция
не запускалась. Проверяются числовая согласованность evidence, hashes исходных
квитанций, относительные ссылки, JSON, `git diff --check`, сохранность runtime
и frozen audit. Прежние source CI / 1122 frontend / 186 API / 18 guard checks
относятся к `c1a6e79`, а не являются новым тестированием этой очистки.

Следующий крупный резерв — обслуживание Docker VHD после отдельной проверки
безопасной остановки, backup, compact и восстановления. Существующий VHD нельзя
удалять или compact при работающем Docker. Служебные файлы Windows, эмуляторы,
модели и чужие проекты не рассматриваются как одноразовые build artifacts.

Штатные операции сверены с [документацией npm cache](https://docs.npmjs.com/cli/v11/commands/npm-cache/)
и [pip cache](https://pip.pypa.io/en/stable/cli/pip_cache/); ограничения VHD и
retention приведены в [runbook](../../operations/HOST-RESOURCES.md).
