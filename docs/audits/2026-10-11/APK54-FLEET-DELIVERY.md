## Контроль доставки

Использован ранее опубликованный immutable APK из существующего OTA-хранилища.
Локальный файл повторно хеширован; exact Android CI исходников APK54 успешен.
Перед выдачей каждого online grant проверены имя/ID, активность, статус,
точный установленный SHA предыдущей версии и отсутствие другого active grant.
Первой парой обновлены PH011 и удалённый PH025; после завершения и package-SHA
readback парк обновлялся партиями максимум3 устройства.

Каждая команда записана до выдачи и затем согласована с recovery status.
Неоднозначный POST не повторяется автоматически. Завершение принято только при
completed receipt с тем же command ID, version code и SHA, возвращении online
и фактическом hash установленного пакета. Очистки данных, ADB installs,
повторной публикации APK или смены обычного OTA channel не было.

## Вопрос об освобождении RAM внутри Android

В агенте есть системный замер RAM через `DeviceStatusProvider.getRamUsageMb()`.
Отдельного режима очистки памяти этой доставкой не добавлено.
Можно спроектировать освобождение неиспользуемых ресурсов самого агента,
наблюдение за memory pressure и, при соответствующих привилегиях, явную политику
управления выбранными фоновыми приложениями. Активная игра, управление, сценарий
и ресурсы действующего стрима требуют защиты от такой политики.

Android самостоятельно управляет cached processes; освобождение ресурсов нужно
привязывать к lifecycle и реальным измерениям. [Официальное руководство памяти](https://developer.android.com/topic/performance/memory/manage-app-memory).
В Android14+ обычный `killBackgroundProcesses` ограничен процессами собственного
приложения. [Ограничения API](https://developer.android.com/reference/android/app/ActivityManager#killBackgroundProcesses(java.lang.String)).
RAM эмулятора, память процесса LDPlayer в Windows и занятое место C:/Docker — разные
измерения; освобождение guest RAM не обещает уменьшения VHDX или свободного места SSD.
