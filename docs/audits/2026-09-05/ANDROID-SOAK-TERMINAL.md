## Почему причина PermissionError пока неизвестна

Последнее исходное событие — resource sample первого устройства в 02:40:59.068 UTC;
затем закрытие viewers и `failed` в 02:40:59.402 UTC. Старый harness сохранял только
название исключения. Traceback, `errno` и `winerror` отсутствуют и не могут быть
восстановлены из этих evidence. Файловая блокировка Windows и ошибка сетевого
вызова пока не различены. Причина не приписывается APK, сети или антивирусу.

## AUD-117: потеря места и системного кода ошибки в harness

- **Severity:** Medium / P2, диагностика длительного теста. Прогон останавливается
  честно, но после многочасового запуска нельзя установить отказавшую операцию.
- **Root cause:** `Runner.run` превращал неизвестное исключение только в имя
  класса. Ни events, ни status, ни итог не сохраняли расположение ошибки.
- **Reproduction:** два изолированных случая инъекции `PermissionError` в разные
  точки вызова возвращают неполный отчёт. До исправления оба теста падают с
  отсутствующим `failure_detail`; это не воспроизведение исходной ошибки Windows.
- **Affected file / fix:** [android_soak.py](../../../scripts/pilot/android_soak.py)
  сохраняет класс, `errno`, `winerror` и до 12 последних frames: имя исходного
  файла, функцию и строку. Текст исключения, проблемный путь, URLs, locals и строки
  исходного кода не публикуются. Detail записывается в status и событие failed.
- **Regression:** [test_safe_soak.py](../../../tests/test_scripts/test_safe_soak.py),
  2 failures до → все **15 tests pass** после; Ruff pass.
  [Evidence](evidence/soak-failure-diagnostics-regression.json).
  Проверены различимые точки отказа, OS codes, отсутствие private message/filename,
  остановка после одной попытки и диагностическое завершение.
- **Residual risk:** исправлена потеря диагностики, **не причина исходного
  PermissionError**. При полном отказе диска запись evidence всё ещё может быть
  невозможна. Сетевые/файловые операции автоматически не повторяются. Восьмичасовой
  повтор с новой версией harness ещё не выполнен.

## Следующие приёмки

Нужен новый явно отделённый прогон с сохранением исходного failed run. До него
следует проверить запись evidence при конкурирующем чтении Windows и полноту
диагностики OS-отказов. Независимое подтверждение визуальных изменений экрана
также остаётся открытым: success shell-команды и приход новых кадров не доказывают
содержимое UI. Полный профиль ввода/жестов/поиска, VPN, network/DB faults и большая
ферма остаются отдельными проверками. Измеренное окно не заменяет всю ночь.
