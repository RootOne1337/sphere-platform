# AUD-127 · Ночной тест принимал зависший просмотр за успешный overlap

**20 сентября 2026 · Medium / P2 · исправлено; 22 tests и native helper прошли.**

## Дефект и доказательство

В `scripts/pilot/android_soak.py`, `Runner.cycle`, дополнительный viewer считался
проверенным после начальных SPS/PPS/IDR. Метод `Viewer.check()` проверял состояние
reader task, но не поступление новых кадров. После открытия и закрытия extra-окна
исходный viewer также не проходил проверку движения экрана.

Это позволяло не заметить [AUD-126](STREAM-MULTI-VIEWER.md): живой WebSocket без
нового видео. Три regression cases с настоящим `Runner.cycle(4)` и управляемыми
входными кадрами до fix **ошибочно завершили цикл** вместо `SoakFailure`:

1. Исходный зритель перестал получать кадры при открытии второго.
2. Дополнительный зритель получил только начальные кадры.
3. Исходный зритель замер после закрытия дополнительного.

Все три теста упали с `DID NOT RAISE`, до изменения runner. Это дефект тестового
критерия, не ещё один отказ APK. Старые 52 события `overlap_verified` ночи
`night-20260920-001` подтверждают начальную готовность дополнительных сокетов;
они **не доказывают непрерывную передачу обоим зрителям**. Историческая ночь
остаётся FAILED; ранее подтверждённые task receipts этим не опровергаются.

## Fix и regression

Новый `Runner.verify_viewer_motion` снимает счётчики всех viewers, через Sphere
открывает и закрывает Android notification shade и требует новые кадры каждому.
После завершения команд допускается не более пяти секунд ожидания. Проверяется
reader failure; закрытие шторки находится в `finally`. Повторов изменяющих
запросов, ADB-команд управления, нового APK или действий в играх нет.

Оба этапа обязательны: **overlap** и **after_overlap_close**. В приватном evidence
сохраняются stage, device, viewer index и фактический прирост кадров. Только после
них цикл может стать passed. Положительный regression подтверждает оба этапа,
отрицательные — остановку и закрытие собственных viewers без ложного cycle_passed.

Затронуты `scripts/pilot/android_soak.py` и новый
`tests/test_scripts/test_soak_viewer_motion.py`. **22 harness tests passed**, включая
предыдущие защиты от неизвестного исхода POST, некорректных task receipts,
подменённого pipeline, OS errors и ложного завершения running-сводки.

Повторить: `pytest tests/test_scripts/test_soak_viewer_motion.py
tests/test_scripts/test_safe_soak.py tests/test_scripts/test_soak_atomic_json.py -q --no-cov`.

## Native-проверка и границы

Непосредственно сохранённый helper вызван на настоящих WSS-сессиях двух APK
1.2.7 / 10207, backend `85fb1ea`. Для каждого устройства проверены три, затем два,
затем один оставшийся viewer. Все шесть этапов получили новые кадры, оба echo
верны; PID 2182/2187 и crash buffers прежние, projection освобождена.
[Evidence](evidence/soak-viewer-motion-regression.json).

Это ограниченная проверка helper, а не новый полный ночной прогон. Она не измеряет
FPS, качество декодированного изображения, latency SLA или вместимость парка.
Проверяется прирост после известного изменения UI; статичный экран сам по себе
не считается ошибкой. Требуется новый конечный длительный запуск с новым run ID.
