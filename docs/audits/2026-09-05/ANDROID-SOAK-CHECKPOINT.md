## Открыто: лишние предупреждения о результатах команд

В ограниченном backend log window от начала прогона (лимит 2,500 строк,
снято около 00:23 UTC) найдено **190 `task.result.not_found`**. У этих 190 UUID
нет пересечения с 19 завершёнными native task IDs в том же окне. Других
warning/error/critical в сохранённом окне нет; это не утверждение о всех логах.

Прослеженный путь: `_request_interactive_command` в
[devices/router.py](../../../backend/api/v1/devices/router.py) выдаёт UUID
интерактивной команде без SQL Task. `handle_command_result` в
[android/router.py](../../../backend/api/ws/android/router.py) сначала
публикует ответ, затем для final UUID вызывает SQL task-result handler. Отсутствие
SQL-строки для такой команды превращается в предупреждение. Это создаёт шум
диагностики и лишние SQL-запросы; сверенные выше DAG-результаты сохранены.

**Исправление ещё не выполнено.** После фиксированного ночного профиля нужны
отдельный failing regression, различение интерактивного ответа и durable task
result и повторная проверка. Реальный неизвестный task result должен сохранять
диагностический сигнал: глобальное подавление `task.result.not_found` неприемлемо.
