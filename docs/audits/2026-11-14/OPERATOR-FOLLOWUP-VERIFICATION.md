# Повторная проверка операторских сценариев

**14 ноября 2026.** Перепроверка пакета из 20 изменений и работа по
EP-023, EP-024, EP-040 и EP-041. Исходная ревизия рабочей копии `ab5236c6`.
Новые миграции и браузерная проверка выполнялись отдельно от действующего
пилота.

## Что исправлено

| Участок | Изменение |
| --- | --- |
| Ручное срабатывание расписания | API принимает необязательный UUID в `Idempotency-Key`. Квитанция и время запрошенного слота сохраняются в одной транзакции. Повтор ключа в течение 24 часов возвращает прежний слот даже после выполнения и деактивации одноразового расписания. Веб переиспользует ключ после неизвестного ответа и после перезагрузки той же вкладки, если браузер разрешает `sessionStorage`. |
| Лимит триггеров | Счётчик опирается на принятые запуски за предыдущие 60 минут. Конкурирующие допуски сериализованы по строке триггера. Ограничение в БД исключает второй запуск для того же сохранённого события. Ошибка допуска сохраняет само событие и позволяет обработать другие триггеры. |
| Проверка правила | Диалог оценивает допуск по указанному типу события, состоянию цели, cooldown и часовому лимиту. GET проверяет право чтения и не создаёт запуск. Проверка отражает состояние на момент запроса. Устройства, содержимое события и повторы уже сохранённого события в этой симуляции не учитываются. |
| Скачивание APK | В защищённом контексте браузер проверяет фактические байты по SHA-256 из ответа запроса выбранного канала. При отсутствующем, неверном или несовпадающем хеше файл не сохраняется. CORS разрешает читать служебные заголовки скачивания. |
| Возврат после входа | Разрешённые ссылки сохраняют фильтр локации и точные фильтры задания по устройству или сценарию. Остальные правила проверки пути и прав продолжают действовать. |
| Неизвестный результат создания API-ключа | Форма просит перечитать список. При обнаружении нового активного ключа с тем же именем повтор остаётся заблокированным. |

Дополнительная перепроверка выявила две гонки квитанции. Поздний ответ
мог стереть новый ключ в браузере после смены вкладки. Теперь ответ удаляет
только свой ключ. Если изменение времени или выключение расписания убирает
принятый слот до обработки, API сохраняет один пропуск с причиной в той же
транзакции. Повтор исходного ключа по-прежнему возвращает исходный слот.

## Стендовая проверка

В Chromium через настоящий API и PostgreSQL открыли сохранённый триггер.
`fixture.complete` совпал, `FIXTURE.complete` через API дал отказ по
шаблону. В БД осталось ноль `pipeline_runs`. Из списка расписаний
запросили одноразовое срабатывание. История показала плановое и фактическое
время. В базе сохранились одна квитанция ключа, одно срабатывание и одна
задача на тестовое устройство.

В отдельной проверке с остановленным опросом планировщика Chromium принял
ручной запрос и выключил расписание до обработки. История показала один
пропуск с причиной «Расписание выключено до запуска». PostgreSQL подтвердил
совпадение планового времени с квитанцией и ноль созданных задач.

Через страницу обновлений скачали два управляемых образца байтов в отдельных
каналах. Образец dev с верным SHA-256 сохранился. Образец enterprise с
изменёнными байтами дал предупреждение и не создал второй файл. Образцы
использовались только для проверки скачивания и не были установочными APK.

PostgreSQL под непривилегированной runtime-ролью проверил два одновременных
запроса с одним ключом, повтор после исполнения, изоляцию организации,
откат и истечение квитанции. Отдельные тесты подтвердили пересекающиеся
транзакции при часовом лимите, повтор события, rollback и cooldown. Обе
миграции прошли upgrade, downgrade и повторный upgrade. [Права роли и
порядок выкладки](../../operations/STARTUP.md#квитанции-расписаний-и-лимиты-триггеров).

В общем наборе затронутых backend-модулей прошли 192 теста. После
дополнительной правки прошли 66 тестов расписаний, в том числе запись
пропуска через PATCH, переключение и удаление под runtime-ролью, повтор
ключа и откат транзакции. Итоговый полный Jest прошёл 3407 тестов в 246
наборах. Android Gradle проверил два варианта
`devDebug` и `enterpriseDebug`. В каждом 1302 успешных, три штатно
пропущенных. Оба debug APK собраны. Android lint для обоих вариантов прошёл
с 67 предупреждениями на каждый вариант.
Production-сборка Next.js сгенерировала 30 страниц с
предупреждениями ESLint. Отдельно прошли 26 Node-тестов упаковки и relay,
103 Python-теста упаковки и сверка контракта действий. TypeScript,
Ruff, mypy для изменённых сервисов, OpenAPI и инвентарь 33 таблиц RLS прошли.
Проверка документации прошла 66 тестов, инвентарь содержит 685 Markdown-файлов.
Go-тесты утилиты VPN netstack прошли.
Контейнерная проверка Redis подтвердила вытеснение при достижении лимита,
сохранение данных при одновременной записи и восстановление после рестарта.

### Сбои, найденные в общем прогоне

Первый полный прогон Python с PostgreSQL и Redis показал 6969 успешных
тестов, 47 пропусков и восемь падений. Нагрузочный каталог исключён по
профилю штатного CI. Падения показали следующие причины.

| Участок | Причина и проверка |
| --- | --- |
| Логи Windows PC Agent | Вызов CLI моторного воркера оставлял глобальный порог логирования выключенным после возврата. CLI восстанавливает прежний порог при успехе и ошибке. Повторена последовательность motor CLI, native screenshot и Windows service logging. Прошли 35 тестов и семь подтестов. |
| Фоновый трекинг, два теста | Фоновый набор унаследовал ожидания синхронной верификации. Синхронные сценарии сохранены отдельно, фоновый набор проверяет позу, пока верификация в очереди. |
| AAC в видео Faggio | MP4 округляет длительность аудиотрека до делений контейнера. Проверка допускает до 1 мс и по-прежнему требует точного числа PCM-сэмплов, тишины и исходных таймкодов кадров. Вместе с трекингом прошли 126 тестов и шесть подтестов. |
| Реконструкция маршрута, два теста | Фикстура имитировала старый вызов, и новый checkpoint читал свободное место машины. Фикстура теперь имитирует текущий вызов и проверяет порядок подготовки декодера и HUD. |
| Ресурсы подготовки навигации | Тест ожидал общий каталог вместо фактического каталога задания. С реконструкцией прошли 33 теста. |
| Диагностика совпадений дескрипторов | Подставной объект не содержал `last_diagnostic` из рабочего контракта. Фикстура дополнена, прошли пять тестов. |

Полный повтор Python после исправления этих восьми падений прошёл без
ошибок. Результат: 6978 тестов, 1150 подтестов, 47 пропусков и одно
предупреждение FastAPI о deprecated `regex`. Время прогона 18 минут
7 секунд. Повтор стартовал до последней правки обработки вытеснённого
слота. Эту правку покрывают отдельные 66 тестов расписаний и описанная
выше проверка Chromium и PostgreSQL.

При повторе Jest под параллельной сборкой одно падение выявило нестабильную
фикстуру бинарного JPEG. Единственный кадр мог устареть до отправки, а тест
принимал возврат стика в нейтраль за выполнение команды. Теперь используются
управляемые часы и проверяется фактическая ненулевая команда. Тесты по-прежнему
проверяют бинарное тело и привязку к сессии, эпохе и кадру.

### Наблюдаемость и объём

Ручной запрос оставляет квитанцию и, при замене слота, одну запись
пропуска в истории. Повтор ключа не пишет строку уровня INFO на каждый
запрос. В журнале отладки используется признак наличия ключа без его
значения. Симуляция триггера показывает причину отказа в ответе. Допуск
триггера можно сопоставить с сохранённым событием через запись запуска.
Ротация файлов Windows PC Agent проверена на UTF-8 и сохранение последней
записи. Общие квоты и сроки хранения журналов остаются в
[EP-033](../../operations/WORK-STATUS.md#реестр-продукта).

## Границы приёмки

Квитанция расписания подтверждает принятие слота. Срок действия повторного
подтверждения составляет 24 часа. Просроченные записи могут оставаться до
следующего запроса с ключом для этого расписания. Предел хранения на одно
расписание составляет 256 ключей. Для гарантий повтора вызывающий клиент
должен передать тот же ключ. Временное окно или исчерпание лимита при
обработке воркером всё ещё могут убрать слот без записи в истории.

Часовой предел начинает считать допуски после миграции. Повтор, который
транспорт сохранил как новое событие с другим ID, остаётся отдельным
событием. Причинные циклы между правилами, DST и нагрузочные сценарии
остаются в плане. SHA-256 подтверждает целостность скачанных байтов.
Проверка сертификата и установка APK остаются отдельными условиями
приёмки. Выкладка в рабочий пилот в этом проходе не проводилась.

Реестр сохраняет 9 принятых пунктов из 50. Ещё 33 имеют частичный
результат, семь открыты и один отложен. Доработки расписаний, триггеров,
настроек и обновлений добавили доказательства к EP-023, EP-024, EP-040 и
EP-041. Их оставшиеся критерии записаны в
[реестре продукта](../../operations/WORK-STATUS.md#что-означают-числа-и-насколько-велика-работа).
