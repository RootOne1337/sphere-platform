# Приёмка расписаний и триггеров

14 ноября 2026. Рабочая копия на базе `ab5236c6`. PostgreSQL 15, Redis
7.2 и Chromium работали на изолированном стенде. Интеграционные тесты
проверили реальные транзакции под непривилегированной runtime-ролью.

## EP-023. Расписания

| Проблема | Исправление и доказательство |
| --- | --- |
| CRON мог сдвинуть отсутствующее местное время на весеннем переходе и повторить слот при осеннем переводе часов. | API и воркер используют один расчёт. Весенний пропуск исключается, для осеннего повтора выбирается первое вхождение. Проверены Нью-Йорк, получасовой переход Lord Howe и пропущенный день Apia. Интервалы считаются в секундах, разовое время хранится как абсолютный момент. Chromium показал 06:30 UTC и 01:30 GMT−5 для одного CRON-слота. |
| Воркер мог снять просроченный слот без записи. Изменение имени с теми же параметрами времени могло вытеснить уже наступивший слот. | Воркер записывает пропуск при закрытом окне, слишком раннем слоте и исчерпанном лимите. Правка без изменения временных параметров сохраняет ожидающий слот. Два конкурирующих воркера обрабатывают один ожидающий слот. Дополнительные просроченные слоты сводятся к одной записи с временем первого пропущенного, следующее время находится за моментом обработки. |
| Сохранение устаревшей формы и конкурирующие команды могли перезаписать последнее изменение. | Веб передаёт увиденную ревизию, API сравнивает её под блокировкой строки. Конкурирующие PATCH и переключение проверены в PostgreSQL. В Chromium параллельная правка через API вызвала HTTP 409, форма сохранила черновик и заблокировала повтор. Принятый ключ ручного запуска возвращает исходную квитанцию даже при смене ревизии. |

Прошли 86 тестов расписаний и отмены, включая сохранение старых API-вызовов
без проверки ревизии, отсутствие двойного запуска, историю и откат.
Слот, сохранённый до обновления, может один раз обработаться в прежнее
время. Это сохраняет совместимость с ранее принятыми ручными запросами.
Новый расчёт применяется при следующем вычислении слота. Сводная запись
не перечисляет каждый слот, который наступил во время простоя. Если окно
уже закрыто или лимит исчерпан, воркер записывает пропуск ожидающего
слота и завершает расписание. Если ожидающий слот использовал последний
разрешённый запуск, дополнительная сводка не пишется.
Термины отсутствующего и повторяющегося локального времени описаны в
[PEP 495](https://peps.python.org/pep-0495/).

## EP-024. Триггеры

| Проблема | Исправление и доказательство |
| --- | --- |
| Результат задачи из пайплайна терял источник. Правила могли повторно запускать друг друга. | Связь задачи с запуском и цепочка причин хранятся в PostgreSQL. Проверка через выполнение шага сценария и обработку результата остановила A→B→A перед повторным запуском A. Результат, отправленный повторно, не продолжил цепочку. |
| Несколько правил могли одновременно принять работу от одного исходного события. | Общий предел в 32 запуска, принятых правилами от одного корня, проверяется в транзакции с блокировкой по организации и исходному событию. Глубина ограничена восемью срабатываниями. Две сессии с разными правилами подтвердили ожидание блокировки, оба commit и один допуск при одном свободном месте. В отдельном тесте PostgreSQL вернул сохранённое отклонённое событие. |
| Повтор доставки с новым серверным ID проходил проверку как новое событие. | Совместимый отправитель WebSocket передаёт UUID `event_id`. Повтор одного ключа в пределах устройства и организации переиспользует запись и не публикует второе событие. Cooldown и часовой лимит действуют для каждого правила. |
| Симуляция по типу не могла объяснить повтор или происхождение конкретного события. | GET поддерживает ID сохранённого события при правах `pipeline:read` и `event:read`. Отображаются причина, корень и лимиты. PostgreSQL проверил изоляцию организации, Chromium показал происхождение и `0 / 32`. После проверки в базе осталось ноль запусков правила. |

Прошли 164 теста событий, результатов задач, пайплайнов и WebSocket.
Новые колонки допускают старые строки. Миграция `20261114_trigger_causality`
прошла чистую установку, downgrade и повторный upgrade. Входящий кадр без
UUID доставки сохраняет прежнее поведение. Причинная связь выводится из
задачи и запуска, подтверждённых сервером. Кадры без такой связи и события,
которые заново создала внешняя система без идентификатора, учитываются
как самостоятельные. Если исходное событие удалено, допуск для связанной
цепочки прекращается. Публикация в fleet WebSocket выполняется один раз
после commit. Повтор ключа сохраняет дедупликацию при сбое публикации,
которая требует отдельного долговечного механизма доставки.

Подготовка браузерной проверки выявила HTTP 500 в POST `/device-events`.
Сериализация после INSERT пыталась лениво загрузить связанное устройство
вне асинхронного контекста. API явно разрешает связанные записи в пределах
организации и возвращает уже загруженные данные. Пять HTTP-тестов проверили
создание, чтение и отказ по неподтверждённым связям. В Chromium также
исправлена вложенность элемента результата, вызывавшая предупреждение React.

## Следующие приоритеты

- **EP-025.** Callback задачи пишет один итог с ID доставки, ID задачи,
  числом попыток и последним сроком повтора, если он был назначен.
  Промежуточные попытки остаются на DEBUG. Веб показывает, что публикация
  событий в реестр не подключена. Прошли 89 Python-тестов, восемь Jest-тестов
  и пять сценариев с локальным HTTP-получателем. В этих сценариях отдельно
  проверен HMAC транспорта при переданном секрете. Действующий callback
  задачи секрет не передаёт. Durable outbox, DLQ и replay остаются.
  [Контракт вебхуков](../../operations/N8N-INTEGRATION.md).
- **EP-033.** Метрика журналов разделяет логические байты истёкших файлов и
  отказов по дневной и общей квоте. Учитываются успешные удаления. Тесты
  проверили точные дельты и отсутствие прироста при неудачном удалении.
  Прошли 84 Python-теста. Квота на организацию, проверка нескольких реплик,
  установленный сбор метрик и восстановление остаются.
  [Контракт хранения журналов](../../operations/DEVICE-LOG-STORAGE.md).

Квитанции расписаний и цепочки триггеров читаются из базы. Повторы ключей
не создают отдельный поток INFO. Метрика журналов имеет три фиксированных
значения метки и не содержит ID организаций или устройств.

## Общий прогон

Финальный Python-прогон с PostgreSQL и Redis прошёл 7016 тестов и
1150 подтестов. 47 пропусков, ноль падений. Покрытие backend составило
84,64% при пороге CI 65%. Сохранились два предупреждения, об устаревшем
`regex` в FastAPI и о свойствах JUnit `xunit2`. Нагрузочный каталог
исключён по штатному профилю CI.

Веб прошёл 3411 тестов Jest в 246 наборах. TypeScript и production-сборка
прошли, сборка сгенерировала 30 страниц с предупреждениями ESLint. Android
прошёл по 1302 теста с тремя пропусками для `devDebug` и `enterpriseDebug`.
Gradle завершился успешно и отбросил configuration cache из-за
`:awg-sdk:verifyUpstream`. Оба debug APK собраны, lint завершился без
ошибок с 67 предупреждениями на вариант. Сверка OpenAPI, инвентарь RLS на 33 таблицы,
Ruff и mypy для затронутых модулей, а также 66 тестов документации прошли.
Отдельно прошли 26 Node-тестов упаковки и прокси, 103 Python-теста
упаковки и сверка сгенерированного контракта действий.
Go-тесты VPN netstack прошли. Изолированная проверка Redis подтвердила
вытеснение при лимите, запись во время сохранения и восстановление при рестарте.

## Границы приёмки

Приёмка EP-023 и EP-024 относится к проверенным сценариям на стенде.
Выкладка, нагрузка на реальном парке и длительный прогон отдельно
отражаются в реестре. Браузерная проверка использовала REST API. Локальный
Next dev proxy не подключал fleet WebSocket, чей backend-путь проверялся
отдельно.
