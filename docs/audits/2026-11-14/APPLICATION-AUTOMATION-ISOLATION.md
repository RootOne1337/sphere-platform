# Привязки приложений и изоляция регистрации и фарма

**14 ноября 2026.** Реализация и приёмка на отдельном стенде с PostgreSQL 15,
Redis 7.2, FastAPI, веб-интерфейсом и тремя клиентами протокола Android WebSocket.

## Что изменилось

| Участок | Поведение |
| --- | --- |
| Парк и карточка устройства | Оператор выбирает профиль своей организации и один из его серверов. БД хранит ID профиля, стабильный ключ сервера и ревизию. Веб перечитывает сохранённое состояние. При конфликте ревизий форма просит обновить данные. |
| Смена привязки | Активная задача, открытый pipeline, активная сессия или используемый либо регистрируемый аккаунт дают HTTP 409. Допуск обычных и запланированных запусков согласован с записью привязки через блокировку устройства. |
| Настройки автоматизации | Для каждого профиля отдельно сохраняются сценарии, переключатели, лимиты и таймауты регистрации и фарма. Фарм также использует целевой уровень и кулдаун. Включённой операции нужны Android package и активный опубликованный сценарий организации. Параметры вступают в силу при следующем допуске. |
| Пул аккаунтов | Для привязанного устройства должны совпасть точные ключ приложения и имя сервера из каталога. Проверка работает при ручном назначении, старте сессии, выборе аккаунта для задачи и pipeline, отправке задачи и ротации. При несовпадении учётные данные не отправляются устройству. |
| Результаты задач | AUTO-задача хранит роль, ID профиля, версию сценария, ID аккаунта, отметку его назначения и кулдаун для фарма. Завершение применяется один раз. Поздний результат после переназначения аккаунта не меняет новое назначение. |
| Совместимость | Миграция оставляет прежние устройства без явной привязки. Встроенная Black Russia продолжает работать через прежние настройки. Старые ключи аккаунтов, включая `black_russia` и `com.br.top`, сохраняются. Историческая задача без новых полей обрабатывается по прежнему сценарию. |

Серверы представлены в каталоге именем, адресом и портом. Привязка определяет
допуск и пул аккаунтов. Android-пакет и сетевой маршрут во время работы выбирает
сам опубликованный сценарий. Параметры профиля и запись в очереди позволяют
создать задание на устройство без подтверждённой связи, доставка ждёт
подтверждения присутствия.

## Стендовая проверка

| Проверка | Наблюдение |
| --- | --- |
| Миграция существующей задачи | На ревизии `20261114_application_profiles` создали устройство, аккаунт и задачу `queued`. Применили `20261114_automation_profiles`, запустили API с runtime-ролью и активным RLS. Попытка перепривязать устройство с ожидающей задачей вернула 409. Диспетчер отправил прежнюю задачу, клиент получил `result_ack`, воркер обработал прежний аккаунт. ID задачи, аккаунта и версии сценария совпали до и после. |
| Запись в интерфейсе | В Chromium открыли карточку устройства, выбрали профиль и `Central`. Карточка показала пару после повторного GET. На странице настроек изменили целевой уровень этого профиля, и форма подтвердила результат повторным чтением. |
| Одинаковые имена серверов | Оба профиля содержали `central / Central` и контрольный сервер `remote / Remote`. API отклонил четыре назначения, два между профилями и два между серверами одного профиля. |
| Регистрация | Каждый из двух клиентов получил команду с версией своего сценария. Перед отправкой результата изменили сценарий политики и выключили регистрацию. Оба результата дошли до `result_ack` и перевели соответствующие аккаунты в `free`. |
| Фарм | В отдельной части той же проверки подготовили по одному аккаунту с логином `shared_operator_login` на `Central` каждого профиля. Каждый клиент получил свою версию сценария и свой ID аккаунта. После отключения политики подтверждённые результаты сохранили уровни 3 и 4, по одной сессии у каждого. Два контрольных аккаунта на `Remote` остались неназначенными. |
| Роли и схема | На отдельной базе проверили свежий upgrade, downgrade до каталога и повторный upgrade. Интеграционные тесты с non-owner ролью проверили изоляцию организаций, права, гонку первого сохранения, блокировку устройства при запуске по расписанию и завершение открытой сессии. |

Регрессионные прогоны дали 74 успешных pytest-проверки диспетчера, задач,
оркестрации и аккаунтов, 58 проверок API и расписаний на другой тестовой базе
и 233 Jest-теста интерфейса. Наборы pytest частично пересекаются. TypeScript,
Ruff, mypy для изменённых сервисов, сверка RLS и OpenAPI прошли.

## Наблюдаемость

Изменения привязок и политик ищутся в журнале аудита по действиям
`put.devices.application-binding` и `put.application-profiles.automation-policy`.
Запись содержит ID ресурса, результат запроса и корреляционный ID. Для
расследования отказа конкретной задачи доступны её ID, терминальное состояние и
причина в API задач. Отказ из-за пула аккаунта оставляет одно предупреждение на
завершённую задачу. Обычные конфликты выбора кандидата доступны на уровне DEBUG.

`sphere_orchestration_failures_total` считает ошибки поиска работы, сбои
обработки организации и недоступность настроенного сценария. Метки ограничены
этими тремя причинами. Повторные предупреждения ограничены одним на причину за
60 секунд на процесс, счётчик при этом продолжает расти. Предупреждение о
сценарии содержит ID профиля и сценария для поиска причины. DAG, токены и
пароли в эти события не записываются.

На стенде архивировали выбранный сценарий при включённой политике. Счётчик
недоступных сценариев вырос как минимум дважды за два опроса воркера.
В журнал попало одно предупреждение с ID профиля и сценария.

## Границы приёмки

- Клиенты WebSocket имитировали Android-агентов. Проверены доставленная
  команда, подтверждение результата и изменения в БД. Установка двух реальных
  игр, действия внутри APK и вход на игровые серверы требуют отдельного прогона.
- Привязка действует на уровне устройства. Ожидающая волна массового запуска
  резервирует устройство после создания задания. До этого смена привязки возможна,
  и дальнейшая проверка аккаунта использует актуальную пару.
- Рабочая установка требует применения миграции и явной выдачи прав роли.
  Сбор метрик, доставка алертов и поведение под реальной нагрузкой проверяются
  при выкладке. [Выдача прав и откат](../../operations/STARTUP.md#привязки-устройств-и-автоматизация-по-профилям-приложений).
