# Результаты автоматизации Android и повтор старого сценария

**14 ноября 2026.** Проверены установленный Android-агент PH025 на действующем
пилоте, новый код обработки Android DAG и совместимость исторической версии
с новой схемой на отдельном стенде.

## Исправления

Android передавал только общее состояние графа и журнал узлов. Оркестратор
читал `level` и `ban_detected` из верхнего уровня результата. Предыдущая
стендовая проверка записывала эти поля через имитатор, тогда как реальный
DagRunner их не формировал. Из-за этого автоматический фарм не мог обновить
уровень и завершить учёт по достигнутой цели.

На конечном узле `end` теперь можно явно указать переменные для `level`
и `ban_detected`. Публикация проверяет поля и имена переменных. APK передаёт
только два известных поля с допустимыми типами. Уровень передаётся при успешном
исполнении. При отмене и общем таймауте результаты не экспортируются. Старые
графы без нового параметра возвращают прежние поля. В регистрации явный
`ban_detected: true` сохраняет статус блокировки вместо отметки об успешной
регистрации. [Настройка сценария](../../operations/TASKS-AND-ORCHESTRATION.md#результат-регистрации-и-фарма-из-android-сценария).

## Что подтверждено

| Проверка | Результат |
| --- | --- |
| Старый сценарий на PH025 | В пилоте с API `1afdc529` и схемой `20261021_vpn_profiles` проверили присутствие и отсутствие активных задач и пайплайнов. Из базы взяли исходную версию `1f5ee5b5-161d-40ef-b243-17112cfd6b60` с графом `start → end` и сверили SHA-256. Новый запуск `1259894b-e2e7-47d2-b36b-102432726d76` на PH025 за 3,34 с дошёл до `completed`. Результат подтверждён HTTP и независимым чтением PostgreSQL, сохранены два ожидаемых узла и прежний формат. |
| Повтор на новой схеме | Точный исторический DAG, ID версии и хеш перенесли в одноразовую БД до D2. После миграции API `rerun` создал новую задачу `d9c90e91-dcb0-46c1-a70f-9e41eac1ac08` с исходной версией. Имитатор получил тот же DAG по WebSocket, отправил результат и получил `result_ack`. |
| Новые поля Android | 42 JVM-теста DagRunner. В исполняемых графах проверены экспорт значения из `set_variable`, сигнал блокировки в обработанной ветке ошибки, отбрасывание некорректных значений и прежний формат старых графов. |
| Сервер и публикация | 128 pytest-проверок, включая PostgreSQL и Redis, изоляцию профиля/сервера и повтор обработки результата блокировки. 91 Jest-тест общего контракта действий, TypeScript и Ruff прошли. |

Установленный на PH025 агент выполнил проверку обратной совместимости. Свежий
стендовый APK 1.2.92-dev установился и запустил сервис на чистом Android 14.
ADB shell видел VM serial, из UID приложения `ro.boot.serialno` и
`ro.serialno` были пустыми. Агент штатно отказался подтверждать идентичность
этой VM. В исходной конфигурации Android 16 отдельно воспроизвёлся сбой
`surfaceflinger` до запуска APK. Временные эмуляторы удалены.

По уточнению владельца запуск внутри игр снят с текущего прогона. Поэтому
измеренные в игре уровень, сервер и факт регистрации остаются без подтверждения.
В базе пилота на момент проверки не было игровых аккаунтов или назначенных
сценариев регистрации и фарма. Исторический `seed_farming_dags.py` относится
к Black Russia и содержит пять экземпляров неподдерживаемых действий в графе
фарма. Его ветка обнаружения блокировки при регистрации завершалась обычным
`end`. Исходные графы сохранены для истории, исправление контракта
используется в опубликованных сценариях с явно настроенным результатом.
