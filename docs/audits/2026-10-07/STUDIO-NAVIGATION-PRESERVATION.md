# Script Studio: сохранность работы при общей навигации

Дата: 7 октября 2026. Область: продолжение EP-014/018 и SF26-01/04.
Связано с [аудитом взаимодействий](../2026-10-06/STUDIO-INTERACTION-FOLLOWUP.md).

## Подтверждённый пробел

Редактор проверял свою кнопку возврата и `beforeunload`, но Next Link в общем
меню, хлебных крошках и лаборатории мог сменить маршрут без этих проверок.
Глобальный поиск вызывал `router.push` напрямую; выход из аккаунта начинал
`signOut` до проверки редактора. Это позволяло потерять неопубликованный граф,
неприменённые параметры и невставленную запись. Нет утверждения, что это
было причиной конкретной потери данных оператора.

## Реализация

- [Общая регистрация защиты](../../../frontend/src/features/navigation/workspaceNavigationGuard.ts)
  живёт только в памяти смонтированной страницы. Каждый экземпляр имеет
  собственную регистрацию; удаление старой регистрации не снимает новую.
- [Редактор](../../../frontend/app/(dashboard)/scripts/builder/page.tsx) проверяет
  текущие изменения и существующий guard лаборатории. Во время проверки или
  сохранения переход блокируется до ответа. Успешное сохранение сохраняет
  собственный переход в каталог и не отправляет второй запрос.
- Обычная активация ссылки проверяется до React/Next и закрытия мобильного меню.
  Ссылка с другой query-строкой тоже проверяется: она может заменить сценарий.
  Переход к якорю текущего документа, скачивание и открытие другой вкладки
  сохраняют обычное поведение, поскольку не уничтожают текущий редактор.
- [Глобальный поиск](../../../frontend/src/features/navigation/GlobalCommandPalette.tsx)
  применяет тот же guard ко всем маршрутам и быстрым действиям. При отмене
  поиск остаётся открыт. [Выход из аккаунта](../../../frontend/src/features/navigation/NOCSidebar.tsx)
  проверяется до отзыва сессии и перехода на login.
- [Лаборатория](../../../frontend/src/features/scripts/studio/DeviceWorkbench.tsx)
  открывает журнал для неизвестного результата и карточку подтверждённого
  задания в новой вкладке. Это сохраняет путь расследования без уничтожения
  текущей записи и без снятия блокировки повторного запуска.

Никакие токены, графы или записи не добавляются в глобальный registry.
Монтирование в React StrictMode не дублирует обработчик; после ухода listener
снимается. Ошибка guard блокирует переход вместо молчаливого разрешения.

## Продолжение: диалог Studio вместо системного confirm

Первая поставка `8780744` установлена отдельно от API `a41c4e6`. Встроенный
браузер при проверке native confirm вернул timeout, затем показал другой маршрут
без доступного диалога. Отмена через native confirm поэтому **не принята**
как browser evidence. Это основание заменить подтверждение общей навигации
собственным [Radix-диалогом](../../../frontend/src/features/scripts/studio/StudioLeaveDialog.tsx).

Диалог перечисляет актуальные причины: неопубликованный исходник, неприменённые
параметры шага и контекст лаборатории. Действия: остаться, скачать JSON и
остаться, явно выйти без сохранения. Escape и закрытие снаружи означают отмену;
начальный focus — на безопасном действии. JSON не обещает сохранить невставленную
запись или неприменённые поля. Внутреннее подтверждение смены устройства остаётся
отдельным; native `beforeunload` сохраняется для перезагрузки и закрытия вкладки.

Registry принимает асинхронный ответ. Пока оператор читает окно, обычная ссылка,
поиск и sign-out не начинают переход или отзыв сессии. Подтверждённая ссылка
активируется один раз только если её адрес, присутствие в DOM и владелец guard
сохранились. Удаление/замена владельца, смена сессии и отказ Promise отменяют
ожидание. Второй запрос перехода не подменяет первое ожидающее намерение.
Перед положительным ответом Studio повторно проверяет живое состояние команды:
ожидающий или неизвестный запуск не становится разрешённым из-за открытого окна.

Scoped проверка продолжения: **112 тестов / 6 suites**, source-only TypeScript
прошёл. Покрыты однократный replay, отмена, смена href, удаление владельца,
rejected guard, замена auth-сессии, повторное намерение и смена состояния команды
во время подтверждения. Полная регрессия продолжения: **1733 теста / 135 suites**,
все прошли. Fresh CI и установленная визуальная приёмка этого продолжения
записываются отдельным срезом после их завершения.

## Проверки и границы

Первый scoped прогон: **142 теста / 6 suites**, включая реальные компоненты
builder, workbench, sidebar и command palette. Source-only TypeScript прошёл.
Стандартная локальная проверка типов обнаружила прежний `.next/types/validator.ts`
со ссылкой на удалённую `app/(dashboard)/page.js`; она не объявлена успешной.
Fresh types/build и установленная browser-приёмка проверяются отдельно.

Последующий полный локальный прогон: **1719 тестов / 134 suites**, все прошли.
Первая полная попытка выявила stub Next Link, терявший `target`/`rel` в тесте
workbench; stub исправлен передачей реальных anchor attributes. Проверка
открытия журнала в новой вкладке сохранена и прошла; assertion не ослаблялся.

Проверены отмена/разрешение, сохранение исходника, ожидание публикации,
отсутствие второго запроса, внешняя ссылка и query replacement, portal content,
модификаторы, download, new-tab, unregister и StrictMode lifecycle. Для неизвестного
результата запуска повтор остаётся заблокирован; новая вкладка не считается
подтверждением исполнения или долговечной идемпотентностью.

Это защита ссылок приложения, global search, explicit logout и предупреждение
браузера при закрытии/перезагрузке. Browser Back/Forward внутри SPA и произвольный
`router.push` других компонентов не перехватываются; forced auth expiry не
блокируется. Здесь не реализованы сохранение записи на сервере, crash recovery,
backend idempotency или полный route blocker Next. При необходимости продолжить
проверку после ухода экспортируйте граф и проверьте задания по ID.

Установленный baseline до поставки: UI/API **a41c4e6**. Этот source change
не обновляет APK, SQL, другие контейнеры или записи сценариев. Общий ledger
**9 accepted / 41 open** не закрывается одной регрессией.
