# Подготовка измерений задержки серийного ввода

Пользователь наблюдал на PH030 рост ACK до 100–300 мс при быстрых кликах,
хотя браузер и эмулятор находятся на одном ноутбуке. В прочитанном активном сеансе
APK 76 оба маршрута были direct, одна попытка peer, примерно 55 FPS, сеть 1–5 мс
и последние ACK 12–17 мс. Пики в редкие десятисекундные срезы не попали.
Этого недостаточно, чтобы приписать задержку сети или Android.

Подготовлены отдельные bounded-измерения:

- В браузере фиксированное окно последних 128 подтверждённых действий сохраняет
  p95 и максимум ACK RTT. Idle heartbeat не вытесняет клики. Максимум остаётся
  в сводке сеанса после вытеснения исходного среза; новая сессия не наследует его.
- APK измеряет ожидание в shared mailbox и обработку в акторе. Последняя включает
  арбитраж, native submission/ACK и возможную работу IME. Она не означает время
  завершения действия приложением. Окно также ограничено 128 действиями.
- API валидирует размеры, диапазоны и согласованность скаляров. Нет траекторий,
  координат, текста, клавиш, владельцев или дополнительного потока событий.

Для отделения служебного каталога от live-подключения кнопка видеопотока в карточке
больше не блокируется только из-за offline/устаревшего heartbeat. Право stream:read
проверяется прежним способом, а WebSocket отдельно авторизует выбранное устройство.
Команды карточки и native screenshot по-прежнему требуют свежей доступности.

Локально прошли 2439 frontend tests / 168 suites и проверка TypeScript;
140 targeted backend telemetry/history tests; 18 Android controller/diagnostic tests.
Версия исходников поднята до 1.2.77. Это подготовка: подписанная сборка APK 77,
полные проверки вариантов, установка веба/API/APK и фактическое измерение серии
нажатий на новой версии ещё не выполнены. Уменьшение задержки пока не заявляется.
