# Наблюдения по учёту фарма и освобождению аккаунта

14 ноября 2026, checkout `6c08c0e1`. Отдельный контейнер PostgreSQL 15 на loopback, пустая БД, миграции `alembic -c alembic/alembic.ini upgrade head` до `20261021_vpn_profiles`. Использованы штатные методы сервисов настроек, задач, аккаунтов и runner. В пробе результата подменена очистка Redis lock, в пробе пайплайна синхронизирована пауза между шагами. Работа на Android моделировалась сообщением успешного результата. [Код пробы](automation-closure-probe.py) · [Отчёт](../AUTOMATION-CLOSURE.md).

| Сценарий | Состояние после commit |
| --- | --- |
| Успешный результат задачи старого скрипта после смены настройки | Task `completed`, учёт отсутствует, аккаунт `in_use` |
| Контроль с возвращённым исходным ID | Учёт отмечен, аккаунт `free`, `total_sessions=1` |
| Штатная отмена задачи до отправки | Task `cancelled`, учёт отсутствует, аккаунт `in_use` |
| Ручной release и назначение B между шагами A | Аккаунт `in_use` на B, `total_sessions=1`, сессия A открыта |
| Шаг release прежнего запуска | Run `completed`, аккаунт `free` без устройства, `total_sessions=2`, сессия A закрыта |

Для повторения из корня репозитория использовать выделенную синтетическую БД `sphere_automation_closure_audit` на loopback и обычные тестовые переменные окружения, в том числе `PYTHONPATH=.;pc-agent` для Windows. После применения миграций запустить `python docs/audits/2026-11-13/evidence/automation-closure-probe.py`. Проба проверяет имя и адрес БД перед подключением. Рабочие креды, таблицы и устройства не используются.
