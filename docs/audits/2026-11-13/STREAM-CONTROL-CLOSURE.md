## STRCTRL-01 · P2. Отменённый до исполнения ввод блокирует перенос записи

У Android-навигации есть два исхода с установленным отсутствием исполнения. Прямой канал возвращает `not_sent`, когда текущий контроллер не принимает команду. В резервной цепочке APK возвращает `device_input_busy`, если `claimDiscrete()` отклоняет захват ввода до вызова `shellExec`. HTTP сохраняет этот код в поле `error`. В обеих ветках `AndroidNavigationBar` сбрасывает `submitted` и показывает «команда не отправлена». Однако наблюдателю записи компонент в обеих ветках отправляет `phase: 'unknown'`. Reducer сохраняет `android-unknown`, а Studio блокирует перенос **всей** записи до удаления этой строки. После клика «Домой» обе ветки дали одинаковую последовательность `submitted → unknown`, одну запись `android-unknown` и отказ `recordingActions` с текстом «нет подтверждённого результата». Приёмка — одинаково трактовать `not_sent` и подтверждённый отказ до выполнения в панели и Studio. Такой отказ исключается из переносимой записи и освобождает ожидание. Потерянный ответ, неполная квитанция и смена сессии во время отправки сохраняют состояние «результат неизвестен» и блокировку до проверки оператором. Проверить запись с двумя успешными действиями и отказом между ними, перенос без отказа, сохранение порядка, отсутствие автоповтора и игнорирование запоздалого ответа старой сессии.

## Приёмка расширений и диагностики

- Для ручного ввода, управления приложениями, снимков и файлов различать допуск, доставку, выполнение и наблюдаемое состояние устройства. Файлы получают подтверждение проверенной записи с размером и хешем. Для системного диалога требуется локальный результат, для старта потока отдельно наблюдается первый декодированный кадр. Проверить эти цепочки на тестовом эмуляторе и физическом Android при обрыве, reconnect и обновлении страницы. [Файлы](DEVICE-EXTENSIONS.md#файлы-в-карточке-устройства) · [Управление Android](ANDROID-CONTROL-PLAN.md#порядок-работ-и-критерии-приёмки).
- Для интерактивного HTTP backend уже журналирует `interactive_rpc.finished` с `command_id`, стадией и исходом. В Web локальный ID записи генерируется отдельно, а панель берёт из API только `data`. Для поддержки связать операцию браузера с серверным ID, показать исход и время, в диагностике direct-канала агрегировать задержки и отказы по сессии. В квитанции и логи включать тип действия и нормализованную причину. Введённый текст, shell stdout, дерево, кадры и байты файлов хранить только в предназначенных для них пользовательских данных с отдельными лимитами. Критерий — из UI найти один подтверждённый отказ, один timeout и одно успешное действие без дубликатов, с ограниченным ростом логов при серии reconnect.
