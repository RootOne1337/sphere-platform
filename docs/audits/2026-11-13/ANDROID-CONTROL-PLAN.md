Проверка `matchesFrame` из исходного TypeScript вернула `true` для snapshot 960×540 с `rotation=1` и `rotation=3` при одном кадре 1280×720. Контрольный портрет 720×1280 вернул `false`. Функция сравнивает пропорции, а контракт кадра здесь не содержит ID или поворот. Поэтому overlay и кнопка вставки XPath могут принять старое дерево после смены окна или поворота с теми же пропорциями. Фикстура `parse_hierarchy` с синтетическими `text` и `content-desc` также подтвердила, что оба атрибута остаются в выдаче текущего провайдера. | Этап | Изменение | Наблюдаемый результат |

| 1. Возможности и согласие | Добавить в карточку источник и свежесть для capture/input, профиля Android, каталога приложений и провайдера управления. Сверять полномочия в API и агенте. Для MediaProjection и installer выдавать состояния «запрошено», «ожидает действия на Android», «отклонено», «истекло», «подтверждено Android», «результат неизвестен». Для видео отдельно показать первый декодированный кадр. Действие пользователя проходит через системный диалог. [MediaProjection](https://developer.android.com/media/grow/media-projection) · [Запуск Activity из фона](https://developer.android.com/guide/components/activities/secure-bal). | Отказ и закрытие диалога видны в Web. Изменения runtime permissions возможны только в пределах поддерживаемой политики device owner, profile owner или делегата; системные разрешения показывают собственное состояние. Минимальная стендовая матрица — физический Android без root, управляемый рабочий профиль при наличии EMM, согласованный эмулятор с уже настроенным управлением, API 26 как нижняя граница сборки и API 34/35 для MediaProjection. ## Квитанции и бюджеты

Мутация получает стабильный `operation_id`, срок и конечный результат после сверки устройства. Записывать переходы состояния с org/device/actor, типом, причиной из закрытого списка и временем. Начальный бюджет для пилота — до 1 KiB на переход, до 8 событий на операцию, с дедупликацией по ID операции и переходу. Технические повторы агрегировать счётчиком. PNG и дерево хранить отдельно от логов с квотой и TTL. Начальные верхние пределы — 5 MiB для PNG и 128 KiB/4096 узлов для дерева, как в действующих обработчиках. Содержимое экрана и дерева, введённые строки, байты APK и ключи доступа исключить из журналов. Метрики получают тип операции и исход, а поиск по ID работает в квитанциях. Проверка — серия reconnect/повторов сохраняет одну конечную запись и укладывается в бюджет, в том числе при медленном или полном хранилище.
