# Диагностика и операторские журналы Web

Проверка 13.11.2026 по текущему рабочему дереву от `b8273839c0787ce865892c47577aa1b764117cc0`. Проверены пути от пользовательского действия до журнальной записи, история WebSocket, область поиска и данные, доступные для передачи инцидента. Использованы временные файлы, синтетические HTTP/WS-события и Jest/jsdom с текущими React-компонентами. Продуктовый код и работающие сервисы не менялись.

## LOGWEB-01. Из Web нельзя открыть сохранённый дневной журнал за нужную дату

В `/logs` можно выбрать устройство, искать строку, фильтровать уровень, обновлять просмотр и включать автоматическое обновление. Путь из VPN передаёт `device_id`, поэтому устройство сохраняется. Поле `date` интерфейс не читает даже из URL, а в GET передаёт `lines=1000` и необязательный `search`. Оператор видит предупреждение об ограниченной области поиска. Из той же страницы нельзя выбрать конкретный дневной файл или экспортировать полученный журнал. Вкладка «Логи APK» инспектора запрашивает только последние 100 строк и не показывает метаданные области чтения. [Переход из VPN](../../../frontend/src/features/vpn/VpnRouterInfrastructure.tsx#L259) · [Параметры страницы](../../../frontend/app/%28dashboard%29/logs/page.tsx#L129) · [GET из Web](../../../frontend/app/%28dashboard%29/logs/page.tsx#L179) · [Предупреждение](../../../frontend/app/%28dashboard%29/logs/page.tsx#L314) · [Инспектор](../../../frontend/src/features/devices/DeviceOperationsPanels.tsx#L113).

Сервер хранит файлы по UTC-дням. Без `date` читатель берёт не более трёх последних файлов и сканирует до 2 MiB, ответ ограничен 512 KiB. `GET /logs/{device_id}` принимает дату `YYYY-MM-DD` и применяет `device:read` и проверку устройства. Для файла за указанную дату остаются лимиты на чтение и ответ. [Имена файлов и ротация](../../../backend/api/v1/logs/router.py#L48) · [Контракт GET](../../../backend/api/v1/logs/router.py#L158) · [Ограничения читателя](../../../backend/services/device_log_reader.py#L15) · [Отбор файлов](../../../backend/services/device_log_reader.py#L51).

В проверке четыре коротких файла от 10–13 ноября. Только `agent_2026-11-10.log` содержит `isolated_archive_incident`. Настоящий читатель с параметрами из Web вернул `total=0`, `files_scanned=3`, `files_available=4`, `truncated=true`, причина `file_limit`. Явный `date=2026-11-10` вернул эту строку. Настоящий React-компонент при переходе с `?device_id=audit-fixture&date=2026-11-10` и поиске строки отправил `?lines=1000&search=isolated_archive_incident` без даты. Для расследования приходится покинуть UI и повторить авторизованный запрос с отдельной датой. [Стендовый читатель](evidence/logging-web-probe.py) · [Проверка GET из UI](evidence/logging-web.test.cjs).

Критерий приёмки. В интерфейсе можно открыть разрешённое устройство за выбранную UTC-дату, передать ссылку с датой и увидеть границы выборки при поиске и сохранении результата. Контрольный инцидент из четвёртого файла находится с датой, а отсутствие совпадения в ограниченной области сопровождается существующим предупреждением.

## LOGWEB-02. Тайм-аут WebSocket выглядит как отказ в доступе, запись инцидента не создаётся

`/ws/stream/{device_id}` ждёт первое сообщение 10 секунд. При тайм-ауте сервер закрывает соединение `4003/auth_timeout`, при действительном запрете `stream:read` использует тот же код `4003` с `stream_access_denied`. Регистрация диагностического сеанса начинается после первичной авторизации и регистрации зрителя в видеомосте. Браузер смотрит только `event.code`, показывает «У этой учётной записи нет доступа к просмотру устройства» и отключает автопереподключение для обоих исходов. Проверка настоящего обработчика WebSocket с синтетическим тайм-аутом получила `4003/auth_timeout`, конструктор истории не вызван. Проверка настоящего `DeviceStream` получила одинаковый итог по коду `4003` и сохранила единственную попытку через 60 секунд по тестовым часам. [WS: тайм-аут и права](../../../backend/api/ws/stream/router.py#L113) · [Начало истории](../../../backend/api/ws/stream/router.py#L174) · [Закрытие в Web](../../../frontend/components/sphere/DeviceStream.tsx#L1037) · [Python](evidence/logging-web-probe.py) · [Jest](evidence/logging-web.test.cjs).

После успешной регистрации журнал содержит `session_id`. Он попадает в структурированный лог `Stream viewer connected` и в HTTP-историю, а панель использует его только как React key. Два сеанса с одинаковой секундой открытия, состоянием и без образцов дали две строки с одинаковым текстом и без ID в DOM. У оператора остаются устройство и локальное время, а идентификатор для сопоставления можно получить из разрешённого JSON или серверного журнала. Панель показывает последний образец браузера, последнюю APK-стадию и последние доступные отказы. При сбое чтения она явно показывает недоступность истории. [Серверный ID](../../../backend/api/ws/stream/router.py#L182) · [HTTP-история](../../../backend/api/v1/direct_probe/router.py#L50) · [Отображение строки](../../../frontend/src/features/stream/StreamSessionHistoryPanel.tsx#L65) · [Два сеанса в Jest](evidence/logging-web.test.cjs).

Критерий приёмки. Временный тайм-аут получает отдельное состояние и ограниченную повторную попытку, подтверждённый запрет остаётся терминальным. Оператор видит идентификатор или безопасную ссылку для копирования из разрешённой истории. Экран различает недоступность истории и состояние попытки, завершившейся до регистрации сеанса.

## LOGWEB-03. Два действия над устройством неразличимы по действию и HTTP ID в аудите

Серверный `RequestIdMiddleware` связывает `request_id` с контекстом структурированного лога и добавляет `X-Request-ID` в ответ. `audit_middleware` сохраняет `action` из метода и первого сегмента после `/api/v1/`, UUID ресурса и три поля метаданных `status`, `duration_ms`, `http_status`. Для `POST /devices/{id}/ui-hierarchy` и `POST /devices/{id}/screenshot/native` с тем же устройством оба действия становятся `post.devices`. Детали в Web умеют показать `request_id` и `trace_id`, если их прислал сервер. Обычная запись middleware этих полей не содержит. Полнотекстовый поиск проверяет ID события, дату, пользователя, действие, ресурс и IP. CSV выгружает эти поля и итог операции, поэтому поиск и выгрузка не восстанавливают связь с HTTP-запросом. [HTTP ID](../../../backend/middleware/request_id.py#L27) · [Нормализация действия](../../../backend/middleware/audit.py#L36) · [Запись](../../../backend/middleware/audit.py#L98) · [Детали в Web](../../../frontend/src/features/audit/AuditDrawer.tsx#L13) · [Поиск и CSV](../../../backend/services/audit_query.py#L40).

Изолированное ASGI-приложение с обоими настоящими middleware и имитацией двух обработчиков ответило `503` на каждый запрос. Ответы сохранили разные `X-Request-ID` (`fixture-hierarchy`, `fixture-screenshot`). Две записи, переданные на сохранение, имели один UUID устройства, действие `post.devices` и одинаковый набор ключей метаданных. Оригинальный CSV-генератор с проекцией экспортного запроса не выгрузил ни один из этих ID. Разные ID самих событий аудита сохраняются, но не указывают на HTTP-запрос или конкретный вид команды. Запись в рабочую БД в проверку не входила. [ASGI-проба](evidence/logging-web-probe.py) · [Проекция экспорта](../../../backend/api/v1/audit/router.py#L71).

Критерий приёмки. Оператор может найти разные операции для одного устройства и связать каждую с её HTTP ID в серверном журнале. Ограниченный CSV включает разрешённые поля корреляции, а существующие границы организации и `audit:read` сохраняются. Тела команд и произвольные метаданные в CSV не требуются.

На проверенных участках Web ошибки HTTP попадают в состояния экрана, а события закрытия транспорта обрабатывают соответствующие хуки. В журнале и просмотре потока нет отдельного пакета для выгрузки browser-console, HTTP и WS вместе. Browser DevTools остаётся отдельным источником наблюдений. Доставка stdout серверов, журналы прокси, реальные задержки и сессия с физическим APK в этот проход не входили. Заполненность рабочего тома не измерялась. Код загрузки ограничивает один файл, а просроченные файлы чистит при следующей загрузке того же устройства. Это отдельный риск хранения, подтверждённый [серверной файловой пробой](evidence/logging-backend-probe.py).

```powershell
node node_modules/jest/bin/jest.js --runInBand --silent --roots ../docs/audits/2026-11-13/evidence --moduleDirectories node_modules '<rootDir>/node_modules' --testMatch '**/logging-web.test.cjs'
```
