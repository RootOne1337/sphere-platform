# Worker0.7.0: анализ GPS-линии миникарты

21 октября2026 по времени владельца (UTC+5). Код `74742fd0`, прежняя ветка PR19.
[Квитанция измерений](MOTOR-MINIMAP-ROUTE070.json).
Это реализация геометрической части N4 из [единого плана](../../design/MOTOR-AI-PLATFORM.md),
не допуск физического управления в обход открытых N1–N3.
По уточнению владельца общий контур должен работать также без GPS/миникарты:
раздел24 плана задаёт optional sensor, цели по изображению/ориентирам и отдельные критерии.
Эта реализация не определяет обязательный способ задания цели.

## Результат

Добавлены `MinimapProfile`, `extract_route`, `MinimapRouteShadow` и публичный CLI-режим
`--shadow-policy minimap`. Геометрия/цвет задаются отдельным JSON v1 размером до4096B.
В коде нет названия игры, package ID, сервера или фиксированного расположения HUD.
ROI ограничен256×256; граф содержит не более4096 цветных пикселей. Исходный размер
кадра должен точно совпасть с профилем, без молчаливого масштабирования.

OpenCV переводит исходный RGB в HSV и выделяет связные компоненты внутри круга миникарты,
исключая область стрелки/персонажа. Компонента должна подходить к этой области.
По связным пикселям строится путь до ограниченного lookahead по длине пути,
а не прямая хорда через угол. Несколько близких компонент, неоднозначный frontier,
чрезмерно плотная маска, короткий/отсутствующий путь дают явный отказ.
Алгоритм не дорисовывает разрывы морфологическим closing.

У первой реализации толстая линия возле player disk ошибочно выглядела как развилка.
Проверка локального anchor теперь отличает толщину от противоположных направлений;
проверка расходящихся продолжений остаётся отдельной на lookahead. Синтетические тесты
подтверждают и нормальную толщину, и отказ на вилке с ветвями разной длины.

`forward_degrees=null` в примере намеренно оставляет ориентацию неизвестной.
Контур пути доступен, но направление не выдаётся. Старые кадры показывают поворот самой
стрелки; принять постоянный экранный верх за направление персонажа нельзя.
Сенсор динамического heading и проверенная связь stick/camera/vehicle остаются следующим этапом.
Угол на lookahead — наблюдение, не готовая команда руля: исполнитель должен учитывать
кривизну, проходимый коридор и скорость. Следование пикселям линии не доказывает обход3D-коллизий.

## Изоляция от ввода и время

Shadow bridge возвращает только нейтральный placeholder для существующей inference boundary.
Он явно запрещён в `StickPolicySession`; `HeadlessSession` не позволяет открыть с ним
native admission. CLI отклоняет `--probe-control` и `--pointer-probe` в режиме minimap.
`goalRevision` — метка анализа, не текстовая инструкция NitroGen/P2P и не доказательство
получения игрового waypoint ID. Для новой цели/epoch нужен новый экземпляр.

Есть один реальный CPU job и64 последних записи диагностики. Отмена coroutine не считается
остановкой `to_thread`: работа shielded и ожидается до подтверждения retirement. Пока она
не завершилась, перекрывающийся запрос запрещён. Неизвестная очистка закрывает outer loop.
После ошибки вычисления cleanup не маскирует первичную ошибку. Stale frame и результат
старше250мс/deadline не получают актуальное направление.

Это bounded read-only анализ, не hard-real-time сертификат OpenCV/OS и не source-capture clock.
Scene/clearance/arrival не распознаются. Наличие линии на замершем игровом экране само по
себе не даёт права движения. При неточном HSV, компрессионном разрыве или неподходящем HUD
возможен отказ; он не заменяется случайным направлением.

## Проверки

184 motor tests и Ruff прошли. Добавлены31 тест: геометрия, HSV/RGB/hue wrap,
ориентация, fork/gap/no-route, размеры/JSON/NaN, stale epoch/frame/deadline,
реальная CPU cancellation, запрет физического режима и CLI без утечки токена/перезаписи evidence.
Отдельная integration-проверка передаёт нарисованную GPS-линию через настоящий H.264/DTLS/SCTP
локального fake APK, анализирует decoded RGB и подтверждает отсутствие всех `touch_*` сообщений.

### Сохранённые реальные кадры

Повторно прочитаны20 PNG из прежних PH011 опытов17октября. Профиль — кандидат для анализа,
не калиброванный game-control profile. На18 кадрах выделена связная GPS-линия;
результат `orientation_not_calibrated`, без направления. На двух кадрах цветной линии нет:
`route_not_anchored`. У кадра050s3D-метка25м ещё видна, поэтому отсутствие линии не является
прибытием. Выборочно просмотрены исходные положительные кадры и045/050/055s.
Это20 исторических snapshots, не новый игровой прогон и не оценка accuracy на размеченном dataset.
Хеши каждого файла и результаты сохранены в квитанции. Для18 положительных изображений
CPU extraction p50≈2.04мс, p95/max≈15.01мс; загрузка PNG исключена из этого замера.
Все24 PNG данного конечного waypoint-теста занимают13.85MiB локально. Это явная запись
private runner, не автоматический серверный архив; подробнее происхождение в разделе24.8 плана.

## Следующее

Калибровать динамическую ориентацию и stick/camera/vehicle mapping; связать полилинию с
локальной проходимостью/скоростью; отдельно стабилизировать ownership/ACK и сквозные сроки
действий на APK. Затем конечный supervised route test при активном игровом мире.
Полное A→B, obstacles/recovery, multi-touch, source/action clocks и проблемы PH030 открыты.
Веб/API/APK этим изменением не обновлялись: код Android и сервера не менялся.

Использованы [официальные OpenCV components/contours](https://docs.opencv.org/4.13.0/d3/dc0/group__imgproc__shape.html)
и [RGB/HSV conversions](https://docs.opencv.org/4.13.0/d8/d01/group__imgproc__color__conversions.html).
[Cradle navigation skill](https://github.com/BAAI-Agents/Cradle/blob/main/cradle/environment/rdr2/composite_skills/navigation.py)
проверен как пример разделения planner и minimap CV; его RDR2 controller в Sphere не переносился.
