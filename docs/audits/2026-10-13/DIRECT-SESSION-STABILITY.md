# Прямой видеопоток и причины повторного открытия управления

Позднейший срез: [прямой маршрут с ноутбука и восстановление запуска ввода](DIRECT-INPUT-RECOVERY.md). Старые наблюдения ниже сохраняют собственные версии и время.

Дата: 13 октября 2026. Текущие установленные версии и открытые границы:
[WORK-STATUS](../../operations/WORK-STATUS.md).
Факты установки, хеши и конечные наблюдения:
[неизменяемый протокол](DIRECT-SESSION-STABILITY-OBSERVATION.json).
Этот аудит не объявляет production-приёмку PH030, совместного ввода или WAN.

## Исправления

APK64 принимает свежий пропуск последовательности допуска управления:
сервер может заменить промежуточные authorization snapshots последним.
Старый либо повторный snapshot не продлевает TTL; истёкший владелец не
восстанавливается. Порядок настоящих касаний и сроки их доставки не ослаблены.

UI `73419abe` продолжает здоровый прямой поток, когда задержался отдельный
диагностический echo. Свежие реально показанные видеокадры учитываются
независимо от диагностического ответа. Пограничная проверка задержала один
echo на 12,5 секунды: сохранились тот же peer, ввод и RTP. Это не симуляция
срыва RTP или отключения сети.

Серверная правка `a4222327` устраняет другую гонку. Android отправляет RELEASE
браузеру прямо, а сервер получает его копию позже. Браузер уже мог запросить
новый допуск, пока сервер ещё хранил прежнего владельца. Раньше сервер
отклонял такой probe. Теперь сохраняется один ограниченный intent, связанный
с точным старым владельцем; новый probe отправляется лишь после его доказанного
освобождения. Никакие DOWN/MOVE/UP не ставятся в очередь и не повторяются.
Исправление типизации этого блока входит в `b65b0b54`.

APK65 сохраняет первую локальную причину завершения владельца отдельно от
успеха очистки. Различаются закрытие браузером, потеря heartbeat, просроченный
pending input, authorization expiry, смена capture/транспорта, потеря direct
channel, ошибка injector и неизвестная cleanup. Это фиксированный словарь
и ограниченный monotonic age; координаты, owner IDs, ключи и exception text
не сохраняются. Wire-формат native ACK не изменён. Старые APK остаются
совместимыми с необязательным расширением backend telemetry.

## Что проверено в браузере

Обычный установленный Chrome, PH010; без RTC flags, подмены транспорта
или серверного воспроизведения касаний.

| Проверка | Результат | Граница |
| --- | --- | --- |
| APK64, 3015, 60 секунд | 1742 новых decoded frames, DOWN/MOVE/UP 13/13 | Один локальный viewer |
| APK64, Tuna, 60 секунд | 1750 новых decoded frames, DOWN/MOVE/UP 15/15 | Публичный origin, прямой медиаканал |
| APK64, Tuna, 180 секунд idle + жест | 5222 новых decoded frames, один peer, ready; жест 13/13 | Трёхминутное наблюдение, не длительный soak |
| По шесть закрытий/новых открытий viewer | Все дошли до прямого ввода; локально 54/55 ACK, через Tuna 51/51 | Один MOVE coalesced; все DOWN/UP подтверждены. Сеть принудительно не рвалась |
| Отложенный диагностический echo | 877 новых decoded frames за 30 секунд, тот же peer и ready | Только один echo задержан на 12,5 секунды |
| APK65 после OTA, PH010, 60 секунд | 1737 новых decoded frames, жест 14/14 | До последующей установки нового API, если отдельная проверка не указана в протоколе |
| APK65 + установленный API b65b0b54, 3015, 60 секунд | 1747 новых decoded frames, жест 12/12 | Текущая связка после установки API |
| APK65 + установленный API b65b0b54, Tuna, 60 секунд | 1738 новых decoded frames, жест 14/14 | Текущая связка через публичный origin |

На этих интервалах счётчик серверных видеобайтов после переключения на direct
не рос, а native жесты не породили серверные `touch_event`. Нулевое/малое
значение ICE RTT не означает нулевую задержку картинки. `framesDecoded`,
`requestVideoFrameCallback` и native presented counters имеют разные значения
и не подменяются друг другом.

Скачивание полного APK65 кнопкой «Скачать последний APK» проверено на 3015
и Tuna. Полный SHA-256 совпал; измерено около 1,1 и 8,6 секунды соответственно.
Это конкретные замеры, а не гарантированная скорость последующих скачиваний.

Вход дополнительно проверен на обоих origin: 1440×1000 и 390×844, отдельный
неавторизованный браузерный контекст с системной светлой темой. Страница
остаётся тёмной, горизонтального overflow и page errors нет.

## PH030: стабильность ещё открыта

В настоящем ноутбучном сеансе RTP оставался direct, ICE/DTLS connected,
а счётчики нативного владельца многократно росли: более 200 открытий за
наблюдаемое окно. Серверная bounded read-only проверка за 120 секунд увидела
16 владельцев PH030 и одного PH010; сервер продолжал обновлять допуск.
Это доказывает churn, но не доказывает доставку каждого допуска в Android
или первоначальную причину его завершения. APK65 добавлен именно для этой
атрибуции. Текущий readback и результат последующих правок описаны в протоколе.

При проверке после установки API ноутбук уже был офлайн. Его последний viewer
закончился до завершения замены API; отсутствие новой причины в этом старом
сеансе не доказывает отказ APK65. На PH010 новое поле `last_release_reason`
дошло до сохранённой истории: `viewer_closed`, с отдельным monotonic age.
Пользовательское управление PH030 после этой установки остаётся непроверенным.

Перезапуск владельца ввода не следует автоматически считать разрывом RTP.
Автоматическое восстановление и отсутствие decoder errors также не доказывают
непрерывность управления пользователя.

На удалённой PH025 с APK65 за минуту показано 1585 серверных кадров по
сохранённой browser telemetry; readiness ввода держался без recovery.
ICE отправлял запросы, но не получил ни одного ответа; direct video не
установился. Указание `surface_hidden` в конце относится к закрытию нашего
viewer навигацией. В этом испытании касания не отправлялись — readiness и
счётчики heartbeat не принимаются за успешно выполненный жест.

## Сохраняющиеся ограничения

- Native pointer может идти по WebRTC; Home/Back/Recents/Menu и текст пока
  используют серверный HTTP/SHELL.
- Один нативный владелец: общий ввод нескольких вкладок и людей ещё не принят.
- Signaling и короткий authorization lease зависят от серверного WebSocket.
  Установленный канал ещё не является независимым от сервера capability v2.
- TURN не включён. Прямой маршрут во всех localhost/LAN/WAN сетях,
  физическая смена сети и удалённый VPS не приняты.
- 60 FPS, адаптивное качество, звук, клавиатура и полная glass-to-glass задержка
  остаются отдельными задачами.
- APK65 подтверждён установленным SHA и completed OTA на всех 14 устройствах,
  доступных при последней проверке. PH030 ранее завершил OTA65, но актуальный
  SHA не прочитан: сначала активный ввод, затем ноутбук офлайн. Ещё шесть
  исходно выключенных устройств не обновлены. Обычный Android channel сохранён.

## Локальные проверки и место на диске

Три локальных CI-профиля опубликовали точные результаты у commit SHA.
Packaging/security/Linux parity ещё не полностью перенесены;
[подробности CI](CI-COST-AND-LOCAL-RUNNER.md).

Работа с предупреждением NTFS продолжена по явному разрешению человека.
Ремонт, reboot и откат не выполнялись. Временные сборки получают свежие
каталоги; проверяются содержимое исходников и подпись APK.
Обслуживание удалило 50 проверенных архивов и 77 старых owned images,
сохранив данные и используемые контейнеры. Docker VHDX физически не сжимался.
Сборщик работает в ограниченном окне: это не ежедневный полный скан диска
и не доказанное устранение всех источников роста.
[Ресурсы и ограничения наблюдения](../../operations/HOST-RESOURCES.md).
