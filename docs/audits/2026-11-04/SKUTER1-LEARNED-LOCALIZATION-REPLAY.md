# Повторная локализация skuter1 с EigenPlaces, SuperPoint и LightGlue

## Данные и способ проверки

Банк построен автоматически из 173 ракурсов сохранённой карты skuter1 с
20 556 точками. Оба метода используют одни и те же измеренные 3D-ориентиры.
Карта связана с заданием `6a77040681d142ec97d51831a22785fb` и навигационным
артефактом `024fd153939b071ca65f825b86c16e28`. SHA-256 геометрии
`75e491be5dff83a4566414c903cc1c666dfb96b88ca0c713e7565de102bff1aa`.

Запросы охватывают дневной skuter2 (0–39,800 с), ночной zaezd888
(0–35,409 с) и постороннюю запись (0–49,007 с). Из каждого источника
выбрано примерно пять кадров в секунду по исходным RTP-меткам. Все три
прогона сопоставлены по записи, номеру кадра и SHA-256 каждого из 624 JPEG.
Дневной и ночной заезды различаются также ракурсом, траекторией и скоростью.
Для независимых заездов точная поза и доля перекрытия с картой неизвестны.

EigenPlaces ResNet18/512 ищет три вида по изображению 448 × 252.
На вход поиска подаётся серое изображение с одной и той же маской HUD
для запросов и опор. SuperPoint извлекает до 1024 признаков запроса
при 640 × 360. В опорных видах дескриптор берётся в координате измеренного
3D-наблюдения, с учётом смещения центра пикселя при масштабировании.
LightGlue сопоставляет признаки, затем штатный PnP Sphere проверяет
соответствия. Дополнительный вариант объединяет виды по общим измеренным
точкам и отбрасывает конфликтующие 2D–3D связи перед тем же PnP.

## Результаты

| Метод | День | Ночь | Посторонняя запись | p95 день / ночь |
|---|---:|---:|---:|---:|
| RootSIFT и оптический поток, CPU | 32 / 200 | 32 / 178 | 0 / 246 | 248 / 224 мс |
| EigenPlaces, SuperPoint и LightGlue, GPU | 47 / 200 | 29 / 178 | 0 / 246 | 196 / 190 мс |
| Та же связка и объединение видов, GPU | 47 / 200 | 31 / 178 | 0 / 246 | 217 / 216 мс |

В таблице считается единственная выбранная геометрически согласованная
гипотеза на кадр. Время измерено внутри стенда на CPU с одним потоком
или на AMD GPU. Оно исключает задержку потока, очереди и управления.
Сравнение по кадрам не учитывает временное подтверждение, ошибку позы
и непрерывность движения.

Одиночный вариант вернул 21 дневную гипотезу там, где базовый метод
отказал, и потерял шесть его гипотез. Ночью он вернул 25 и потерял 28.
В окнах skuter2 19–21,4 с и 27–29,4 с результат изменился с 0/12 до
3/12 в каждом. На возвращении 37,516–39,916 с оба дали 0/12. Визуальный
просмотр показывает подходящие виды ворот, фасада и переулка. Из 153
дневных отказов нового метода в 139 хотя бы один кандидат дошёл до PnP
с 24 или более связями, но поза отклонена. Подходящий вид и число
сопоставлений сами по себе не подтверждают пространственное решение.

Разрешение 960 × 540 проверялось отдельно. На 1 ГиБ лимита HIP
остановился на выделении рабочего буфера, а на 2 ГиБ опыт остановил
защитный порог Windows commit во время построения банка. Для этого
разрешения результатов качества нет.
Повторный короткий запуск финального скрипта также остановился по
`commit_headroom_low` при построении банка. Приведённые числа относятся
к трём ранее завершившимся прогонам. Финальная версия прошла Ruff и
49 тестов локализации и объединения опор.

Эксперимент пригоден для повторного офлайн-сравнения. Дневной выигрыш
и взаимодополняемость методов оправдывают дальнейшую проверку запасного
поиска позы. Данные по возвращению и ночному заезду пока не дают
допуска к живому управлению.

## Повторение

Подготовка запросов запускается модулем
`scripts.pilot.prepare_learned_replay_queries` в окружении motor worker.
Передаются три аргумента `--capture LABEL PATH` для каталогов `input`
нужных заданий, `--hz 5` и новый каталог `--output`.

`scripts.pilot.check_learned_route_replay` принимает `--navigation`,
`--assets`, `--queries` (путь к manifest.json) и новый каталог `--output`.
Для измеренного профиля использованы `--device cuda --top-k 3 --stride 1`,
для второго прогона добавлен `--merge-covisible`. На Windows запускали
в `.local-pilot/motor-amd-venv` с `PYTHONPATH`, указывающим на
`.local-pilot/motor-worker-venv/Lib/site-packages`. Код и веса проверяются
перед загрузкой и берутся с диска.

Подготовка моделей для воспроизведения:

- LightGlue в `.local-pilot/reconstruction-tools/lightglue`, checkout
  `eb42fee2d71449efb0aa5c10549752b5d75384d8`. Файлы `superpoint_v1.pth`
  и `superpoint_lightglue.pth` из релиза `v0.1_arxiv` помещаются в
  каталог `--assets`. [Релиз LightGlue](https://github.com/cvg/LightGlue/releases/tag/v0.1_arxiv)
- EigenPlaces в `--assets/global/EigenPlaces`, checkout
  `a2969f71d5ea31017443af490b15273ca4c50af1`, файл
  `ResNet18_512_eigenplaces.pth` в `--assets/global`.
  [Репозиторий EigenPlaces](https://github.com/gmberton/EigenPlaces)

Локальные исходные результаты находятся в `.local-pilot`. Базовый
прогон и его скрипт лежат в `skuter1-hloc-baseline-20261104-v1`, запросы
в `skuter1-hloc-queries-20261104-v1`, отдельные прогоны в
`skuter1-hloc-replay-20261104-v2` и `skuter1-hloc-replay-20261104-v3`.
Каждый содержит построчные результаты. Маркер `COMPLETE` отличает
завершённый прогон от прерванного.

## Проверка пуска транспорта 5 ноября

На той же активной карте `024fd153939b071ca65f825b86c16e28` подали
сохранённые JPEG по времени записи в штатное подтверждение позы,
чтение спидометра и `VehicleRouteFollower` в режиме `beginning`.
Загрузили профиль скорости исходного skuter1. Вариант с восстановлением
RootSIFT повторяет поиск режима наблюдения, подключённый к тому же
планировщику только в стенде. EigenPlaces и LightGlue в этом прогоне
не участвовали. Каждое окно и метод начинались с пустого состояния.

| Видеовход | Кадров на метод | Штатная поза / первый газ | RootSIFT в стенде, поза / первый газ |
|---|---:|---|---|
| skuter1, начало 0–9 с | 45 | 39 localized / 0,441 с | 39 localized / 0,441 с |
| skuter2, начало 0–8 с | 40 | 0 localized / нет | 19 localized / 0,419 с |
| zaezd888, начало 0–8 с | 40 | 0 localized / нет | 0 localized / нет |
| skuter1, финиш 32–36,95 с | 25 | 23 localized / нет | 23 localized / нет |
| Посторонняя запись 0–5 с | 25 | 0 localized / нет | 0 localized / нет |

«Первый газ» означает первый план `throttle` с возрастом не более 250 мс
от времени подачи кадра на стенде. На исходном видео первый такой ответ
занял 38 мс. На дневном независимом старте RootSIFT потребовалось 168 мс.
Оба плана рассчитаны при показании HUD 0 км/ч. На финише при верных
позах старт остановлен причиной `vehicle_start_outside_recorded_beginning`.
Ночью только две промежуточные позы прошли геометрию и остались в
`confirming`. При второй позе, спустя более трёх секунд после первой,
планировщик зафиксировал разрыв центра. Подтверждённой серии не было.

Этот тест не измеряет нажатия и траекторию под управлением Sphere.
Скорость и последующие кадры приходят из готовой записи, подтверждения
Android отсутствуют. Локальная квитанция
`.local-pilot/skuter1-scooter-start-replay-20261105-v1/report.json`.
Модуль для повторения — `scripts.pilot.check_vehicle_start_replay`.
Аргумент `--window NAME MANIFEST CAPTURE FROM TO` задаёт каждое окно,
`--compare-descriptor-recovery` включает второй прогон. Использованы
манифесты из `skuter1-start-replay-queries-20261105-v1` и
`skuter1-hloc-queries-20261104-v1`.

## Потеря позиции после старта и повторный захват

Исправлен отказ до начала движения. Предварительная поза вне начала
сбрасывает голоса и оставляет планировщик в ожидании. Истёкшая поза
также больше не сравнивается с новой как действительная. Для газа
по-прежнему нужны три согласованных свежих наблюдения со спидометром
и текущая поза `localized`. Если уже получена подтверждённая поза
за пределами старта или после начала движения прогресс резко изменился,
защитный останов сохраняется.

Повтор ночного старта на тех же 40 кадрах изменил 12 терминальных
ответов `vehicle_pose_discontinuity` на ожидание. Подтверждённых поз и
газа по-прежнему ноль. Синтетический тест отдельно проверил паузу
2,426 с. При возвращении близкой позы газ возможен после трёх новых
наблюдений. При скачке вдоль маршрута контроллер завершает попытку.

| Прогон после исправления | Локализовано | Что произошло с планом |
|---|---:|---|
| skuter1 целиком, штатный и RootSIFT | 170/185 в обоих | Первый газ 0,441 с. Потеря позы с 8,407 с, завершение на 9,406 с с `vehicle_progress_discontinuity` |
| skuter2 целиком, штатный | 0/200 | Все 200 ответов в ожидании |
| skuter2 целиком, запасной поиск RootSIFT | 26/200 | Первый газ 0,419 с. Завершение на 18,401 с с `vehicle_progress_discontinuity` |
| zaezd888, первые 8 с, оба метода | 0/40 в обоих | План остался в ожидании |

В replay видео продолжает движение само, в том числе после того, как
планировщик отпускает газ. Например, на 9,406 с спидометр исходного видео
показывал 53 км/ч. Скачок характеризует расхождение плана и записи, но
не измеряет перемещение при реальном отпускании газа.

Отдельно проверен оптический поток с начальным приближением из
перепроекции последней подтверждённой позы. Предыдущая поза только
подсказывает координаты поиска. Два соседних ракурса должны независимо
получить согласованную текущую PnP-позу по непересекающимся ID точек,
после чего остаются обычные проверки свежести и движения. В первом
прогоне на 70 исходных кадрах локализовано 55 обоими методами.
В коротких повторах на проблемном интервале 6–12 с оба метода дали
16/30. Ни одна дополнительная поза не принята. Другой вариант
проверки неоднозначных гипотез остановлен при входе по
`commit_headroom_low`; измерения для него отсутствуют.

Воспроизведение с оптическим потоком использует
`check_vehicle_start_replay --compare-projected-recovery`, полный
прогон использует `--compare-descriptor-recovery`. Первичные журналы
`.local-pilot/skuter1-projected-recovery-20261105-v1`,
`skuter1-projected-recovery-20261105-v2`,
`skuter1-projected-recovery-20261105-v3` и
`skuter1-full-vehicle-recovery-20261105-v1`. Сопоставлены индексы и
временные метки кадров, пропущенных кадров нет. Команды Android и
живой проезд в этих прогонах отсутствуют.

### Защита от предварительного скачка после потери позиции

Поза `confirming` за пределами допустимого продвижения или смещения
сбрасывает голоса и переводит транспорт в ожидание с отпущенным газом.
Центр и максимум прогресса обновляются только после принятия текущей
позы `localized`. Для возобновления по-прежнему нужны три согласованных
наблюдения, действующий спидометр и свежая локализация. Повторные
скачки не продлевают 15-секундное ожидание. Для скачка подтверждённой
позы действует прежний останов.

| Запись и метод | Результат |
|---|---|
| `skuter1`, штатный Reference LK, 70 кадров до 14 с | На 8,407 с потеряна поза. На 9,406 с предварительный скачок на 2,875 усл. ед. при допуске 2,741 оставил сессию в ожидании. На 10,819 с подтверждённый скачок на 8,947 усл. ед. завершил её. |
| `skuter2`, день, штатный Reference LK, 120 кадров до 24 с | 0 подтверждённых поз, команды газа не сформированы. |
| `skuter2`, день, диагностический RootSIFT, те же 120 кадров | 19 подтверждённых поз. Первая команда газа на 0,419 с. После потери на 8,039 с новых команд газа нет. Предварительный скачок на 18,401 с отклонён. На 23,232 с сработал тайм-аут восстановления. |

Отдельная проверка шести кадров `skuter1` на 8,407–9,406 с показала
ошибку выбора ракурса в исходной записи. На 8,407 с три первых
ракурса по сходству миниатюры дали от 266 до 398 геометрических
совпадений. Центры отклонялись от интерполированного положения камеры
исходной реконструкции на 0,880–4,408 усл. ед. В пределах локального
окна от последней принятой позиции на каждом из шести кадров нашлись
как минимум два ракурса с отклонением 0,003–0,037 усл. ед. Ни один из
них не вошёл в первые три кандидата поиска по миниатюре. Локальное
окно задавалось опорой на 8,208 с. Метка времени проверяемого кадра
использовалась для оценки ошибки, и для отдельного диагностического
набора ракурсов. Это сравнение с моделью той же записи. Перенос на
отдельный дневной заезд и выигрыш по скорости поиска не измерены.

Первичные журналы находятся в `.local-pilot/`.

- `skuter1-own-reacquire-guard-20261105-v2/report.json` — штатный метод, исходное видео.
- `skuter1-day-reacquire-guard-20261105-v1/report.json` — два метода, отдельный дневной заезд.
- `skuter1-gap-reference-evidence-20261105-v1/report.json` — сравнение кандидатов, SHA-256 кадров и ошибки центров.
- `skuter1-reacquire-guard-20261105-v1/report.json` — частичная квитанция. Между методами сработал `commit_headroom_low`.

В браузерном тесте проверена последовательность `following → lost →
confirming → following`. В фазах ожидания выход нейтрален, а после
подтверждения используется тот же сеанс ввода. Живые действия Android
и полный проезд по маршруту этими проверками не подтверждены.
