# Фоновая перепроверка карты: результат эксперимента

30.10.2026. В рабочем API **не включена**. Переключателя в пользовательском
вебе нет. Код `BackgroundVerifiedRouteLocalizer` вызывается только явно из
диагностического скрипта/тестов; схема сохранённых карт не менялась.

## Гипотеза

Убрать периодические блокировки полного RootSIFT-поиска из быстрого цикла,
оставив LK/PnP текущего RGB в основном потоке. Отдельный verifier имеет
собственный индекс и mutable state. В очереди максимум один запрос.

Обязательные ограничения экспериментального класса:

- Запрос запускается после 0,5 с от предыдущего descriptor-кадра. Прежний
  deadline 0,8 с не продлевается ожиданием фонового потока.
- Глобальная поза должна проецировать foreground 3D-ID в **тот же query RGB**:
  не менее 24 точек, не менее 75% положительных глубин, median error ≤3 px,
  не менее 75% ошибок ≤6 px.
- Результат и его потребление должны уложиться в 250 мс от query. При успехе
  старый query служит лишь началом LK к новому кадру; актуальная поза снова
  решается по новому RGB. Timestamp остаётся временем query.
- Неуспех, противоречие, потеря изображения или deadline очищают tracking.
  Поздний результат не восстанавливает прежнее разрешение на движение.
- `close` сразу закрывает публикацию, отменяет ожидающую работу и shutdown
  executor. В работе может оставаться максимум один ограниченный native вызов;
  Python не может принудительно прервать уже исполняющийся OpenCV.

## Результат

Сравнение на двух участках настоящей записи, четыре OpenCV-потока, независимые
от опорных source indices. Измерение включает JPEG decode, локализатор и planner,
не включает HTTP, браузер, Android и обратную реакцию игры.

В первых парных прогонах (обычный shortlist 3):

| Участок | Режим | Localized | p95 обработки | CPU core-seconds |
|---|---|---:|---:|---:|
| 4–11,6 с | Последовательно | 62 / 64 | 127,16 мс | 3,19 |
| 4–11,6 с | Фоновая проверка | 56 / 64 | 144,30 мс | 5,22 |
| 19–26 с | Последовательно | 47 / 64 | 116,28 мс | 5,33 |
| 19–26 с | Фоновая проверка | 44 / 64 | 116,40 мс | 6,08 |

Эти строки не показали выигрыша по одновременно требуемым критериям. У
сопровождения появились более длинные задержки из-за конкуренции native CPU;
более частая descriptor-проверка также повысила стоимость. Успешные общие
позы близки: p95 различия угла около 0,003–0,0054 рад. Это согласие двух
локализаторов на одной карте, не независимая точность геометрии.

После этого отдельно исправлена частота проб: минимум 50 мс между началами
наблюдений, как у веба. Без этого офлайн-проигрыватель после долгого поиска мог
подать два кадра на одном дискретном `monotonic` tick Windows и закономерно
получить `route_binding_retired`. На приведённых четырёх строках такого отказа
не было; строка отдельного раннего эксперимента «shortlist 8 всегда» имела этот
артефакт и не служит доказательством потери маршрута в игре.

Итоговый парный прогон после исправления частоты и добавления адаптивного
shortlist сохранён в `backgroundFinal` файла
[walk-realtime-evidence.json](walk-realtime-evidence.json).
Нагрузочные результаты могут колебаться вместе с остальными приложениями.

**Решение:** оставить последовательную проверку в рабочем API; сохранить
воспроизводимый ограниченный эксперимент для последующего улучшения. Полезное
изменение из этих проверок — расширенный retrieval только до подтверждения
позиции — включено отдельно и не требует фонового потока.

## Воспроизведение

Из корня проекта, с установленным CPU-venv и существующим заданием:

```powershell
.local-pilot/motor-worker-venv/Scripts/python.exe -m scripts.pilot.check_route_tracking_latency --job .local-pilot/reconstruction-jobs/b861ac82fcd64425bc583b37f620ba2a --output .local-pilot/new-paired-result.json --start 4 --count 64 --native-threads 4 --recovery-candidate-limit 8
```

Для сравнения обычного/адаптивного acquisition использовать разные новые
output paths и `--kinds synchronous`, во втором запуске добавив
`--recovery-candidate-limit 8`. Уже существующие результаты не перезаписываются.
Скрипт сохраняет SHA исходных assets, последние кадры вместо очереди, source
indices, время, inliers, состояния и позы; не отправляет native input.

Тесты проверяют single pending query, deadline, свежий RGB после reanchor,
противоречащую геометрию, exception, late result, отзыв подтверждения и close.
Они проверяют контракты, а не прохождение игры.
