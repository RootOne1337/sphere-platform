# VPN v2: сборки готовы, установка Android ещё не выполнена

Checkpoint 22 октября 2026 года. [Машинная запись](VPN-SCOPE-V2-DELIVERY-CHECKPOINT.json).

Все четыре hosted-прогона завершились успешно: полный Android CI,
настроенный APK86, backend и frontend. APK86 скачан, распечатан только локально
и переподписан прежним сертификатом; содержимое 936 записей APK сохранено.
Одноразовый секрет конфигурации сборки удалён из GitHub. Приватный ключ VPN,
API key провайдера и локальный ключ подписи в этот workflow не передавались.
Настройки development bootstrap и публичный ключ получателя передавались:
поле `privateConfigurationUploaded:false` в исходном шаблонном dispatch receipt
не описывает эту передачу и не должно использоваться как доказательство её отсутствия.

Веб установлен из CI на `a239baa26c5d945a4e3b09f4596b94d4db0cada2`.
В существующем браузере проверены каталог, работающая авторизованная связь
событий, выбор «Все приложения, кроме Sphere», подпись IPv6 и закреплённые
кнопки модального окна. Тестовая форма закрыта без сохранения. Проверка исходного
preview на 390 px описана в предыдущем checkpoint; текущая установленная
страница проверена при ширине 638 px. Это конечная проверка перечисленных
элементов UI, а не приёмка Android VPN.

Backend остаётся `cd2431e2ae0c719959147626981b00ac8f9703f5`; PH030, PH025,
PH011 и PH010 сообщают APK85. Образ нового backend уже прошёл admission и
загружен в Docker, но работающий контейнер не заменён. Повторная проверка
перед заменой обнаружила недостаточный резерв памяти: при записи checkpoint
свободно 3,61 GiB RAM, Windows commit 86,85%, штатные границы — минимум 4 GiB
и commit строго ниже 85%. Порог не ослаблен, процессы пользователя и хост
не перезапускались.

PH030 оставлена с прежним paused guard для `com.br.top`. Новый клиент WG1
ещё не применён на Android, браузерный egress PH030 не подтверждён. В каталоге
есть ровно один созданный для этого теста WG1-профиль v1; новую ревизию v2
пока не сохраняли. На удалённом сервисе создан один peer; остальные серверы
и их привязки не меняли.

Следующая физическая последовательность: обновить только backend после
прохождения свежей проверки ресурсов; установить APK86 адресной OTA только
на PH030 с сохранением старой блокировки; проверить восстановленный guard;
на время перехода запретить запуск игры, снять точно прежний guard и создать
новый plan 5; восстановить прежнее состояние доступности игры. Затем проверить
IP обычного Android-браузера, HTTPS/DNS, паузу с блокировкой приложений и
сохранение прямого Sphere control/media. Никаких очисток данных игры или
дополнительных peers для этого не требуется.

Границы остаются открыты: системный DNS и делегированные сетевые службы,
перезагрузка, дополнительные Android users/profiles, длительная работа,
production executor/leases. Сохранение профиля не включает VPN. Полная
отказоустойчивость и готовность всего парка не заявляются.
