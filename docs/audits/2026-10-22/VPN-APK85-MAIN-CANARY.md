# Основной APK85: данные, пауза и аварийная изоляция

22 октября 2026. PH011, Android 9, APK `10285`, API `cd2431e2`. Выбран только
временный диагностический package с UID 10108; UID Sphere 10082 исключён.
Игра и host VPN не менялись. Все операции VPN доставлены через Sphere, код
диагностики подготовлен локальным ADB. Это конечный maintainer pilot, не общий
серверный журнал операций с CAS/leases.

APK85 читает прежний `RELEASED` journal plan 3; новый туннель создаёт plan 4.
Новый guard использует UID route/table, blackhole и FILTER, не устанавливая
MANGLE/packet mark. Основание исправления — [воспроизведённый дефект APK84](VPN-APK84-MAIN-CANARY.md).

| Опыт | Подтверждено | Что не подтверждено |
| --- | --- | --- |
| Внешний WG1 профиль | Handshake, первые TCP после apply/resume, Sphere вне туннеля | Повторные TCP и DNS нестабильны; причина не установлена |
| Новый локальный AWG1 peer | 12 HTTP-ответов с ожидаемым body подряд | Интернет/DNS и AWG3.1 obfuscation этим peer не проверялись |
| Pause/resume локального peer | Выбранный UID заблокирован на паузе; 5 HTTP-ответов после resume | Длительная нагрузка и смена внешней сети |
| Аварийное завершение `:vpn` | TUN закрыт, blackhole сохранён, выбранный UID заблокирован; Sphere работает | Восстановление новым автоматическим apply не выполнялось |
| Согласование после аварии | Новый PID сообщает `RECONCILIATION_REQUIRED` с причиной | Этот readback правильно имеет failed RPC и не считается healthy VPN |
| Явный disconnect | Guard `RELEASED`, обе таблицы пусты, UID rules/filter jumps сняты | Общий production executor не объявляется готовым |

При внешнем WG после apply/resume два первых TCP подключения проходили, следующие
TCP/DNS запросы истекали по timeout. Успешный локальный опыт с отдельными временными
ключами сужает поиск, но не доказывает, что виноват именно внешний сервер: остаются
внешний маршрут, peer configuration и взаимодействие с Android. Нельзя считать
один handshake или один успешный TCP доказательством стабильной передачи данных.

В локальном опыте использован настоящий native AWG в основном APK и отдельный
аутентифицированный userspace peer на loopback. Обмен проверялся чтением ожидаемого
HTTP body, а не только connect(). Native implementation `v3.1.20260814` здесь
исполняла AWG protocol 1; это не испытание параметров протокола 3.1.

Ранние ошибки диагностической оснастки сохранены: чтение stdin peer, права staging
и неверная временная пара public keys. Последняя потребовала отдельного disconnect
и архивации профиля перед исправленным опытом. Эти попытки не представлены как
успешные проверки APK. Пользовательские VPN-ключи в оснастке локального peer не
использовались; временный server key лежал только в каталоге 0700 и удалён после
остановки своего процесса, client profile доставлялся зашифрованно.

После обоих опытов профили архивированы, kernel cleanup подтверждён. Собственный
traffic-only APK и восемь диагностических файлов удалены; основной процесс Sphere
сохранил PID. Полные безопасные результаты, command IDs, счётчики и границы:
[квитанция](VPN-APK85-MAIN-CANARY.json).

APK85 [установлен на четырёх online pilot-устройствах](VPN-APK85-CLOUD-AND-ADDRESSED-DELIVERY.md).
Приёмка этого опыта ограничена локальными HTTP/pause/fault/release. Общая готовность
VPN и игры не заявлена; DNS, внешний egress, IPv6, мобильность, длинная нагрузка,
production journal/leases и ещё 17 offline устройств остаются открытыми.
