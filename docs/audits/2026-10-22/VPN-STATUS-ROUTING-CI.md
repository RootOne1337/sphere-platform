# Доставка состояния VPN: исправление маршрута WebSocket

22 октября 2026. Эта квитанция подтверждает исходники, проверки и допуск образа.
Она не является квитанцией установки или физического VPN.

При проверке APK84 на PH011 `VPN_APP_STATUS` завершался с ответом `IDLE`, но
авторизованный `GET /api/v1/vpn/runtime` не получал наблюдение. Обработчик
`handle_agent_message` уже валидировал `app_vpn_status` и записывал отчёт с
проверкой владельца WebSocket. Основной цикл `android_agent_ws` использовал
отдельный `match` и этот тип сообщения не передавал обработчику.
[Живой baseline и независимый PID](VPN-APK84-IDLE-BASELINE.json).

Добавлена явная ветка в настоящий receive loop. Политики валидации, размер
сообщения, идентификатор устройства/соединения и атомарная запись Redis сохранены.
Схема БД, зависимости и физические команды VPN не изменены.

Новые проверки вызывают полный endpoint с контролируемым сокетом: корректный
отчёт, запрещённое дополнительное поле и отказ Redis с последующим heartbeat.
До исправления два сценария падали, после — прошли. Дополнительно прошли 988
WebSocket/runtime tests, 44 subtests и 48 device-status tests.

[Полный CI](https://github.com/RootOne1337/sphere-platform/actions/runs/39681623774):
4428 passed, 107 skipped, 668 subtests, покрытие 82,57%, все шесть jobs успешны.
Первый прогон сохранён как failure: два Docker gateway tests не смогли получить
nginx из ECR из-за `Data limit exceeded`. В CI указан официальный Docker Hub с
тем же digest. Байты manifest дополнительно проверены через API реестра.
Тесты и требование успешного CI не ослаблялись.

Точные SHA, artifact identity и границы:
[машинная квитанция](VPN-STATUS-ROUTING-CI.json).

## Контроль установки

После загрузки образа повторный admission не пропустил замену API: Windows commit
выше штатного порога 85%. Наблюдение из 17 замеров за восемь минут не подтвердило
допуск. Intent замены не создавался, ID/image старого backend сохранены, readiness
API/БД/Redis проверена. Работают прежние UI `46dd02ff` / API `4a6ada92`.
PH011 online сообщает APK84, PH030 offline. Физические VPN/игровые команды не
отправлялись. [Квитанция остановки](VPN-STATUS-ROUTING-INSTALL-CHECKPOINT.json).

Для продолжения требуется обычный допуск хоста, повторная сверка baseline и
штатный `scripts.pilot.install_reviewed_backend` с этим CI-артефактом. Тот же
проверенный образ уже загружен: повторный импорт не требуется. После установки
нужны новый read-only RPC, сверка его snapshot/session с авторизованным runtime
API и визуальная проверка. Применение туннеля остаётся отдельной приёмкой.
