# PH030: предоставленный WG-профиль, путь пакетов и сохранённая блокировка

22 октября 2026. На PH030 применён предоставленный владельцем WireGuard-профиль
через встроенный VPN основного APK85. Выбран только `com.br.top`, UID 10061;
Sphere UID 10060 остаётся вне туннеля. Общий VPN всех приложений этим тестом
не включался. Владелец подтвердил, что этот конфиг не работает в другом клиенте.

Android consent проверен по свежему PNG и XPath, принят для Sphere. Профиль
хранится в зашифрованном каталоге и доставлен связанным с операцией RSA/AES
envelope; ключи не помещались в shell-команды, журналы или публичные файлы.

## Что подтвердилось

| Проверка | Наблюдение |
| --- | --- |
| Подключение | Native handshake подтверждён |
| Выбор маршрута игры | UID направлен на TUN, исходный адрес соответствует профилю |
| TCP к известному IP | SYN/SYN-ACK и connect проходят |
| TLS | Curl прочитал server hello, certificate, key exchange и server finished |
| Следующая отправка | Client finished попадает в TUN и повторяется без ответа |
| Внешний интерфейс Android | Соответствующие шифрованные UDP отправки видны на `wlan0` |
| HTTPS по IP / с DNS, простой HTTP от UID игры | Timeout; рабочий интернет игры не подтверждён |
| HTTPS от UID Sphere | Ответ получен; management WebSocket тот же |
| A/B приоритета UID-правила | После native VPN rule результат не улучшился; оригинал точно восстановлен |
| Reverse-path filter | `0` у all/default/TUN; эта гипотеза не подтверждается |

Захват ограничен заголовками тестовых IP/TCP/UDP пакетов; содержимое игрового
трафика не записывалось. В [квитанции](PH030-WG85-PATH-INVESTIGATION.json)
оставлены только тип, направление, размер, ifindex и TCP flags, без адресов peer,
полезной нагрузки и ключей. Kernel transmit на `wlan0` не доказывает получение
пакета удалённой стороной. Нельзя объявить подтверждённой ни блокировку провайдера,
ни отказ сервера, ни корректность шифрования каждого потерянного пакета.

Первый запуск `su UID curl` не имел INTERNET supplementary group; его ошибки не
используются как доказательство сбоя VPN. Последующие тесты использовали отдельный
проверенный launcher с UID приложения и group 3003. Диагностические файлы и их
временная раздача удалены, конфигурация gateway восстановлена. Игра не запускалась,
её данные, другие приложения и host VPN не менялись.

## Что оставлено на PH030

**`PAUSED_GUARD_HELD`: туннель закрыт, Black Russia заблокирована.** Проверены
blackhole UID routes и FILTER DROP для IPv4/IPv6. Профиль не архивирован, guard
не снят. Возобновление требует ту же session; явный `disconnect` в APK85 снимает
блокировку и возвращает родной интернет. Это оставленное состояние, а не cleanup
или успешный игровой VPN. Старые квитанции с очищенными временными VPN описывают
предыдущие опыты и не заменяют этот checkpoint.

Для независимого теста подготовлен userspace netstack client на рабочей станции,
без изменения host routes. Его компиляция/запуск не выполнялись: действующий
Windows resource guard остановил сборку по commit headroom. Порог не менялся,
пользовательские процессы не завершались. Этот отрицательный этап не считается
независимой проверкой сервера.

В исходниках веба уточнена область действия VPN и убрана неоднозначная подпись
«Требуется обновление» для устаревшего native sample. Все 11 VPN suites / 85 tests
прошли. **Эта правка ещё не установлена**; текущий UI остаётся `46dd02ff`,
API `cd2431e2`, APK `10285`.

## Следующие развилки

1. Выполнить независимый userspace тест после штатного ресурсного допуска либо
   в отдельном изолированном runner; PH030 при этом остаётся на паузе, чтобы не
   создавать два клиента с одним ключом. Сопоставить с серверным захватом/логами,
   если появится доступ. Не считать один TCP или handshake исправлением.
2. Если внешний WG-путь подтверждён как проблемный, проверить настоящий профиль
   совместимого AWG-сервера. Дописывание параметров AWG в WG-конфиг без серверной
   поддержки не объявляется обновлением протокола.
3. Режим [всех приложений кроме Sphere](../../design/VPN-ALL-EXCEPT-SPHERE.md)
   требует диапазонов UID, новых установок, DNS/IPv6 и отдельной reboot-проверки;
   перечисление двух текущих package IDs не заменяет этот режим.

Общая готовность внешнего VPN, игрового входа и production не принята.
