# One automatic pose-gap refinement iteration

This is an offline single-iteration research result, not a validated route or an automatic publication. `scripts.pilot.route_overlap_sampling.plan_pose_gaps` was given all 901 real source-frame records, the 166 selected source indices and exact tick/name bindings from the prior targeted model, and that model's camera-motion audit. With at most 24 new frames, 240 total views and three per flagged interval, it automatically selected [690,691,692] inside 689→694 and [695,697,699] inside 694→700. The planner responds to speed-outlier flags only; it does not resolve or independently validate reversal flags, camera errors or turns. The two flagged intervals were selected across the whole source by this heuristic, not manually specified for this run.

All source access units were verified during complete decoding. The new frames are original 1920x1080 pixels with source index/timestamp/access-unit SHA binding; the three old endpoints 689,694,700 were also pixel-equal to prior prepared PNGs. SIFT/RootSIFT (cap 4096) was extracted only for six new frames, with the existing precise HUD mask. Neighbor float32 caches were read from the earlier exact stage1 and targeted-frame caches and checked against their stored SHA. The copied previous database retained all 823 old raw pair records and all 823 previous verified pair match blobs; post-map comparison confirms both are unchanged. Forty-nine raw pairs were added, each incident to a newly selected frame and using the existing lag set 1,2,3,5,8; 872 raw pairs, 856 nonempty verified results. View-graph calibration can change geometry matrices/configurations; byte equality claim covers pair IDs, counts and match blobs. No old source database, cache or PNG was modified.

One global model registered 172/172 cameras with 17,397 points, shared focal refined to 604.2144 px, mean reprojection 1.185 px, endpoints 0–35.493 s and maximum view gap .266 s. The near-camera-point heuristic passed (0). Global positioning nevertheless stopped at 101 iterations with Ceres `NO_CONVERGENCE`. The route audit failed; the complete-model counts are 24 heuristic reversals and 6 speed outliers. More cameras, low reprojection or a passed near-camera heuristic cannot establish a correct road or trajectory.

To avoid comparing different sampling densities, the prior and new model were audited on the same original 163 camera timestamps: rapid reversal flags changed 25→24 and speed-outlier flags 2→6. The two initial speed flags at 27.468 and 27.668 s disappear, and six new flags appear at 30.517–31.631 s. These are model-relative heuristics, not a count of actual physical turns or independently confirmed error. On the original common-view sequence, endpoint step / within-model median step decreased 18.67→0.994 for 689→694 and 14.81→0.888 for 694→700. Units have arbitrary scale; this local normalization cannot prove actual vehicle motion or establish a correct new global solution.

On the same 125 original HUD edge endpoints, with scale fit on the first 65 and evaluation on the last 60 only: ratio p90/p10 worsened 7.25→14.96, median absolute log ratio .603→.761, and factor-four deviations 5/60→13/60. This held-out applies only to the fitted scalar; both model construction and HUD values use the same recording. HUD speed is not verified metric ground truth, and camera/body coupling is unknown. Together with the relocated outliers and no-convergence status, this does not justify accepting the new model or performing more iterations automatically.

A single process-isolated iteration completed in 121.84 s wall (prepare 8.03, GPU matching 11.03, verify/global 102.67), below the 240 s total and 120 s mapping bounds. CPU mapping ran with two-logical-CPU affinity and the mapper configured for two threads; pycolmap's verifier may create more OS worker threads even though CPU concurrency was affinity-limited. GPU allocator cap 3 GiB, peak allocated 517,404,160 bytes and reserved 1,524,629,504 bytes. Minimum sampled available RAM 7.21 GiB and commit headroom 17.24 GiB, above 4.5 GiB. Source video, journals, original prior DB, metadata, previous three new cache files and precise mask SHA-256 matched before/after. `plan.json`, `prepare-receipt.json`, `match-receipt.json`, `verification.json`, `report.json`, `common163-audit.json`, `comparison.json`, `graph-preservation.json`, and `receipt.json` contain provenance, full details and caveats. No publication, device/browser action, autoplay or production change occurred.
