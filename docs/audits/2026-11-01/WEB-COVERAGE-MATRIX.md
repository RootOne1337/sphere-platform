# Сверка Web UI: карта покрытия

Срез по исходникам `555b620a` и документационным изменениям в рабочем дереве.
Матрица показывает, где искать действия и свидетельства по каждой странице,
а не подтверждает построчную проверку каждой кнопки или актуальность установки.
Параметр `[id]` обозначает динамический маршрут; `/fleet` и `/` — редиректы.
Проверка соответствия перечня `frontend/app/**/page.tsx` ведётся отдельно в

## Найденные несоответствия, требующие отдельной работы с продуктом

- `/discovery`: backend отправляет `discover_adb`, отсутствующую в dispatcher
  PC Agent; ошибки могут преобразоваться в пустой результат. Пустой ответ не
  доказывает успешное сканирование. [Разбор](../../operations/DEVICE-STREAM-GUIDE.md).
- Teaching: worker ограничивает библиотеку 100 папками, тогда как подсказка UI
  говорит о 20. [Контракт и граница](../../operations/TEACHING-WEB.md).
- В форме создания pipeline выбранные ранее устройства сохраняются при нажатии
  «Создать Pipeline»; после создания обработчик может отправить запуск на эти
  устройства. Сверка выполнена по исходнику, живое действие не воспроизводилось.
  [Порядок и ограничение](../../operations/TASKS-AND-ORCHESTRATION.md).
- `/accounts`: подсказка обещает генерацию пустого пароля, но форма требует его;
  пароль в полях исходного UI отображается открытым текстом. Недопустимый JSON
  metadata при редактировании может быть пропущен при сохранении остальных полей.
  [Управление](../../operations/USER-ADMIN-GUIDE.md).
- `/webhooks`: серверный список выбирает активные записи; отключённая запись
  может исчезнуть из списка, поэтому повторное включение через тот же экран не
  следует обещать без дополнительной проверки. [Исходник сервиса](../../../backend/services/n8n_webhook_service.py).
- `/event-triggers`: поле лимита запусков в час хранится, но в исследованном
  `EventReactor` его фактическая проверка не реализована. Не используйте значение
  формы как подтверждённый rate limit. [Руководство](../../operations/USER-ADMIN-GUIDE.md).
- `/webhooks`: в просмотренном backend найден метод отправки, но вызовов из других
  компонентов не обнаружено; сохранение webhook не доказывает delivery. Подпись
  вычисляется с использованием hex SHA-256 от секрета, а не самого секрета.
  Реальная доставка и совместимость получателя не проверены.
- `/events`, `/sessions` и `/webhooks`: при потере ответа сообщения об ошибке
  не доказывают, что mutation не произошла. Перед повтором нужен readback.
  [Реестр](USER-SECTIONS-COVERAGE.md).
- Очистка `/logs`: серверный код игнорирует ошибки удаления, поэтому 204 не
  является независимым подтверждением полного удаления. [Руководство](../../operations/DEVICE-LOG-STORAGE.md).

## Остаток

Для полной поэлементной приёмки нужны отдельные сценарии для каждого действия,
разрешения, отказа и состояния, включая мобильную компоновку, реальные данные,
согласованные роли и контролируемые устройства. Тесты с моками, статическое чтение
и сравнение маршрутов не заменяют эти проверки. Различайте отсутствие теста,
непроведённую приёмку и подтверждённый дефект; не исправляйте исторические receipts
задним числом.
