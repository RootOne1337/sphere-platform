# Архив выполненных экспериментов

Это исходники исследования `zaezd888` от 2026-11-01. Они **не подключены к production pipeline** и не дают допуск автономного управления. `skuter1` к этому пакету не относится: его видео локальный обработчик пока не получил.

`source-index.json` связывает каждый файл с точным исходным путём и SHA-256. Файлы сохранены без изменения, включая абсолютные/относительные пути, лимиты и зависимости. Это архив конкретного запуска, а не универсальный CLI для произвольной записи. Не импортируйте эти скрипты в сервер: некоторые содержат исполняемый код на верхнем уровне.

Для воспроизведения нужны неизменные пользовательские видео/PNG, metadata, предыдущие квитанции и отдельные runtime, перечисленные в основном [отчёте](../../SCOOTER-HUD-FUSION.md). Они не включены в Git. Скрипты следует восстановить по `original_path` в **отдельной копии рабочего пространства** с новыми пустыми output-каталогами; существующие результаты не перезаписывать. Зависимости и модели должны быть заранее проверены по receipt и pinned SHA. Повторный запуск части скриптов в существующем каталоге может быть намеренно отклонён.

Порядок состоявшегося эксперимента:

1. CPU `stage1_features.py`: 163 lossless float32 файла, сравнение с ранее извлечёнными feature SHA; процесс завершился до запуска GPU. `watch_stages.ps1` задаёт admission и ограничения дочернего процесса.
2. GPU `stage2_match.py`: FP32 LightGlue, LRU не больше двух кадров, 796 raw пар. Это ещё не геометрически подтверждённый граф.
3. CPU `verify_incremental.py`: 783 непустые verified пары; incremental mapping остановлен по 120-секундному лимиту без модели. Верифицированная копия DB сохранена.
4. CPU `global_fixed.py`: f=960, модель 163/163 и 15 706 точек; route audit rejected, global positioning `NO_CONVERGENCE`.
5. CPU `global_shared_focal.py`: тот же проверенный граф, начальный общий f=604,4325 с уточнением. Итог f=603,2399 и 15 049 точек; route audit также rejected. `compare_shared_focal.py` использует одинаковые HUD-рёбра и один train/test split внутри записи; это не независимая метрическая истина.
6. `calfvo_full.py` + `calfvo_tensor_reader.py`: отдельная полная оценка 901 кадра и ограниченная потоковая загрузка проверенного checkpoint. `calfvo_convention_fixture.py` сверяет преобразования с upstream; `parallax_audit.py` проверяет уже оценённую геометрию, не физическую глубину сцены.
7. `jump_forensics.py`, `jump_forensics_details.py` и `jump_adjacent.py` локализуют конфликт вращения и переноса на реальных кадрах около 20 с. `targeted_gap.py` и `targeted_gap_comparison.py` добавляют три реальных кадра в отдельном контроле, сохраняя старые соответствия. Этот участок выбрали по диагностике той же записи; результат не является независимым подтверждением.
8. `render_result.py` строит рисунок из сохранённых моделей и реальных PNG. Флаг `--refined` выбирает общий уточнённый фокус, `--targeted` — контроль 166 кадров. Привязки кадров и результата находятся в figure receipt.
9. `calfvo_reverse.py` выполняет настоящий порядок 900→0 на тех же 901 кадре. `calfvo_reverse_compare.py` сравнивает циклы соседних относительных преобразований и явно отделяет 450 рёбер подгонки масштаба от остальных 450. Согласованность вращения не переносится автоматически на оценку расстояния; обе стороны используют одну learned-модель и не являются ground truth.
10. `hud_heading.py` проверяет условное объединение направления и только подтверждённых HUD-интервалов: неизвестные интервалы разрывают результат на независимые участки. `render_heading.py` визуализирует направления и покрытие скорости, не выдавая их за сшитую карту.

Отдельная исследовательская функция [`plan_pose_gaps`](../../../../../scripts/pilot/route_overlap_sampling.py) формирует ограниченный план добавления исходных кадров по флагам и точной привязке к PTS. На полном исходном наборе она выбирает 497–499 без зашитых в код индексов. Это ещё не production-цикл повторной реконструкции и не самостоятельная проверка результата; её выход явно не даёт разрешения на управление.

Время, memory guard и выход каждого процесса надо читать по receipt. Снижение потребления памяти не доказывает корректность маршрута. Изменение маски, квоты признаков, графа пар, фокуса и mapper меняет эксперимент; сравнение нельзя называть чистым A/B, если изменены несколько факторов.

Модели [CalfVO](https://github.com/VladimirYugay/CalfVO) и [LightGlue](https://github.com/cvg/LightGlue) здесь только импортируются из проверенных локальных установок. Их код, веса и лицензии не заменяются этим архивом; никаких весов в репозитории нет. Все операции запускаются офлайн. Ограничения host reserve и запрет непроверенного допуска сохраняются.
