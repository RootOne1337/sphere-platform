# Навигация по карте игрового мира

Статус · архитектура и проверенный прототип планирования A→B. Первый участок взят из Black Russia. Исходные игровые ассеты хранятся в локальном стенде.

## Внешняя карта Black Russia · 20 ноября 2026

Собраны две послойные сетки из наружной сцены Ariane. Транспортная использует подтверждённое дорожное покрытие и геометрию столкновений. Пешеходная учитывает опору, воду, высоту персонажа и место для прохода. Общая привязка к координатам позволяет прокладывать маршрут с пересадкой. Предыдущие районные схемы ниже сохраняют значение для проверки полос и конкретных мест.

В повторе **на тех же 32 парах** автомобильный планировщик построил 25 маршрутов против 13 до исправлений. Все 13 ранее достижимых пар сохранились. Пешеходный планировщик нашёл 27 из 32. В отдельной смешанной выборке для 11 из 12 пар удалось найти автомобильный и пешеходный участки с общей точкой. Процент относится к статической выборке. Движение по полосам, фактическая скорость скутера и действия при выходе из транспорта требуют проверки в игре.

Участки без связи сохраняются в отчёте. Инструмент проверки выбирает соседние края разделённых частей сети и пересекает вертикальными лучами исходные DFF в нескольких местах между краями. Наличие дороги на виду можно сверить с материалом, высотой и данными коллизий. Прямая между ближайшими точками служит местом проверки и не добавляется в граф.

Автомобильный профиль использует ячейку 0,5 единицы, шаг по высоте 0,125, радиус 1,5, высоту 2 и предельную ступень 0,25. Пешеходный профиль использует радиус 0,5, высоту 1,875 и ступень 0,375. Смешанный режим проверяет места перехода на поверхностях обоих профилей и ищет полные пути с обеих сторон. Расстояние на транспорте получает вес 1/3 при сравнении вариантов. Оптимальность по всем возможным точкам пересадки, правила парковки, поворотный радиус и динамические препятствия пока остаются вне этой проверки.

### Воспроизведение

Нативный адаптер использует [Recast Navigation v1.6.0](https://github.com/recastnavigation/recastnavigation/releases/tag/v1.6.0) и Zig 0.13.0. Переменные PowerShell ниже обозначают исходную карту `$mapRoot`, каталог ранее проверенного адаптера Ariane с DragonFF `$adapter`, каталог артефактов `$outputDir`, старый атлас `$previousAtlas`, манифест общего вида `$roadReport` и сохранённую исходную выборку `$baseline`. Для публикации карт потребуются исходные рендеры и районные слои, собранные по командам ниже.

```powershell
./scripts/pilot/world_map_lab/build_recast_native.ps1 -RecastSource $recastSource -Zig $zigExe -Output $outputDir
python -m scripts.pilot.world_map_lab.collect_ariane_nav_geometry --source $mapRoot --geometry-tools $adapter --output $outputDir
python -m scripts.pilot.world_map_lab.world_navmesh build --folder $outputDir --road-report $roadReport
python -m scripts.pilot.world_map_lab.audit_world_navmesh --folder $outputDir
python -m scripts.pilot.world_map_lab.recheck_world_routes --folder $outputDir --baseline $baseline
python -m scripts.pilot.world_map_lab.audit_navmesh_gaps --source $mapRoot --geometry-tools $adapter --folder $outputDir
python -m scripts.pilot.world_map_lab.serve_world_navmesh --folder $outputDir --port 8817
```

Для первой базовой выборки сохраните копию `world-navigation-audit.json` после аудита. Последующие версии сравниваются по тем же XYZ. Для проверки отрисовки используйте режим рендера `--navigation-geometry` с каталогом геометрии, затем соберите атлас и примените `visible_ariane_surfaces`. Генератор `report_world_navigation` собирает HTML и районные сравнения. Проверки на синтетической геометрии включают параллельные уровни моста, шов тайлов, недостаточную опору, воду, непрерывный склон, резкую ступень и переход с транспорта на пешую сеть.


## Как должен выглядеть запуск

В вебе оператор выбирает карту и ставит метку на нужной высоте или вводит координаты. Начальная точка для живого запуска определяется по игровому кадру. Ручной старт доступен для предпросмотра. Клик сохраняет исходную метку и показывает точку привязки к доступной поверхности, её этаж и расстояние до неё. При цели внутри здания машина планирует подъезд, а пешеходный участок идёт через известный вход.

Система рассчитывает последовательность участков и переходов, например проезд до парковки, остановку, выход из транспорта, пеший подход и вход в интерьер. Для перехода хранятся условие начала, действие и визуальное подтверждение результата. Смена помещения сбрасывает локальную гипотезу, пока кадр не подтвердит позицию в новом пространстве. Для каждой игры такие переходы подключаются через профиль действий.

| Проезд | Направленные участки, полосы и допустимые повороты, ширина, уклон, высотный просвет, ограничения по габаритам, места остановки. Сначала проверяем связность по коллизиям. Разметку и одностороннее движение вводим из подтверждённых данных. |
| Ходьба | Проходимые полигоны с учётом радиуса персонажа, зазора над головой, лестниц и переходов. Мост и проезд под ним хранятся на разных поверхностях. Порталы привязаны к паре пространств. |
| Визуальные ориентиры | Ключевые ракурсы, 3D-точки на видимых поверхностях, соответствия 2D–3D, дескрипторы и связи видимости. Входы, развилки и однотипные кварталы получают ракурсы, помогающие отличить соседние места. |

Глобальный граф соединяет районы и переходы, локальный планировщик работает в ближайшем коридоре. Так же отдельно организованы вычисление маршрута по графу и планирование на локальной карте в Nav2. Recast/Detour оцениваем для подготовки пешеходных тайлов без зависимости от игрового движка. [Nav2 Route Server](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/route_server/configuring_route_server/) · [Recast Navigation](https://github.com/recastnavigation/recastnavigation)

### Как запекаются и хранятся точки

Импорт фиксирует хеши активных сцен, архивов моделей, коллизий, конфигурации координат и версии сборщика. Геометрия и ориентиры режутся на пространственные тайлы в координатах источника. Для ориентиров рендерятся выбранные положения и направления камеры. Признак сохраняется вместе с пересечением луча с исходной поверхностью и ID ракурса. Для сопоставления держим ракурсы с разным светом и высотой камеры. Выбор плотности и сжатия проверяем на отдельно снятых кадрах с замером доли найденных поз и ложных совпадений.

Пакет хранится как неизменяемые файлы с контрольными суммами и манифестом. Небольшой индекс доступен целиком, тяжёлая геометрия и дескрипторы загружаются по району. Версия активной карты фиксируется на весь сеанс движения. Правки оператора, временные перекрытия и ревизии источника записываются отдельно. Резервная копия включает исходный манифест, готовые тайлы и отчёты. Восстановление проверяет хеши и повторно открывает контрольный маршрут.

## Локализация и управление

1. При старте поиск по всему индексу выдаёт несколько подходящих районов. В каждом кандидате проверяются соответствия 2D–3D, геометрия позы и согласие ракурсов. Повторяющийся фасад и высокий счёт совпадений сами по себе не дают допуска. Иерархический поиск кандидатов и проверка позы поддерживаются в HLoc. Результаты его бенчмарков используем при выборе вариантов для сравнения в нашей сцене. [Hierarchical Localization](https://github.com/cvg/Hierarchical-Localization/)
2. При движении дешёвый трекинг обновляет положение между абсолютными проверками по карте. Тяжёлый поиск запускается при потере опор, неоднозначности или расхождении прогнозной и измеренной поз. Локализация берёт последний доступный кадр, просроченные кадры пропускаются.
3. Положение включает версию карты, пространство, эпоху захвата, номер и время кадра, XYZ, направление и оценку достоверности. Время кадра фиксируется захватом. Метка получения решения хранится отдельно. Поза и темп берутся из согласованных по времени наблюдений.
4. Контроллер выпрямляет траекторию в пределах проверенного коридора, снижает целевой темп по кривизне впереди, удерживает газ и руль между командами и учитывает препятствия по свежим кадрам. Если коридор перекрыт, локальный объезд проходит проверку статического просвета и контроля ориентации. Полное перекрытие ребра инициирует поиск альтернативы.
5. По таймауту позы ввод освобождается или включается предусмотренное торможение. Возобновление требует свежего подтверждения позы и направления. Остановка, восстановление и новый план видны на карте и в телеметрии.

Цель для первичного живого теста — коррекция по RGB в 5 Гц при измеренном возрасте кадра до команды. Текущий ориентир в контроллере составляет 250 мс. Считаем перцентили по каждому этапу и число команд, прошедших проверку свежести. Во время ночного тумана p95 одного поиска на стенде составил около 659 мс, поэтому пригодность текущей локализации для живого проезда ещё предстоит подтвердить.

## Что проверено на Ariane

В активном списке источника 48 сцен. Индекс по исходным файлам содержит 97 136 внешних размещений без LOD и 2 285 занятых тайлов по центрам объектов. Отчёт фиксирует хеш каждой активной сцены. Этот индекс показывает, где есть размещения, и служит входом к дальнейшей сборке коллизий и поверхностей.

Аудит декодировал 64 файла nodes в gta3.img. Все 28 991 уникальные дорожные XYZ из закреплённого браузерного графа GTA San Andreas совпали с архивными дорожными координатами. На контрольном участке ни один из 13 архивных дорожных узлов, попавших в его XY-границы, не оказался на поддержанной исходными коллизиями дороге Ariane. В навигационный пакет Black Russia эти дорожные узлы не вошли. Происхождение пешеходных узлов само по себе не подтверждает их соответствие тротуарам. [Разметка записей CPathNode в Plugin-SDK](https://github.com/DK22Pac/plugin-sdk/blob/master/plugin_sa/game_sa/CPathNode.h) · [Чтение областей путей в gta-reversed](https://github.com/gta-reversed/gta-reversed/blob/master/source/game_sa/PathFind.cpp#L3247)

Первый участок Нижегородска размером 225 × 320 игровых единиц проверен на сетке 0,5 ед. Расчёт использует одну доступную поверхность, статический просвет и ограничение соседства по уклону. Путь по заданным A и B имеет длину 267,36 ед., 515 точек и минимальный отступ по центрам ячеек 1,50 ед. Шесть маршрутов прошли проверку ячеек. Четыре запроса получили ожидаемый отказ при разрыве сети, непроезжей цели, неверной высоте или выходе за границы. Браузерная проверка включала ввод координат и перестроение после клика.

На этом этапе план имеет статус предпросмотра. Участок содержит геометрию проезда. Дорожные правила, многоуровневые коллизии, режим ходьбы, переходы внутрь и живое управление ожидают отдельной проверки. [Исходники лаборатории](../../scripts/pilot/world_map_lab/)

## Порядок проверки следующих выпусков

1. Собрать смежные районы, один мост с отдельным проездом снизу и точку перехода в интерьер. Проверить 3D-связность, стыки тайлов, подъезды, лестницы и допустимость пути для разных габаритов. Хранить происхождение каждого ребра и перечень плавающих или неподтверждённых соединений.
2. Проверить позицию на новых кадрах Black Russia, разметить истинные места и собрать реальные отрицательные пары из однотипных зданий. Сравнить плотность хранения, короткий трекинг, тяжёлый поиск и гибрид при том же бюджете. Начальные положения задавать в разных точках и на разных ракурсах. Анализировать отдельно доступность позы, ошибки принятых поз и задержку от кадра до команды.
3. Проверить два типа задач из пользовательского интерфейса. Первая строит и проходит произвольный наружный A→B, включая повороты и объезд. Вторая доезжает, останавливается, переключается на ходьбу и подтверждает вход. Тестовые цели и стартовые ошибки определяются до прогона, условия включают ясный день, сумерки, ночь и туман. Записываем коллизии, сход из коридора, трек скорости, простои и итоговый допуск к цели.
4. Измерить CPU, GPU, память и свежесть команд на 1, 5, 10 и 20 потоках. Статический индекс и тайлы разделяются по версии карты, состояние захвата и управления изолировано на окно. Тяжёлый поиск имеет ограниченную очередь и не вытесняет управление в активных окнах. Измеряем пропуски на каждом окне и долю завершённых маршрутов.

Критерий первого живого выпуска — завершение нового маршрута в допуске к цели, ноль столкновений в проверенных сценариях и подтверждённая работа по игровым кадрам. Отчёт должен позволять сравнить повтор запуска по версии карты, профилю камеры и контрольным кадрам.


## Покрытие исходников Ariane

Аудит активных IPL нашёл 97 136 наружных размещений без LOD. Для всех разрешаются ссылки на визуальные модели, у 96 820 есть одноимённая запись в COL. Количество записей COL измеряет покрытие исходников. Проходимость требует проверки формы коллизий, уклона, просвета и связности.

При импорте тип модели берётся из активных IDE. Для статических объектов Ariane заменяет исходный кадр атомика трансформацией IPL. У clump заменяется корень, а дочерние смещения остаются. Старый обзор применял кадр модели и IPL вместе. У новогоднего покрытия это повторно прибавляло позицию на тысячи игровых единиц. Пересчёт сетки проезда у Кремля с исправленным импортом дал те же шесть растров, включая проходимость, высоту и зазор. [Ariane, размещение объекта](https://github.com/Dryxio/ariane/blob/ff702f096b6a1751cdb418bdfc71fc3441457407/tools/euryopa/objectinst.cpp#L834-L856)

В первом обзоре по именам материалов пропускались `asfcrbtraskc1` и `perroad_01` в Батырево, `lf_arzasf7` на севере Арзамаса, `t_nn_pavem_a` и `t_nn_pavem_c` в Нижегородске. Исправленный обзор показывает три визуальных слоя. Совпадение по материалу и горизонтальная проекция позволяют искать участки для проверки. Для построения маршрута используются только проверенные поверхности отдельного тайла. Региональные цифры группируются по координатам размещения, а площадь проекции треугольников может включать перекрытия.

Замер исходной разметки на набережной даёт два центра полос длиной около 99,6 игровой единицы. Пример A→B проходит 83,1 единицы внутри каждой полосы. Связи между полосами и направления движения пока не подтверждены. Для пешего тайла у Кремля дополнительно проверены опора на исходную коллизию, препятствия и боковой зазор. В наружном слое осталось 6 763 ячейки с шагом 0,5 единицы после проверки. На них построен пример длиной 153,7 единицы. Многоуровневые связки, переходы, лестницы и входы требуют отдельной разметки и проверки.

В `README_RU.txt` 22.10.2026 относится к исправлению рендера земли MatFX9. У сборки есть известные пропуски. В README указаны 558 исходных размещений без моделей, среди них 499 интерьерных. Граф для всей карты требует чтения слоёв земли и их масок, проверки коллизий по фактическим границам мешей, а также выделения дорог, полос и пешеходных переходов на правильной высоте.

## Воспроизведение

## Цветной атлас

Рендер использует исходные наружные размещения, меши DFF и воду. Базовые текстуры TXD берутся из mip-уровней до 64 пикселей, у грунта дополнительно читаются цветовые маски MatFX9 и слои из родительских словарей. Это обзорное освещение с приближённым смешиванием слоёв. Рендер исходных треугольников показывает объём зданий и перекрытий. Интерактивный вид использует упрощённую сетку верхней поверхности для быстрого вращения всей карты.

На 2D-виде можно выключить дорожный слой. Цвета покрытия помогают искать участки для измерений. Отдельным цветом показаны проверенные центры двух полос на набережной. Узлы перекрёстков и направления движения проходят отдельную проверку до допуска к управлению.

~~~powershell
python -m scripts.pilot.world_map_lab.render_ariane_world --source <ariane-root> --geometry-tools <local-adapter-directory> --road-report <artifact-directory>/ariane-world-road-materials.json --output <atlas-directory>
python -m scripts.pilot.world_map_lab.build_ariane_atlas --output <atlas-directory> --road-report <artifact-directory>/ariane-world-road-materials.json --lane-report <artifact-directory>/ariane-kremlin-lanes.json
python -m unittest scripts.pilot.world_map_lab.test_ariane_world_render
~~~

Два HTML и изображения открываются из одного каталога. Если браузер не поддерживает WebGL 2, 3D-страница показывает исходный цветной рендер.


Для проверки Южного и Батырева оба слоя пересчитываются на ширину 4000 пикселей по исходным треугольникам. В 2D-атласе выбор района подгружает детальные текстуры и дорожное покрытие. Нижний уровень MatFX9 может храниться в основном архиве DFF, поэтому маски читаются из обеих разновидностей архива. Точечная проверка исходных поверхностей показала пропуски `nbt_rd6` на северном подъезде к Батырево и `t_asph_drt_lina/b` на юго-восточных дорогах. Эти участки добавлены в дорожный слой.

Чтобы собрать крупный план, обеим командам проекции и рендера передаются одна область `--area batyrevo` или `--area uzhny`, `--width 4000` и каталог района внутри атласа. Сначала собираются страницы районов по их дорожным манифестам, затем общий атлас подключает эти страницы и текстуры.
