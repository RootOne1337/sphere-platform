# Навигация по карте игрового мира

Статус · архитектура и проверенный прототип планирования A→B. Первый участок взят из Black Russia. Исходные игровые ассеты хранятся в локальном стенде.

## Поездка от A до B

В локальном веб-планировщике режим «Откуда → куда · автоподбор» принимает две точки с высотой поверхности. Пешеходный подход, проезд на Faggio и выход к цели строятся по соответствующим сетям Detour. На стенде скутер размещается в расчётном месте посадки. Для поездки к уже стоящему транспорту служит режим «К припаркованному скутеру → до цели». В нём точка V из выбранного сценария подставляется автоматически и доступна для ручного выбора. Для живой игры место транспорта должно поступать от наблюдения или оператора.

При полной сборке обеих сетей формируется индекс мест пересадки. Для существующей карты его можно пересчитать отдельно.

```powershell
python -m scripts.pilot.world_map_lab.build_taxi_transfers --folder $world --adapter $adapter
python -m scripts.pilot.world_map_lab.serve_world_navmesh --folder $world --adapter $adapter --port 8817
```

Индекс привязан к контрольным суммам обеих сетей. На этой карте найдено 384 733 места на 384 825 проверенных дорожных полигонах. Подбор сравнивает стоимость путей в проверенных кандидатах, считая единицу пути на скутере втрое дешевле пешей. Это приближение времени поездки. Включены проверка высоты и связности каждого участка, отсечение по нижней оценке расстояния и кэш 24 последних пар. После выбора A карта выделяет доступные пешеходные компоненты, в том числе через одну поездку. Заливка показывает проекцию сверху. Этаж, настил моста и точная доступность выбранной B проверяются при запросе пути.

В выборке из 53 пар (3 контрольные, 32 из прежней проверки и 18 случайных по всей карте) для 41 построен связный маршрут. В 40 маршрутах есть транспортный участок. В 12 остальных парах у выбранного конца нет связной пешеходной поверхности, ведущей к пересадке. На 48 обследованных ближайших переходах источник показывает пересечение с препятствием, разрыв опоры либо воду. Другие обходы требуют отдельной проверки. У этих 12 пар на странице `/taxi-report` указаны координаты, отмечен проблемный конец и приведены результаты проверки исходных коллизий.

Пять коротких поездок с визуальным управлением дошли до цели. В их числе Батырево и Нижегородск. Конечная ошибка на стенде составила 0,27–0,33 единицы карты. Видео первого лица строится по журналу поз этой попытки, графики используют те же метки времени. Исходные игровые кадры Scooter 4 также можно оформить через `film_game_archive`, который проверяет хеш видео и покадровую шкалу RTP. Показатели статической доступности, управления на геометрическом стенде и локализации в живой игре измеряются отдельно.

На новом длинном пути из 14 130 единиц базовое управление потеряло положение после 3 526 единиц транспортного участка. Дополнительные опоры позволили пройти 6 561. Вариант с постоянной проверкой коридора прошёл 2 867, а с проверкой остановки по оптическому потоку — 1 891. На отдельной попытке с известной стоянкой последний вариант прошёл 1 854. Экспериментальная коррекция доступна через `check_journey_rgb --experimental-tracking`. В вебе по умолчанию используется прежний контроллер. Законченное видео продолжительностью 24 минуты относится к ранее пройденному маршруту на геометрическом стенде.

## Подмена мира в классической GTA San Andreas

Для проверки физики персонажа и Faggio выбран оригинальный клиент для Windows. На карте Scooter 5 оцифрован подход 4,00 единицы, круг 312,96 и пеший выход 7,00. В игровом пакете вокруг этого пути 1 179 размещений с оригинальными трансформациями, включая 388 размещений для дальнего обзора. Все 388 ссылок проверены при повторном чтении IPL. В IMG упакованы 246 моделей и 116 словарей текстур. Вода и освещение берутся из исходного комплекта Black Russia.

У 157 из 164 записей COL оказался один и тот же исходный числовой идентификатор. При подготовке сборки каждая коллизия получает ID своей модели по имени из IDE. Коллизии включаются в IMG как отдельный файл, который загружает штатный стример игры. Повторное чтение игровых файлов подтвердило опору в 21 точке подхода, во всех 1 606 точках скутера и в 30 точках выхода. Максимальная разница высот на проезде 0,0065 единицы. Это измерение поверхности. Динамику шин, наклон и управление проверяют после запуска игры.

`build_classic_scenario` компилирует автономный сценарий средствами gta3sc 0.9.8 и повторно читает машинный скрипт. Он создаёт персонажа и Faggio 462, выставляет камеру, включает обычное управление и оставляет скутер припаркованным. Автопилот должен передавать игровые команды отдельным контуром по изображению. `open_classic_stand` готовит отдельную копию полного клиентского каталога, проверяет соответствие сценария маршруту и запускает игру. Для сценария нужно начать новую игру. Папка Ariane содержит карту и модели. Для физического прогона необходима совместимая игровая установка. [Компилятор GTA3script](https://github.com/thelink2012/gta3sc) · [Классическая трилогия Rockstar](https://store.rockstargames.com/game/buy-grand-theft-auto-the-trilogy)

~~~powershell
python -m scripts.pilot.world_map_lab.export_game_quarter --source $ariane --folder $network --adapter $geometryTools --route $route --output $quarter
python -m scripts.pilot.world_map_lab.build_classic_scenario --route "$quarter/route.json" --compiler $gta3sc --output $classic
python -m scripts.pilot.world_map_lab.stage_game_quarter --map-only --quarter $quarter --classic-scenario $classic --output $pack
python -m scripts.pilot.world_map_lab.check_native_surface --staged $pack --source $ariane --geometry-tools $geometryTools --output $floorReport
python -m scripts.pilot.world_map_lab.open_classic_stand --game $game --quarter $quarter --scenario $classic --output $playable
~~~

Браузерный порт использует отдельный наблюдатель. Он проверяет прохождение контрольных сечений через каждые шесть единиц в правильном порядке, включая дальнюю сторону квартала, и выход пешком в районе финиша. Наблюдатель получает состояние движка для проверки. Игровой видеорегистратор требует подтверждения всего транспортного участка. При проверке модуля Scooter 5 с файлами Ariane и техническим словарём браузер дошёл до девятого этапа, последним был запрос `models/coll/peds.col`. Персонаж и первый кадр мира на этой сборке ещё не появились. Сводка по подготовленной сборке публикуется на `/classic-game`.

Каждый IPL сохранён побайтно под отдельным коротким именем. Относительные индексы LOD действуют в своём IPL. Переупаковщик перечитывает каждую запись IMG и сверяет хеш с данными перед записью. В COL меняется идентификатор модели. Для исходных моделей и текстур сохраняются байты, включая сектора выравнивания. Поздний DFF рельефа заменяет одноимённый ранний DFF. В полный пакет включены вода и профиль освещения из исходного комплекта.

Остались 558 закомментированных размещений без исходной геометрии, внешняя ссылка на словарь `generic` и семь именованных групп анимаций объектов без соответствующего IFP в проверенных архивах. У 3 789 определений нет собственной COL, в это число входят дальние модели. Оно само по себе не определяет количество разрывов дорог. Пользовательский материал рельефа Ariane также требует визуальной сверки в игровом движке.

Для физического стенда подходит чистая совместимая PC-версия San Andreas с профилем полной замены мира. Автор Clean Map показывает удаление старых размещений при сохранении персонажа. GTA Mixed показывает работающий пример переноса городов и конфигурации расширения лимитов. SA Map Studio может выпустить одиночный мод для Mod Loader. Подтверждения автоматического импорта именно всей поставки Black Russia этим редактором нет. ### Проверка ресурсов Black Russia и отклика Faggio

Центральный каталог исходного ZIP Ariane (7 939 970 250 байт) содержит 149 файлов, включая 87 IMG. Упомянутого в README каталога `original/data` в этом ZIP нет. В каталогах IMG есть модель и текстуры Faggio, группа анимаций `bikev.ifp` и коллизии мира. Встроенная COL3 скутера из `models/gta3.img` содержит 13 сфер и 10 треугольников. В переданном комплекте отсутствуют `data/handling.cfg`, `data/vehicles.ide`, `anim/ped.ifp`, `models/coll/peds.col` и исполняемый игровой клиент. По коллизии можно определить форму контакта. Для разгона, торможения, баланса и посадки требуются код игры и соответствующие данные.

Для проверки браузерного OpenSA взяты два DFF из одного IMG и неизменённые функции `parseDff`, `parseDffCollision`, `buildVehicle` и `PhysicsWorld` ревизии `d30f4e8a`. У каждого прогона одна плоская поверхность, 120 шагов до подачи команды и ещё 180 шагов по 1/60 с. Для сравнения заданы одинаковые тестовые масса 1000, масштаб колёс 0,55 и сила 4200 либо 0. Расстояние измерено между конечными горизонтальными положениями в двух запусках. Эти параметры служат только для проверки реакции на ввод.

| Модель | Узлы колёс в DFF | Колёса в контроллере | Разница с газом и без, ед. |
| --- | --- | ---: | ---: |
| Faggio | `wheel_front`, `wheel_rear` | 0 | 0,00 |
| Premier | четыре угловых узла `wheel_*_dummy` | 4 | 17,25 |

Для повтора `$opensa` указывает на чистый checkout OpenSA указанной ревизии, `$probe` — на отдельный каталог теста, `$ariane` — на распакованную карту. Для вывода результатов в локальном веб-отчёте используйте каталог `vehicle-physics-audit` внутри собранного стенда и повторно запустите `report_classic_scenario`.

### Подготовка и загрузка квартала

В браузере собран sa-engine на ревизии `d66f65e1937516320d6f3cc6a6cab2a7671e018e`. Для этой версии нужен каталог данных классической GTA San Andreas 1.0 US. Исполняемый файл Windows браузеру не требуется. Сборка для WebAssembly включает поддержку модов. Порт ещё развивается, поэтому поведение скутера, анимации и управление требуют проверки в игровом мире. [Инструкции разработчика](https://github.com/ghosty2004/sa-engine/blob/d66f65e1937516320d6f3cc6a6cab2a7671e018e/web/README.md)

В комплекте Ariane найдены Faggio, модели людей и группа анимаций `bikev.ifp`. Отдельные файлы `anim/ped.ifp`, `data/handling.cfg`, определения транспорта и людей, параметры поверхностей и основной сценарий отсутствуют. Предварительная инвентаризация проверяет необходимые файлы, а запуск в Chrome независимо проверяет загрузку движка. В локальном запуске браузер загрузил мод и выполнил 1666 статических инициализаторов. Управляемый персонаж в этом запуске не появился. Страница `/gameplay` содержит журнал, результат проверки игрового комплекта и состояние проверки вождения.

Для первого теста выбран квартал в Южном вокруг короткого смешанного маршрута. Экспортёр извлекает оригинальные DFF, TXD вместе с родительскими словарями, отдельные COL и точные трансформации наружных объектов. Повторное чтение IMG и IPL проверяет содержимое и ориентацию. Пакет квартала содержит 710 исходных размещений ближней сцены и 124 размещения для дальнего обзора. Проверены 227 моделей, 142 словаря текстур, 205 моделей коллизий и все 124 связи с уровнями детализации. Номера размещений пересчитываются отдельно для каждого исходного IPL. На карте встречаются одноимённые IPL в разных районах. Подготовка игровой папки создаёт отдельное дерево, сохраняет определения персонажей и транспорта, назначает свободные ID моделям квартала и заменяет список размещений мира. Игровые данные остаются на ПК.

## Как должен выглядеть запуск

В вебе оператор выбирает карту и ставит метку на нужной высоте или вводит координаты. Начальная точка для живого запуска определяется по игровому кадру. Ручной старт доступен для предпросмотра. Клик сохраняет исходную метку и показывает точку привязки к доступной поверхности, её этаж и расстояние до неё. При цели внутри здания машина планирует подъезд, а пешеходный участок идёт через известный вход.

Система рассчитывает последовательность участков и переходов, например проезд до парковки, остановку, выход из транспорта, пеший подход и вход в интерьер. Для перехода хранятся условие начала, действие и визуальное подтверждение результата. Смена помещения сбрасывает локальную гипотезу, пока кадр не подтвердит позицию в новом пространстве. Для каждой игры такие переходы подключаются через профиль действий.

### Как запекаются и хранятся точки

Импорт фиксирует хеши активных сцен, архивов моделей, коллизий, конфигурации координат и версии сборщика. Геометрия и ориентиры режутся на пространственные тайлы в координатах источника. Для ориентиров рендерятся выбранные положения и направления камеры. Признак сохраняется вместе с пересечением луча с исходной поверхностью и ID ракурса. Для сопоставления держим ракурсы с разным светом и высотой камеры. Выбор плотности и сжатия проверяем на отдельно снятых кадрах с замером доли найденных поз и ложных совпадений.

Пакет хранится как неизменяемые файлы с контрольными суммами и манифестом. Небольшой индекс доступен целиком, тяжёлая геометрия и дескрипторы загружаются по району. Версия активной карты фиксируется на весь сеанс движения. Правки оператора, временные перекрытия и ревизии источника записываются отдельно. Резервная копия включает исходный манифест, готовые тайлы и отчёты. Восстановление проверяет хеши и повторно открывает контрольный маршрут.

## Локализация и управление

1. При старте поиск по всему индексу выдаёт несколько подходящих районов. В каждом кандидате проверяются соответствия 2D–3D, геометрия позы и согласие ракурсов. Повторяющийся фасад и высокий счёт совпадений сами по себе не дают допуска. Иерархический поиск кандидатов и проверка позы поддерживаются в HLoc. Результаты его бенчмарков используем при выборе вариантов для сравнения в нашей сцене. [Hierarchical Localization](https://github.com/cvg/Hierarchical-Localization/)
2. При движении дешёвый трекинг обновляет положение между абсолютными проверками по карте. Тяжёлый поиск запускается при потере опор, неоднозначности или расхождении прогнозной и измеренной поз. Локализация берёт последний доступный кадр, просроченные кадры пропускаются.
3. Положение включает версию карты, пространство, эпоху захвата, номер и время кадра, XYZ, направление и оценку достоверности. Время кадра фиксируется захватом. Метка получения решения хранится отдельно. Поза и темп берутся из согласованных по времени наблюдений.
4. Контроллер выпрямляет траекторию в пределах проверенного коридора, снижает целевой темп по кривизне впереди, удерживает газ и руль между командами и учитывает препятствия по свежим кадрам. Если коридор перекрыт, локальный объезд проходит проверку статического просвета и контроля ориентации. Полное перекрытие ребра инициирует поиск альтернативы.
5. По таймауту позы ввод освобождается или включается предусмотренное торможение. Возобновление требует свежего подтверждения позы и направления. Остановка, восстановление и новый план видны на карте и в телеметрии.

Цель для первичного живого теста — коррекция по RGB в 5 Гц при измеренном возрасте кадра до команды. Текущий ориентир в контроллере составляет 250 мс. Считаем перцентили по каждому этапу и число команд, прошедших проверку свежести. Во время ночного тумана p95 одного поиска на стенде составил около 659 мс, поэтому пригодность текущей локализации для живого проезда ещё предстоит подтвердить.

[Каталог маршрутов](../../frontend/src/features/stream/TeachingRecordingCatalog.tsx)
- План содержит точки привязки, проверенные пространственные участки, коридоры, режимы движения и ожидаемые переходы. Исполнитель запускается отдельным действием, после привязки к окну и подтверждённой стартовой позы той же версии карты. Возобновление после потери позы оставляет исходную цель и проверяет остаток маршрута.

Дорожный план нуждается в явном адаптере для подачи геометрического коридора и профиля темпа. Модель контракта видеообучения сохраняет действующие проверки исходника и позы. - Для другой игры подключаются источник геометрии, правила проходимости, камера, действия и профиль транспорта. В общем планировщике идентификатор игры используется как ключ пакета данных. При наличии только записи продолжает применяться режим повтора маршрута по видео.

## Что проверено на Ariane

В активном списке источника 48 сцен. Индекс по исходным файлам содержит 97 136 внешних размещений без LOD и 2 285 занятых тайлов по центрам объектов. Отчёт фиксирует хеш каждой активной сцены. Этот индекс показывает, где есть размещения, и служит входом к дальнейшей сборке коллизий и поверхностей.

Аудит декодировал 64 файла nodes в gta3.img. Все 28 991 уникальные дорожные XYZ из закреплённого браузерного графа GTA San Andreas совпали с архивными дорожными координатами. На контрольном участке ни один из 13 архивных дорожных узлов, попавших в его XY-границы, не оказался на поддержанной исходными коллизиями дороге Ariane. В навигационный пакет Black Russia эти дорожные узлы не вошли. Происхождение пешеходных узлов само по себе не подтверждает их соответствие тротуарам. [Разметка записей CPathNode в Plugin-SDK](https://github.com/DK22Pac/plugin-sdk/blob/master/plugin_sa/game_sa/CPathNode.h) · [Чтение областей путей в gta-reversed](https://github.com/gta-reversed/gta-reversed/blob/master/source/game_sa/PathFind.cpp#L3247)

Первый участок Нижегородска размером 225 × 320 игровых единиц проверен на сетке 0,5 ед. Расчёт использует одну доступную поверхность, статический просвет и ограничение соседства по уклону. Путь по заданным A и B имеет длину 267,36 ед., 515 точек и минимальный отступ по центрам ячеек 1,50 ед. Шесть маршрутов прошли проверку ячеек. Четыре запроса получили ожидаемый отказ при разрыве сети, непроезжей цели, неверной высоте или выходе за границы. Браузерная проверка включала ввод координат и перестроение после клика.

На этом этапе план имеет статус предпросмотра. Участок содержит геометрию проезда. Дорожные правила, многоуровневые коллизии, режим ходьбы, переходы внутрь и живое управление ожидают отдельной проверки. [Исходники лаборатории](../../scripts/pilot/world_map_lab/)

## Порядок проверки следующих выпусков

1. Собрать смежные районы, один мост с отдельным проездом снизу и точку перехода в интерьер. Проверить 3D-связность, стыки тайлов, подъезды, лестницы и допустимость пути для разных габаритов. Хранить происхождение каждого ребра и перечень плавающих или неподтверждённых соединений.
2. Проверить позицию на новых кадрах Black Russia, разметить истинные места и собрать реальные отрицательные пары из однотипных зданий. Сравнить плотность хранения, короткий трекинг, тяжёлый поиск и гибрид при том же бюджете. Начальные положения задавать в разных точках и на разных ракурсах. Анализировать отдельно доступность позы, ошибки принятых поз и задержку от кадра до команды.
3. Проверить два типа задач из пользовательского интерфейса. Первая строит и проходит произвольный наружный A→B, включая повороты и объезд. Вторая доезжает, останавливается, переключается на ходьбу и подтверждает вход. Тестовые цели и стартовые ошибки определяются до прогона, условия включают ясный день, сумерки, ночь и туман. Записываем коллизии, сход из коридора, трек скорости, простои и итоговый допуск к цели.
4. Измерить CPU, GPU, память и свежесть команд на 1, 5, 10 и 20 потоках. Статический индекс и тайлы разделяются по версии карты, состояние захвата и управления изолировано на окно. Тяжёлый поиск имеет ограниченную очередь и не вытесняет управление в активных окнах. Измеряем пропуски на каждом окне и долю завершённых маршрутов.

Критерий первого живого выпуска — завершение нового маршрута в допуске к цели, ноль столкновений в проверенных сценариях и подтверждённая работа по игровым кадрам. Отчёт должен позволять сравнить повтор запуска по версии карты, профилю камеры и контрольным кадрам.


## Покрытие исходников Ariane

Аудит активных IPL нашёл 97 136 наружных размещений без LOD. Для всех разрешаются ссылки на визуальные модели, у 96 820 есть одноимённая запись в COL. Количество записей COL измеряет покрытие исходников. Проходимость требует проверки формы коллизий, уклона, просвета и связности.

При импорте тип модели берётся из активных IDE. Для статических объектов Ariane заменяет исходный кадр атомика трансформацией IPL. У clump заменяется корень, а дочерние смещения остаются. Старый обзор применял кадр модели и IPL вместе. У новогоднего покрытия это повторно прибавляло позицию на тысячи игровых единиц. Пересчёт сетки проезда у Кремля с исправленным импортом дал те же шесть растров, включая проходимость, высоту и зазор. [Ariane, размещение объекта](https://github.com/Dryxio/ariane/blob/ff702f096b6a1751cdb418bdfc71fc3441457407/tools/euryopa/objectinst.cpp#L834-L856)

В первом обзоре по именам материалов пропускались `asfcrbtraskc1` и `perroad_01` в Батырево, `lf_arzasf7` на севере Арзамаса, `t_nn_pavem_a` и `t_nn_pavem_c` в Нижегородске. Исправленный обзор показывает три визуальных слоя. Совпадение по материалу и горизонтальная проекция позволяют искать участки для проверки. Для построения маршрута используются только проверенные поверхности отдельного тайла. Региональные цифры группируются по координатам размещения, а площадь проекции треугольников может включать перекрытия.

Замер исходной разметки на набережной даёт два центра полос длиной около 99,6 игровой единицы. Пример A→B проходит 83,1 единицы внутри каждой полосы. Связи между полосами и направления движения пока не подтверждены. Для пешего тайла у Кремля дополнительно проверены опора на исходную коллизию, препятствия и боковой зазор. В наружном слое осталось 6 763 ячейки с шагом 0,5 единицы после проверки. На них построен пример длиной 153,7 единицы. Многоуровневые связки, переходы, лестницы и входы требуют отдельной разметки и проверки.

В `README_RU.txt` 22.10.2026 относится к исправлению рендера земли MatFX9. У сборки есть известные пропуски. В README указаны 558 исходных размещений без моделей, среди них 499 интерьерных. Граф для всей карты требует чтения слоёв земли и их масок, проверки коллизий по фактическим границам мешей, а также выделения дорог, полос и пешеходных переходов на правильной высоте.

## Воспроизведение

Команды запускаются из корня репозитория. Для аудита нужны архив Ariane, закреплённый бинарный граф браузерного стенда San Andreas и подготовленная сетка квартала. Для сборки предпросмотра нужны та же сетка и вид сверху, выровненный в её координатах.

~~~powershell
python -m scripts.pilot.world_map_lab.index_ariane_world --root <ariane-root> --report <placement-index.json>
~~~

Пути в угловых скобках обозначают входы стенда и имена выходных файлов. Сборщик выпускает автономный HTML, который открывается локально. Сетка и снимок карты входят в HTML. Статический планировщик работает в браузере без подключения к игровому окну.

## Цветной атлас

Рендер использует исходные наружные размещения, меши DFF и воду. Базовые текстуры TXD берутся из mip-уровней до 64 пикселей, у грунта дополнительно читаются цветовые маски MatFX9 и слои из родительских словарей. Это обзорное освещение с приближённым смешиванием слоёв. Рендер исходных треугольников показывает объём зданий и перекрытий. Интерактивный вид использует упрощённую сетку верхней поверхности для быстрого вращения всей карты.

На 2D-виде можно выключить дорожный слой. Цвета покрытия помогают искать участки для измерений. Отдельным цветом показаны проверенные центры двух полос на набережной. Узлы перекрёстков и направления движения проходят отдельную проверку до допуска к управлению.

~~~powershell
python -m scripts.pilot.world_map_lab.render_ariane_world --source <ariane-root> --geometry-tools <local-adapter-directory> --road-report <artifact-directory>/ariane-world-road-materials.json --output <atlas-directory>
python -m scripts.pilot.world_map_lab.build_ariane_atlas --output <atlas-directory> --road-report <artifact-directory>/ariane-world-road-materials.json --lane-report <artifact-directory>/ariane-kremlin-lanes.json
python -m unittest scripts.pilot.world_map_lab.test_ariane_world_render
~~~

Два HTML и изображения открываются из одного каталога. Если браузер не поддерживает WebGL 2, 3D-страница показывает исходный цветной рендер.


Для проверки Южного и Батырева оба слоя пересчитываются на ширину 4000 пикселей по исходным треугольникам. В 2D-атласе выбор района подгружает детальные текстуры и дорожное покрытие. Нижний уровень MatFX9 может храниться в основном архиве DFF, поэтому маски читаются из обеих разновидностей архива. Точечная проверка исходных поверхностей показала пропуски `nbt_rd6` на северном подъезде к Батырево и `t_asph_drt_lina/b` на юго-восточных дорогах. Эти участки добавлены в дорожный слой.

Чтобы собрать крупный план, обеим командам проекции и рендера передаются одна область `--area batyrevo` или `--area uzhny`, `--width 4000` и каталог района внутри атласа. Сначала собираются страницы районов по их дорожным манифестам, затем общий атлас подключает эти страницы и текстуры.
