# Прямой рекордер: контракт следующего блока

Статус: **DESIGN, не реализовано**. 15 октября2026. Текущий production-код не записывает произвольную native-траекторию в воспроизводимый direct-формат. [Установленная граница](../audits/2026-10-15/MODE-PEER-DELIVERY.md).

## Один канал, отдельные доказательства

Video peer живёт независимо от режима «управление / запись / XPath». Запись наблюдает события того же scoped native controller; включение записи не закрывает peer и не назначает нового владельца. XPath выбирает элемент локально в браузере; чтение Android-дерева остаётся отдельной командой и при необходимости ждёт подтверждённого RELEASE. ACL/auth/capture меняются независимо и продолжают отзывать ввод.

Нужны observer hooks для реально принятых DOWN/MOVE/UP/CANCEL и terminal native ACK. Зафиксировать controller generation, capture epoch/размер/rotation, локальный requestID, monotonic t0 и относительные времена точек. Это данные локальной записи, не общий диагностический лог; координаты/текст/trajectory не отправлять в fleet telemetry. Observer не должен менять send cadence, backpressure или путь транспорта.

## Формат выполнения

Текущий swipe описывает только начальную/конечную точки и длительность. Он не эквивалентен произвольной кривой/движению назад, long-press и мультитачу. До реализации typed trajectory action в общем action contract и APK такой жест нельзя объявлять успешно воспроизводимым. Не сериализовать raw WebRTC wire frames с owner/session/key — они принадлежат старой сессии и не являются форматом сценария.

Предложение: версионированный `gesture_path` с ограниченным массивом `{t_ms,x,y}`, source dimensions/orientation и одним pointer в первой версии. Отдельные верхние пределы времени/числа точек/размера JSON; валидация всей записи до начала исполнения. Нормализация масштаба ровно один раз, запрет воспроизведения с неподтверждённой геометрией/rotation. Android выполняет через существующий native actor, а не последовательность shell input swipe с подъёмом пальца между сегментами. Реальный terminal release обязателен при отмене/ошибке/watchdog.

Для клика допустим существующий tap только после терминального ACK и при движении в пороге. Для прямого swipe возможна явная оптимизация **после** проверки геометрии всего пути; не подменять произвольную траекторию. Клавиши сохраняют пары DOWN/UP, modifiers и reset; Android Unicode/IME-композиция должны иметь воспроизводимую операцию commit, не shell escaping. Пароли по умолчанию не записывать и явно информировать пользователя о содержимом сценария.

## Состояния записи

`local-pending → native-confirmed / native-cancelled / native-unknown`. Индивидуальный gestureID не путать с порядковым номером wire message. Начало новой записи не подтверждает предыдущий pending. Переключение клиента, blur/visibility/capture resize, transport loss или потеря роли финализирует затронутый жест как cancelled/unknown. Поздний ACK проверяет точную сессию/capture/generation. Отправленные касания никогда не воспроизводятся повторно автоматически.

При Stop во время удержания запись остаётся drain до terminal outcome; UI показывает pending, не теряет черновик и не выдаёт готовый DAG. Несколько клиентов могут управлять; recorder сохраняет только команды своего контроллера и отмечает вмешательство других как interrupted. Не объединять траектории разных клиентов в успешный жест. Вставка в DAG отделена от реального выполнения; неизвестные действия не получают зелёную галочку.

## Поставка и приёмка

Общий action contract → backend validation/model/export → APK actor handler + capability negotiation → browser observer/recording review → runner. Старые APK получают явное «не поддерживается», без падения на shell и без скрытой потери precision. VersionCode/подпись APK проверяются в OTA. Совместимые tap/swipe записи остаются читаемыми.

Обязательные кейсы: localhost/LAN/WAN прямой + реальный fallback; Start/Stop без пересоздания peer;10клиентов, чужой DOWN во время записи; trajectory туда-обратно и curve; hold→blur; отмена/неизвестный ACK; rotation/capture epoch; network change/ICE restart; клавиши/Unicode/composition; XPath при активной записи; task launch handoff; reload/back/dirty guard; ограниченная память и очистка recorder session. Скриншоты и trace связывают actual Android receipt с записью/воспроизведением; отсутствие UI-ошибки не является доказательством исполнения.
