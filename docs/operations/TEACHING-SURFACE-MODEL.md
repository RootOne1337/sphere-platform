## Как открыть

1. На странице записи выберите сохранённый маршрут. Ссылка на его существующее
   задание восстанавливается из библиотеки этого профиля браузера.
2. После завершения восстановления камер выберите начальный ракурс и длину
   короткого участка, затем нажмите «Построить поверхности».
   Нужен запущенный локальный обработчик3342 и подготовленный OpenMVS CPU.
   На другой компьютер модель автоматически не передаётся.
3. Обработка показывает отдельные этапы: проверка, multi-view depth, mesh,
   текстурирование. Повторный запрос читает тот же intent и не запускает дубликат.
4. В сохранённом результате выберите «3D-модель». Доступны «Текстуры»,
   «Поверхности», «Нормали», «Каркас», траектория и ползунок камер прохода.
   Левая кнопка вращает, правая перемещает, колесо приближает.
5. «Развернуть» открывает полноэкранный просмотр. «Скачать GLB» сохраняет один
   проверенный файл с фотографиями внутри. Этот проход можно снова выбрать позже.

Существующая «Визуальная сцена» показывает Gaussian-результат отдельно. Он может
выглядеть плавнее между исходными камерами, но его внешний вид не заменяет геометрию.
Открывать проект повторно для просмотра сохранённого результата не требуется.

## Что именно строится

COLMAP задаёт уже восстановленные K/позы. OpenMVS2.4.0 CPU выполняет multi-view
depth, согласованное объединение глубин и meshing. На mesh проецируются исходные
фотографии после проверки видимости: вершины и центр внутри кадра, keep-mask,
угол к поверхности и perspective-correct z-buffer. Невидимые грани исключаются;
геометрическое закрытие дыр и сглаживание выключены.

На маршруте012 native текстурирование OBJ и GLB дало неприемлемые диагностические
изображения; одна смена направления UV проблему не решила. Поэтому выбран явно
проверяемый projective bake. Это вывод из локального опыта, не заявление о дефекте
OpenMVS для любых данных. Проекция не исправляет ошибочные поверхности и калибровку.

На стенах/земле появляются текстурированные поверхности. Небо, закрытая сторона
здания, однотонные или бликующие участки могут оставаться пустыми. Это не извлечение
игровых ассетов, не лидар и не полная копия уровня. Поворот на180° в ранее невидимую
область не обязан показывать модель. Плохой параллакс нельзя исправить числом FPS.

## Пределы текущего профиля

| Граница | Значение |
|---|---|
| Платформа внешнего инструмента | Подготовленный Windows CPU release2.4.0, проверка трёх binary SHA-256 |
| Связанные ракурсы | 3–24 в выбранном фрагменте из максимум240камер; по умолчанию18 |
| CPU | Не более4потоков native |
| Геометрический depth | Длинная сторона до960px, до5соседних видов, минимум3для fusion |
| Наблюдавшаяся mesh | Цель330000граней, жёсткий предел350000; без hole filling/smoothing |
| Фотографии | JPEG95, исходники не меняются; до2048px/фото и суммарно64Miпикселей |
| GLB | До64MiB, один BIN, JPEG внутри, только unlit material; никаких внешних URI |
| Рабочие файлы | До4GiB на surface-попытку; retained quota основного сервиса сохраняется |
| Время | До30минут общего процесса; monitor дополнительно подтверждает завершение |
| Память/диск | RAM≥4GiB free, commit<85%, disk≥20GiB free; отказ сохраняет причину |

Разрешение исходной записи FullHD сохраняется. Текущий профиль depth960 и отдельный
бюджет текстур открыто ограничивают детализацию mesh; больше пикселей на экране
просмотра не создаёт новых измеренных деталей. Полный эксперимент012 содержал80фотографий
1213×682 и был отклонён визуально из-за ложных поверхностей. Для текущего короткого
фрагмента бюджет позволяет сохранить текстуры1920×1080. Это производный ресурс для Web;
все81оригинальных PNG1920×1080 остаются неизменными.

## Жизненный цикл и диагностика

`POST /jobs/<id>/surface/start` допускается с той же capability, после завершения
камер и при отсутствии другой тяжёлой работы. Один глобальный активный процесс
сохраняется и для основного pipeline, и для surface. Во время обработки рекордер
не начинает новую запись. `surface/cancel` отменяет только этот производный этап.

Перезапуск сервиса помечает незавершённый этап failed и ставит CANCEL. Даже поздний
READY или review_required от прежнего процесса не выдаётся как доступная модель. Неопределённая попытка
не перезапускается автоматически. Исходники и прежний Gaussian остаются доступны.

`GET /jobs/<id>/surface` повторно проверяет размер, hash, связь с исходником,
геометрию/индексы/конечность чисел, бюджеты JPEG и отсутствие внешних ресурсов.
Браузер сверяет SHA-256 до GLTFLoader и также запрещает внешние URI/декодеры.
Секретная capability не добавляется в URL, GLB, access log или документацию.

Типичные отказы: `surface_openmvs_cpu_not_installed`, `surface_native_digest_changed`,
`surface_source_binding_changed`, `surface_view_limit_or_camera_binding`,
`surface_insufficient_visible_triangles`, `surface_fragment_range_invalid`,
`surface_result_binding_changed`,
`surface_asset_changed`, `resource_guard`. Не очищайте исходники при таком отказе.

## Выбор инструмента и дальнейшая проверка

- [OpenMVS2.4.0](https://github.com/cdcseacave/openMVS/releases/tag/v2.4.0):
  готовая CPU-сборка подходит текущей AMD-машине. Используются фактические опции
  pinned release, а не несовместимые новые опции `develop`.
- [2D Gaussian Splatting](https://github.com/hbb1/2d-gaussian-splatting):
  surface-oriented discs и TSDF mesh — сильный кандидат отдельного NVIDIA-опыта;
  готовый rasterizer требует CUDA. Это не конвертер текущего Brush-PLY одной кнопкой.
- [gsplat](https://github.com/nerfstudio-project/gsplat): развивающаяся CUDA-библиотека,
  включая2DGS; новая версия сама по себе не доказывает переносимость на RX9070.
- [Open3D TSDF](https://open3d.org/docs/release/tutorial/t_reconstruction_system/integration.html):
  пригоден для fusion проверенных глубин/поз; не устраняет ошибку исходной глубины.

В сообщениях пользователей2DGS описаны [плохие cluttered участки](https://github.com/hbb1/2d-gaussian-splatting/issues/133)
и [сравнение качества со стройплощадкой/3DGS](https://github.com/hbb1/2d-gaussian-splatting/issues/245).
Это частные воспроизводимые жалобы, не benchmark нашей игры. Выбор проверяется
на сохранённой записи и независимых ракурсах, не по одному скриншоту репозитория.

Дальше отдельно требуются ошибки глубины/поверхностей, неизвестные области,
локализация на свежем игровом кадре и low-quality повторе, camera/body transform,
живые препятствия и короткий closed-loop тест. Моторной модели нельзя объявлять
картинку со стрелкой поддерживаемым goal API без отдельного опыта.

OpenMVS используется как внешний offline backend с AGPL-3.0 и сохранённой
атрибуцией. Бинарники не включены в APK/Web bundle; условия продуктового
распространения проверяются отдельно.
