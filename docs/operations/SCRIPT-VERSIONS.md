## Операторский путь

1. Открыть [Сценарии проверочного веба](http://127.0.0.1:3015/scripts).
   Каталог по умолчанию показывает активные сценарии. «Архив» и «Все сценарии»
   меняют фильтр на сервере, сохраняют поиск и возвращают страницу на первую.
   Размер страницы — 50; архив не ограничен первой страницей активного каталога.
2. Выбрать «История и управление». Диалог читает метаданные сценария,
   его текущую версию и историю. Версии можно просматривать и после архивирования.
   Просмотр не запускает Android-команд.
3. Выбрать неизменяемую версию: веб отдельно получает её DAG, полный серверный
   SHA-256, дату UTC, автора и описание. Текущий DAG читается для сравнения.
   Поля, похожие на токены, пароли и ключи, скрываются в панели кода.
4. Сравнение показывает изменённые структурные пути, максимум 200. Оно выполняется
   после скрытия учётных данных и не доказывает равенство скрытых значений.
   Полный хеш относится к оригинальному DAG, а не к его показанному представлению.
5. Для отката выбрать другую версию, нажать «Откатить к выбранной версии»,
   прочитать влияние и подтвердить. Подтверждение фиксирует ID текущей версии
   и ID выбранной версии; смена выбора снимает подтверждение.
6. Откат создаёт **новую** версию с DAG и хешем выбранной. Это не перемещение
   указателя на старую запись. Исходные версии сохраняются. Веб проверяет ID
   сценария/организации, новый ID и номер версии, полный DAG и хеш ответа.
7. Новый запуск из каталога показывает зафиксированные номер и SHA-256 версии.
   И одиночное задание, и пакет передают серверу эту версию как условие допуска.
   Успешный ответ должен содержать именно её `script_version_id`.
8. Для архивирования нажать «В архив», прочитать влияние и подтвердить.
   Веб передаёт условие текущей версии, ожидает 204 и проверяет архивное состояние
   новым GET. После этого сценарий находится через вкладку «Архив».

## Влияние на задания

- Архив скрывает сценарий из активного каталога; новые изменения, откат
  и новые запуски архивного сценария отклоняются. Редактор из архивной карточки
  не предлагается. История и DAG остаются доступны по праву `script:read`.
- Архивирование **не отменяет уже созданные задания** и не очищает очереди.
  Для остановки используется отдельный протокол отмены задания.
- Откат **не меняет `script_version_id` существующих задач или пакетов**.
  Следующий допущенный запуск фиксирует новую текущую версию.
- Автоматическое восстановление из архива этим контрактом не предусмотрено:
  соответствующего API пока нет. Диалог не изображает несуществующую кнопку.

## HTTP и совместимость

| Операция | Контракт | Предел |
| --- | --- | --- |
| Каталог | `GET /api/v1/scripts?state=active\|archived\|all&page=1&per_page=50&query=...` | Default `active`; per_page 1–200; tenant scope; стабильный порядок updated_at/id |
| Метаданные/история | `GET /api/v1/scripts/{id}?include_dag=false` | Все метаданные истории; это пока не пагинированная история |
| Один DAG | `GET /api/v1/scripts/{id}/versions/{version_id}` | Версия должна принадлежать этому сценарию и организации |
| Откат | `POST /api/v1/scripts/{id}/versions/{version_id}/rollback` | Body `{expected_current_version_id: UUID}`; создаёт новую версию |
| Архив | `DELETE /api/v1/scripts/{id}?expected_current_version_id=UUID` | 204 после commit; версии сохранены |
| Редактирование | `PUT /api/v1/scripts/{id}` | Опциональное поле `expected_current_version_id` до любых изменений |
| Задание | `POST /api/v1/tasks` | Опциональное `expected_current_version_id`; response `script_version_id` |
| Пакет | `POST /api/v1/batches` | То же условие; все будущие волны фиксируют принятую версию |

Старые API-клиенты могут не передавать условие; их контракт сохраняется.
Они не получают оптимистическую защиту от устаревшего выбора. Включённый
в F27 каталог передаёт условие всегда. Остальные точки запуска не объявляются
переоборудованными этим этапом.

Update/archive/rollback блокируют tenant-owned строку сценария `FOR UPDATE NOWAIT`
до commit. Условный Run держит shared row lock до commit допуска: независимые
допуски сосуществуют, а изменение версии не может пройти одновременно.
Конфликт возвращает 409, а не неограниченное ожидание. Повторные чтения строки
обновляют ORM identity map перед проверкой версии. Отдельный SQL writer, который
обходит эти service paths, не поддерживается этим протоколом.

Права: `device_manager`, `org_admin`, `org_owner`, `super_admin` имеют `script:write`.
`viewer` и `script_runner` читают историю без кнопок записи. Право запуска
проверяется сервером отдельно через `script:execute`. Чужой сценарий/версия
возвращает 404; нарушение права — 403. Tenant isolation дополнительно проверена
под настоящей non-owner PostgreSQL ролью с активным RLS.

## Ошибки и восстановление

- Ошибка первого чтения или обновления не считается пустой историей. Кнопки
  записи блокируются; доступны ручные повторные чтения.
- 403/404/409/422 отображаются структурированным безопасным сообщением;
  raw серверные ошибки и credentials не выводятся в уведомления.
- Таймаут, потеря ответа или неподходящий receipt означают **неизвестный результат**.
  Автоматический повтор записи запрещён. В истории сначала требуется явное
  «Обновить состояние», затем новое подтверждение. Это чтение не переигрывает запись.
- После неизвестного допуска Run нужно открыть обычный журнал `/tasks` и проверить
  существующие задачи перед новым запуском. Targeted `script_id` URL-filter
  на этой странице пока не поддержан и не изображается рабочим.
- Открытый диалог привязан к организации, оператору, роли и версии сессии.
  Смена сессии удаляет прежний диалог; его поздний ответ не показывает успех
  новому оператору. Выбор другой версии отменяет незавершённое чтение.
- Метаданные открытого диалога перечитываются раз в 15 секунд только в активной
  вкладке. Неизменяемые DAG кэшируются по полному script/version/session scope.

## Границы доказательств

Source/test/API/build acceptance описана в [отчёте](../audits/2026-10-02/SCRIPT-VERSION-WORKFLOW.md).
Визуальная проверка и доступность с клавиатуры в настоящем браузере этой ревизии
остаются открытыми: `OPEN_URL_POLICY_BLOCKED`. JSDOM/compiled CSS не заменяют её.
История пока возвращает все метаданные; большой объём версий требует отдельной
проверки производительности и дальнейшей пагинации. Не заявляются production
rollout всего веба, новые Android execution/FPS/latency proofs, массовая OTA
или завершение исходных F28/F32/F33.
