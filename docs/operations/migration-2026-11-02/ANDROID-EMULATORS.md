# Android-эмуляторы: отдельная копия перед переустановкой

GitHub, APK и база Sphere **не содержат** виртуальные диски эмуляторов. В них
могут находиться Android-приложения, токены агентов, игровые данные и локальная
идентичность. По локальному снимку 2 ноября обнаружен один зарегистрированный
работающий LDPlayer; каталог `C:\LDPlayer\LDPlayer9\vms` занимает около
24,54 GiB логически. Стандартный каталог `.android\avd` занимает около
18,46 GiB. Число директорий vms не означает число зарегистрированных машин.
Размеры не равны проверенной резервной копии; они могли измениться.

**Экспорт ещё не выполнен.** Требуется внешний накопитель на другом физическом
диске с достаточным свободным местом, шифрованием и дополнительной независимой
копией. Оцените не менее суммы исходных данных + 10% + 5 GiB; при включении
дополнительной сырой копии LDPlayer `vms` потребуется ещё столько же места, как
для этого каталога. Реальный `.ldbk` может иметь другой размер. Виртуальные
диски нельзя безопасно считать согласованными во время работы гостя.

Из корня checkout в PowerShell посмотрите план:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\migration\export-android-emulators.ps1 -IncludeAvd
```

Самостоятельно корректно завершите работу всех экземпляров LDPlayer и Android
эмулятора; при `-IncludeAvd` закройте также Android Studio. Скрипт ничего не
останавливает и не копирует работающие машины. Для нового каталога на внешнем
NTFS/ReFS диске после закрытия выполните, заменив путь на настоящий:

Учтите задание `Sphere-LDPlayer-pilot-20260911` и другие watchdog: на время
финального окна резервирования они не должны автоматически запускать закрытые
VM. Текущее задание и его конфигурация сохранены отдельно в host snapshot;
экспортёр сам не меняет и не останавливает задания Windows.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\migration\export-android-emulators.ps1 -Export -IncludeAvd -Destination 'E:\Sphere-backups\android-emulators-20261102'
```

Родительская папка должна уже существовать; сама конечная папка обязана не
существовать. Скрипт отказывается от того же номера диска Windows, ссылок в пути,
запущенных процессов и недостаточного места; он экспортирует каждый экземпляр
из `list2` через `ldconsole backup --index ... --file ...ldbk`, копирует AVD
пофайлово и сохраняет размеры и SHA-256. Для дополнительной **сырой копии всего
каталога** `vms`, включая потенциально не зарегистрированные директории,
добавьте `-IncludeRawLdVms`. Это требует дополнительного места. Разные номера
дисков Windows не доказывают разные физические носители для Storage Spaces,
RAID и виртуальных дисков; проверьте это отдельно. Нельзя запускать
эмуляторы во время всего экспорта и вычисления хэшей; проверки процессов не
представляют собой эксклюзивную блокировку запуска другим приложением.

Экспортный каталог и manifest содержат имена экземпляров и персональные данные;
не отправляйте его в публичный GitHub. ACL ограничивается текущим пользователем,
но ACL не заменяет шифрование. Ранее сохранённые Windows-ключи, в том числе
`.android` ADB keys и Android signing/debug keystores, требуют отдельной закрытой
копии; восстановите их безопасным способом с учётом Windows SID и ограничений
шифрования профиля. Существование файла и совпадение SHA подтверждают копирование,
но не пригодность гостевой системы и всех её токенов к переносу.

После установки Windows сначала установите совместимую версию LDPlayer и проверьте
копию и хэши на другом носителе. Создайте **новый пустой** экземпляр через
multi-instance manager, зафиксируйте его новый индекс и убедитесь, что он не
используется; затем вручную укажите именно новый индекс и файл:

```powershell
& 'C:\LDPlayer\LDPlayer9\ldconsole.exe' list2
& 'C:\LDPlayer\LDPlayer9\ldconsole.exe' restore --index <НОВЫЙ_ПУСТОЙ_ИНДЕКС> --file 'E:\Sphere-backups\android-emulators-20261102\ldplayer-index-0.ldbk'
```

`restore` перезаписывает выбранный экземпляр; не направляйте команду на уже
существующую нужную машину. Повторите для остальных файлов и сравните приложение,
данные и идентичность внутри гостя до подключения к действующей Sphere. Сырую
копию `vms` рассматривайте как резерв для отдельной проверки совместимости
версии/пути, а не как гарантированно переносимый импорт.

Для AVD отдельно восстановите Android SDK и соответствующие system images,
проверьте `*.ini`, абсолютные пути и фактические `-datadir`/`-data`: нестандартно
расположенные данные не покрываются стандартной папкой. На новом хосте
восстанавливайте в отдельное место без перезаписи имеющихся AVD, затем проверяйте
загрузку и приложения. Подробнее: [LDPlayer: backup и restore](https://jp.ldplayer.net/support/ldconsole-command-line-guide.html),
[расположение и данные AVD](https://developer.android.com/studio/run/emulator-commandline).
