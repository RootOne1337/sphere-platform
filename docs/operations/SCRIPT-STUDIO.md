## Каталог сценариев

Откройте **Сценарии**. Поиск выполняется на сервере по всему каталогу, а не только
по загруженной странице. Вкладки **Активные**, **Архив**, **Все сценарии** меняют
выборку. Сводка показывает общее число сценариев в выбранной выборке и число
опубликованных сценариев **на текущей странице**: это разные значения.
Первый запрос каталога читает метаданные без DAG; при ошибке или недоступной паре
version/hash/node_count список не подменяется пустым успехом или legacy-загрузкой.

В **Настроить каталог** выберите обычную или компактную плотность, 25/50/100
сценариев на странице и нужную детализацию: описание, хеш версии, идентификаторы,
дату создания. Переключатель вида выбирает список или карточки. Эти настройки
сохраняются в браузере отдельно для организации и пользователя; DAG и приватный
исходник в эту настройку не записываются. Это локальная настройка браузера,
а не синхронизация предпочтений между компьютерами. Поиск, текущая страница и
вкладка состояния в этот сохраняемый набор не входят. При отказе localStorage
на запись изменения действуют только в памяти страницы; интерфейс сообщает
об этом. Ошибка чтения, повреждённая запись или JSON длиннее **4096 символов**
возвращают настройки по умолчанию. Этот предел проверяется по длине строки,
а не по байтам произвольного Unicode-текста.

Действия сценария:

- **Открыть** — редактор текущей версии активного сценария.
- **Посмотреть DAG** — отдельное чтение исходника выбранной опубликованной версии
  без запуска. Версия, полный хеш, дата и число узлов сверяются с receipt строки;
  новая публикация не подменяет открытую панель. Без версии кнопка недоступна. Панель
  просмотра маскирует чувствительные поля; для работы с полным исходником
  используйте редактор и его экспорт.
- **История и управление** — версии, сравнение, откат и архивирование.
  Изменения требуют права записи и актуальной базовой версии; подробный порядок
  описан в [инструкции по версиям](SCRIPT-VERSIONS.md).
- **Запустить** — отдельный диалог выбора целей и запуска опубликованной версии.
  Для первой проверки предпочитайте лабораторию одного устройства в редакторе.
- **Новый сценарий** — новый документ с началом и завершением, без команд Android.

## Создание и редактирование

1. Откройте **Новый сценарий** либо **Открыть** у существующего сценария.
   Укажите название длиной 1–255 символов. Если загрузка существующего сценария
   завершилась ошибкой, сначала нажмите **Повторить загрузку**: пустой шаблон
   вместо недоступной версии не становится редактируемым документом.
2. Найдите действие в библиотеке слева. Можно искать по русскому названию или
   имени типа API. Добавление вставляет шаг после выбранного линейного шага
   либо перед существующим завершением. Оно **не выполняет** действие Android.
3. Выберите шаг на графе. В **Параметры** справа настройте действие, переходы,
   число повторов и таймаут; нажмите **Применить параметры**. До применения или
   отмены редактирования нельзя выбрать другой шаг, сохранить или проверить
   этот документ. ID шага в этой форме менять нельзя.
4. При необходимости откройте **JSON шага** для сложных структур или **JSON**
   целого сценария для полного исходника. Импорт принимает `.json` до 512 KiB.
   Неверный исходник остаётся для исправления; сохранение не подменяет его
   прежним скрытым графом. Возврат в **Граф** требует валидной структуры.
5. В **Настройки сценария** задайте описание DAG и таймаут всего сценария
   от 1000 до 86400000 мс. Здесь также видны входной шаг, базовая версия и хеш.
   Переименование ID со всеми входящими ссылками выполняйте в полном JSON.
6. Нажмите **Проверить на сервере**, затем **Создать сценарий** или
   **Сохранить версию**. Что подтверждает каждая операция, описано ниже.
7. После сохранения найдите сценарий в каталоге и снова откройте его для
   проверки опубликованной версии на конкретном Android.

В библиотеке **32 типа действий**, разделённые на четыре группы:

| Группа | Типы API |
| --- | --- |
| Управление экраном | `tap`, `swipe`, `long_press`, `double_tap`, `scroll`, `key_event`, `type_text`, `input_clear` |
| Элементы и проверки | `find_element`, `tap_element`, `find_first_element`, `tap_first_visible`, `get_element_text`, `wait_for_element_gone`, `scroll_to`, `assert` |
| Логика и данные | `sleep`, `condition`, `set_variable`, `get_variable`, `increment_variable`, `lua`, `start`, `end` |
| Приложения и система | `launch_app`, `stop_app`, `clear_app_data`, `screenshot`, `shell`, `http_request`, `open_url`, `get_device_info` |

Значения нового шага служат отправной точкой: координаты, пакет, селектор,
текст и HTTP-адрес нужно заменить под задачу. Наличие действия в библиотеке
не подтверждает его поддержку любой установленной версией APK. `shell`, Lua,
HTTP-запросы, ввод и очистка данных могут менять состояние; `retry` способен
повторить побочные эффекты. Сначала используйте отдельное тестовое устройство.

## Граф и параметры

Каждый шаг, включая начало и завершение, показан прямоугольной карточкой
шириной **256 px** с названием, типом действия, краткими параметрами и выходами.
По умолчанию схема идёт **сверху вниз** (`DOWN`). Переключатель **Направление
схемы** также предлагает **слева направо** (`RIGHT`). У линейного шага есть
выходы успеха и ошибки; у условия — **Да**, **Нет**, **Ошибка** с явными
идентификаторами `true_branch`, `false_branch`, `failure`. Перемена направления
не меняет эти маршруты, действия и хеш исполняемого DAG.

Переходы можно редактировать в форме или соединениями графа. Один выход ведёт
к одному шагу. Для смены уже соединённого выхода сначала удалите прежнюю связь.
В установленном frontend линия открывает **Откуда / Когда / Куда / Разорвать связь**;
конец переносится мышью, шаги при разрыве сохраняются. Эти операции доступны
только с правом записи и без неприменённых параметров. Editor в лаборатории
не закрывает живое устройство. При разорванном неполном маршруте публикация
по-прежнему блокируется; Undo восстанавливает JSON.
Новое условие сохраняет достижимость прежнего продолжения через обе ветви;
далее настройте каждую ветвь явно. Поллинг-циклы допустимы и ограничиваются
таймаутом сценария. Неразрешённые ссылки и недостижимые шаги блокируют публикацию.
Лимит графа — **500 шагов**.

**Упорядочить** запускает ELK в локальном worker, обслуживаемом приложением.
Worker получает выбранное направление и завершается после успеха, ошибки,
отмены или истечения бюджета **10 секунд**. При ошибке существующий граф
сохраняется. Начальная раскладка также учитывает маршруты и циклы. **Весь граф**,
масштабирование и перемещение помогают осмотреть схему. Позиции и направление
canvas временные: они не входят в DAG, серверные версии и локальный черновик.

Структурированные формы показывают поля текущего типа действия. Стратегии
поиска — `xpath`, `id`, `text`, `desc`, `class`; `desc` означает content-desc.
Импортированные дополнительные поля внутри `action`, неизвестные значения
и точные JSON-типы параметров сохраняются при несвязанном редактировании формы.
Отображаемые шаблонные значения не записываются автоматически: изменение поля
и применение параметров явные.
Массивы, сложные карты и дополнительный код доступны через **JSON шага**.
Графовая модель переносит стандартные поля DAG и шага, а пропущенные `retry`
и `timeout_ms` заполняет значениями по умолчанию. Если импорт содержит другие
поля на уровне всего DAG или самого шага, после графового редактирования
проверьте экспортированный JSON; их сохранение графом не гарантируется.

Поля проверки зависят от текущего `check`, включая импортированные сценарии:

| Действие | Поддержанные варианты `check` в форме |
| --- | --- |
| `condition` | `element_exists`, `text_contains`, `battery_above` |
| `assert` | `element_exists`, `element_gone`, `text_equals`, `text_contains`, `variable_equals`, `variable_contains`, `http_status` |

У `assert.text_equals` и `assert.text_contains` ожидаемый текст находится в
`params.value`, у `condition.text_contains` — в `params.text`. Переменные
используют `params.key`/`params.value`; HTTP-проверка — `params.node_id` и
числовой `params.value`. При явной смене `check` форма заменяет набор `params`
шаблоном нового варианта: проверьте значения до применения. Дополнительные
конструкции, например код условия, редактируются в JSON; форма не обещает
полную проверку их поведения на APK.

## Проверка структуры и сохранение

**Проверить на сервере** обращается к `/scripts/validate` без создания версии
или задания. Ответ содержит SHA-256, число шагов и область проверки
`structure-routes-lua-safety`: структуру DAG, маршруты/достижимость и ограничения
Lua. Это **не проверка исполнения на Android**, не подтверждение наличия
элементов, root-доступа или всех runtime-параметров. После изменения документа
прежний результат проверки перестаёт относиться к текущему исходнику.

Сохранение нового сценария использует `POST /scripts`; изменение существующего —
`PUT /scripts/{id}` с `expected_current_version_id`. Конфликт 409 означает, что
базовая версия изменилась либо сценарий больше нельзя изменять. Исходник остаётся
в редакторе: экспортируйте его, прочитайте актуальную версию из каталога и
согласуйте изменения вручную. Автоматического объединения и повтора нет.

Если после отправки сохранения связь потеряна или результат неизвестен, сервер
мог уже принять запрос. **Повтор сохранения блокируется в текущем редакторе**.
Экспортируйте исходник и проверьте каталог/историю версий перед новым сохранением.
Определённый отказ API 4xx позволяет исправить причину и повторить действие явно.

Блокировка неизвестного результата хранится **только пока смонтирован этот
редактор**, а не в долговечном журнале идемпотентности. Перезагрузка, закрытие
страницы или смена сессии могут её сбросить; они не доказывают, что запрос
не выполнился. Для нового сценария повторный POST после потерянного ответа может
создать дубликат. Сначала сверяйте фактическое состояние сервера.

## Лаборатория одного устройства

Откройте **Устройство · запись · проверка**, найдите конкретный Android и
выберите его. Выбор доступен для устройств со статусом `online` или `busy`;
статус сам по себе не гарантирует root-доступ и успешное выполнение команды.
Лаборатория использует существующий H.264-поток и инструменты управления,
XPath-инспектор и исходный снимок для одного устройства. Это реальное
устройство: обычные клики и ввод меняют его состояние.
Правила управления описаны в [навигации Android](ANDROID-NAVIGATION.md) и
[работе по статичному кадру](STATIC-STREAM-INPUT.md).

### Добавление XPath

1. Включите **XPath-инспектор** после получения видеокадра.
2. Нажмите элемент на изображении либо выберите его в дереве справа.
   Это выбор для инспекции, а не нажатие на Android. Инспектор показывает
   возвращённые атрибуты и границы, если Android их предоставил.
3. Убедитесь, что дерево относится к выбранному устройству, текущей сессии
   и геометрии видео. При ошибке, повороте или устаревшем дереве обновите его.
4. Нажмите **Добавить элемент в сценарий**: в граф вставляется `tap_element`
   с XPath, стратегией `xpath` и `timeout_ms: 5000`, без исполнения этого шага.

Дерево получается через существующие root-команды APK и `uiautomator dump`;
отдельный сервис UIAutomator2 в этом пути не используется. Инспектор не обещает
доступ ко всем внутренним объектам приложения: игровой Canvas может раскрыть
только поверхность. Снимок пригоден в течение **30 секунд с начала запроса**,
а не с получения ответа. Автообновление запускается через **5 секунд после
ответа**, только в видимом активном инспекторе; ошибка приостанавливает его.
Бюджет запроса — до 50 секунд, поэтому долго шедший ответ может сразу оказаться
устаревшим. Выбор устройства, смена токена, потеря права или соединения отменяют
прежнее чтение. Видео и дерево независимы; одинаковые координаты не гарантируют,
что интерфейс приложения остался тем же между двумя снимками.

### Запись действий

1. Нажмите **Записать действия** и выполните необходимые действия над видео
   или через панель навигации Android.
2. Нажмите **Остановить запись**. Просмотрите полученную последовательность.
3. Оставьте **Сохранять паузы между действиями** включённым либо отключите его явно.
4. Нажмите **Вставить в граф**. Запись переносится только этим действием;
   при отказе редактора она остаётся в лаборатории для исправления причины.

Запись содержит до **200 событий в памяти**. Клики, свайпы и колесо имеют
статус **Отправлено WS**: это подтверждение отправки транспорта,
**не ACK исполнения Android**. Панель навигации записывает системные и
редакторские клавиши и поддержанный текст через установленный HTTP/SHELL
контракт. Они проходят состояния **Ожидает APK**, **Подтверждено APK** или
**Результат неизвестен**. Только подтверждённые key/text команды переносятся
в исполняемый граф. Неподтверждённое действие нельзя молча пропустить или
повторить: после остановки записи проверьте экран и явно удалите его из списка.
Во время ожидания команды нельзя закрыть устройство, очистить запись,
перенести её или запустить проверку сценария. Остановка самой записи допустима;
поздний ответ обновит исходную строку, а не добавит новую.
Это не полный recorder всех действий эмулятора: внешние ADB/скриптовые действия
и физическая клавиатура за пределами панели не перехватываются.
XPath во время записи автоматически не строится: нужный элемент выбирается
в актуальном инспекторе и добавляется отдельной кнопкой.

Координаты кадра переводятся в опорные координаты APK: **1280×720** для
горизонтальной и **720×1280** для вертикальной ориентации. Время предыдущего
свайпа вычитается из межсобытийной паузы; для key/text вычитается ожидание
уже подтверждённого результата. HTTP round-trip не становится дополнительным
`sleep` поверх исполняемого шага. Отдельное ожидание ограничено 60 с.
Паузы добавляют шаги, поэтому запись из 200 действий может потребовать больше
200 узлов; общий лимит графа остаётся 500. Изменение ориентации или компоновки
может изменить смысл координат. Для устойчивых целей используйте XPath.

Невставленная запись не является серверным сценарием или локальным черновиком.
Смена устройства и закрытие лаборатории предупреждают о её потере. Перед уходом
перенесите её в граф и сохраните либо экспортируйте исходник.

Текст в списке показан числом символов; сам текст попадёт в `type_text.text`
при вставке. `clear_first` всегда `false`: запись добавляет только выполненный
ввод, а не непроверенную очистку поля. До вставки запись не сохраняется в
localStorage или серверной версии и уничтожается при смене auth session.
После вставки исходник может содержать приватный текст и попасть в явно
включённый локальный черновик/экспорт; не записывайте пароли.
Ввод ограничен поддержанным установленным каналом ASCII, 1024 символа.
Кириллица/emoji/переносы строк и запрещённые shell-символы не отправляются.
Копировать/вырезать/вставить записывают keycode, а не содержимое буфера:
повтор зависит от выделения, поля и буфера Android. Буфер браузера отдельный.
[Контракт и доказательства этапа](../audits/2026-10-06/STUDIO-COMMAND-RECORDING.md).

`input_clear` и `type_text.clear_first:true` требуют отдельного внимания к версии
агента. В source **1.2.46 / 10246** исправлена ошибочная очистка через CUT 277:
root chord Ctrl+A/Delete выполняется в прежней очереди и ждёт ограниченный ACK.
Unknown outcome прекращает цепочку без повтора и ввода замены. ACK не доказывает
состояние произвольного поля: `field_verified=false` сохраняется в output.
Candidate собран и helper проверен на одном Android9; **APK ещё не установлен**.
Старые 1.2.44/1.2.45 не меняются при обновлении веба. Полный installed-agent canary,
другие SDK/IME/editors и адресная доставка остаются отдельной проверкой.
[Source contract, два debug suites и native PNG](../audits/2026-10-06/ANDROID-FOCUSED-TEXT-CLEAR.md).

### Проверка сохранённой версии

**Проверить на [имя устройства]** доступно для сохранённой неизменённой версии
с известным хешем и правом запуска. Сначала лаборатория показывает
**«Освобождаем Android…»**: новое управление/чтение блокируется, текущий native
owner ждёт подтверждённого release, текущие XPath/PNG-запросы завершаются.
Максимум подготовки55с; истечение срока или прерванный HTTP не доказывают,
что Android закончил работу. Ошибка подготовки сообщает **«Задание не создано»**:
после исправления причины можно повторить явно. При неизвестном release или
незавершённом чтении новый input/задание не отправляется.

После готовности именно этого запуска и повторной проверки версии/прав/сессии
кнопка создаёт **одно реальное задание** через `/tasks` на выбранном Android,
закреплённое за базовым ID версии. Это handoff текущей лаборатории; исключение
ручного ввода другого оператора/вкладки ещё не является подтверждённым global lease.
Запрос передаёт этот ID как `expected_current_version_id`; если текущая версия
на сервере уже изменилась, заново откройте сценарий перед проверкой.
Для нескольких целей используйте отдельный диалог **Запустить версию** и
проверьте список целей перед отправкой. Библиотека действий и проверка структуры
сами по себе не запускают Android.

Во время отправки, активного задания или неподтверждённой принадлежности
результата ручное управление блокируется. Над видео указана временная причина
блокировки, отличная от отсутствия права управления. **Остановить задание**
отправляет отдельную команду; проверяйте реальный статус, поскольку отправка
запроса остановки не равна завершению задания.

Во время подготовки и пока запрос создания задания ожидает ответ, лабораторию нельзя закрыть или
сменить её устройство: сначала дождитесь подтверждённого ID задания либо
сообщения о неопределённом результате. После подтверждения известного активного
задания закрытие требует отдельного подтверждения; оно не отменяет само задание.
Откройте его детали по ID, чтобы проверить итоговый статус, отчёты шагов,
параметры и снимки. Завершённая карточка использует итоговые значения сервера;
длительность фиксируется по `finished_at`. Полученные отчёты не доказывают
прохождение всех возможных ветвей DAG.

Если ответ создания задания потерян или не подтверждает выбранные устройство,
сценарий и версию, повтор, управление и смена/закрытие устройства в лаборатории
блокируются; откройте журнал заданий и выясните результат. Определённый отказ
API 4xx можно исправить и повторить вручную. Автоматического повторного запуска
нет. Блокировка живёт в текущем экземпляре лаборатории; уход через другие ссылки,
перезагрузка или новая сессия не обеспечивают долговечную идемпотентность.
Перед повтором найдите уже созданное задание и проверьте его итог.

Граф подсвечивает **последний обработанный шаг**, сообщённый APK, и реальные
отчёты шагов с успехом/ошибкой. Прогресс активного задания опрашивается каждые
**2 секунды**, статус и журнал — каждые **5 секунд**. После завершения сводка
показывает число полученных отчётов, а не устаревшее отношение промежуточного
прогресса и не утверждение об исполнении всех ветвей DAG. Повторы и циклы могут
давать несколько отчётов одного шага. По ID можно открыть карточку задания.

Видео, дерево Android и прогресс не имеют общего идентификатора кадра.
Покадрово точное воспроизведение и нулевая задержка не реализованы; подсветка
не является искусственным таймером или доказательством соответствия конкретному
видеокадру. Для оценки проверяйте итог задания, отчёты APK и наблюдаемое
состояние устройства вместе.

## Черновики, история и уход из редактора

Undo/redo хранит до **20 документов** и до **2 MiB на каждый стек**. Undo
открывает восстановленный исходник в JSON; переход в **Граф** применяет его.
До применения или явной отмены параметров выбранного шага Undo/redo недоступны:
неприменённые поля ещё не являются документом в стеке истории.
Выделение, перемещение узлов и раскладка не создают исполняемых версий.

Сохранение полного черновика на ПК **выключено по умолчанию**. В настройках
сценария его можно включить: запись выполняется после паузы 700 мс. Сохраняется
один документ на пару организация/пользователь; другой сценарий может заменить
его. Лимиты — 512 KiB исходника и 528 KiB закодированного конверта. Восстановление
предлагается явно, до 7 дней и только для того же сценария или нового документа.
Оно не делает серверную запись. Черновик может содержать приватный текст,
заголовки и код: на общем ПК используйте экспорт и осознанно выбирайте эту опцию.
**Очистить локальный черновик** удаляет только соответствующий ключ.

Неприменённые параметры узла и невставленная запись действий не входят в общий черновик.
Сначала примените параметры и вставьте запись либо сохраните их отдельно.
Ошибки localStorage показываются; серверное сохранение и экспорт от него
не зависят.

Кнопка возврата к каталогу проверяет контекст лаборатории и несохранённые
изменения документа. Сохранение также проверяет guard лаборатории, поскольку
успешная операция возвращает в каталог. Закрытие вкладки использует
`beforeunload` при изменённом документе, невставленной записи, активном/ожидающем
или неизвестном запуске; показ предупреждения зависит от политики браузера.
Обычные ссылки общего sidebar, хлебных крошек и страницы, глобальный поиск и
explicit выход из аккаунта проверяют текущий guard Studio. Отмена сохраняет
редактор; во время проверки/сохранения и неподтверждённой команды переход
блокируется. При несохранённой работе диалог Studio перечисляет причины и
предлагает остаться, скачать JSON и остаться или явно выйти без сохранения.
Escape отменяет переход. Экспорт содержит текущий исходник; неприменённые поля
и невставленная запись в него не входят. Пока окно открыто, sign-out не отзывает
сессию. При подтверждении состояние команд проверяется повторно; ожидающий или
неизвестный запуск остаётся блокирующим. Смена сессии отменяет старый переход.
Журнал для неизвестного запуска и карточка задания открываются
в новой вкладке, сохраняя редактор и запрет повторного запуска. Якоря текущего
документа, download и открытие новой вкладки не уничтожают рабочую область.
Browser Back/Forward внутри SPA, forced auth expiry и произвольная навигация
других компонентов не обеспечены полным route blocker; перед уходом примените,
экспортируйте или сохраните нужное и проверьте незавершённые операции.
[Контракт, source-проверки и границы поставки](../audits/2026-10-07/STUDIO-NAVIGATION-PRESERVATION.md).

## Права, сессия и границы поддержки

Чтение и структурная проверка требуют `script:read`, запись — `script:write`,
запуск — `script:execute`. Управление видео требует `stream:control`, чтение
дерева и исходного снимка — `device:write`. UI скрывает или блокирует действие,
если соответствующее право не подтверждено; сервер выполняет собственные проверки.

Редактор изолирован по организации, пользователю, версии сессии и ID сценария.
Смена этого контекста пересоздаёт редактор, отменяет принадлежащие ему запросы;
поздний ответ прежнего редактора не меняет документ новой сессии. Лаборатория
применяет прогресс только к своему устройству, сценарию и закреплённой версии.

Каталог типов не является версионированной схемой возможностей APK. Полная
проверка всех runtime-параметров, root/разрешений, селекторов и поведения версии
агента требует живого canary на конкретном устройстве. Успешный `/metrics`,
наличие видеокадра, структурная проверка или наличие XPath не заменяют этот тест.

## Библиотеки и лицензии

Схема использует существующую **React Flow** (`@xyflow/react`, MIT, авторы xyflow)
и оригинальные узлы Sphere. Видимая attribution React Flow сохраняется.
Автоматическая раскладка добавляет зависимость **elkjs 0.12.0**, авторы Eclipse
Layout Kernel / Kiel University; используется предложенная лицензия **EPL-2.0**.
Worker не изменён, алгоритм остаётся отдельно от UI Sphere.

Скрипт [prepare-elk-worker.mjs](../../frontend/scripts/prepare-elk-worker.mjs)
копирует worker и полный текст лицензии из зафиксированного npm-пакета перед
`npm run dev` и `npm run build` в `/vendor/elk/worker-0.12.0.js` и
`/vendor/elk/LICENSE.md`. Внешний CDN для раскладки не нужен. При прямом запуске
Next, обходящем npm prehook, подготовьте эти ресурсы тем же скриптом.
Платные React Flow Pro templates и сторонние коммерческие конструкторы
в эту реализацию не включены.

Источники, авторство и тексты лицензий сохранены в
[THIRD-PARTY-NOTICES](../design/previews/admincn-sphere-2026-09-28/THIRD-PARTY-NOTICES.md).
