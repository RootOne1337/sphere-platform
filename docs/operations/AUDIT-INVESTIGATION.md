## Расследование по всей организации

GET `/api/v1/audit/logs` и GET `/api/v1/audit/logs/export` требуют `audit:read`.
Разрешение проверяется реальной зависимостью авторизации; `org_id` берётся из
аутентифицированного пользователя. Даже super_admin получает журнал своей
организации. Передать другой tenant через параметры нельзя. Матрица RBAC выдаёт
`audit:read` ролям `org_admin`, `org_owner` и `super_admin`; фактический доступ
проверяется сервером. RLS — дополнительная защита при корректных миграциях,
tenant context и runtime-роли без обхода RLS; состояние конкретной установки
здесь не проверялось. Это не межорганизационный поиск.

Оба endpoint используют [один построитель условий](../../backend/services/audit_query.py)
и [одну валидацию](../../backend/schemas/audit.py):

| Параметр | Семантика |
| --- | --- |
| `q` | До 500 символов, 20 разделённых пробелами условий; все объединяются через AND |
| `status` | SUCCESS / FAILED / WARNING / UNKNOWN; нормализация только `meta.status` |
| `action` | Буквальная подстрока без учёта регистра, до 255 символов |
| `resource_type` | Точное совпадение, до 100 символов |
| `user_id` | Полный UUID пользователя; отсутствие пользователя ищется `user:system` |
| `from`, `to` | Включительные границы; ISO timestamp с обязательным UTC offset |
| `page`, `per_page` | Только список; page ≥ 1, per_page 1–100 |
| `limit` | Только экспорт; 1–5000, по умолчанию 5000 |

В `q` поддерживаются `status:FAILED`, `action:put.groups`, `user:system` и
`user:<подстрока UUID>`. Остальные слова ищутся в фиксированном наборе scalar
полей: UUID события/пользователя, время в текстовом представлении БД, action,
resource_type/resource_id и IP. Произвольные `meta`, old_value/new_value не
просматриваются. Поиск email не реализован: audit хранит UUID, а не email.
`%` и `_` — буквальные символы, а не SQL wildcard. Неизвестный префикс остаётся
буквальным текстом; некорректный известный structured term возвращает 422.

Порядок: `created_at DESC, id DESC`, включая одинаковые timestamps. У списка
count и page — отдельные SELECT в живом журнале: новые INSERT могут изменить
total между ними или сдвинуть offset следующей страницы. Это не snapshot paging.
Карточки результатов SUCCESS/FAILED/WARNING/UNKNOWN подписаны как сводка
загруженной страницы; total соответствует применённым серверным фильтрам.

## CSV: ограничение и состав

Экспорт независимо от открытой страницы выполняет один SELECT, проецирует только
scalar поля, получает `limit+1` строк и сериализует первые `limit`. Таким образом,
первая страница не задаёт полноту CSV. У файла нет обхода offset страниц во время
конкурентных INSERT и нет фоновой неограниченной выгрузки.

По [официальному описанию PostgreSQL Read Committed](https://www.postgresql.org/docs/current/transaction-iso.html#XACT-READ-COMMITTED),
один SELECT видит согласованный statement snapshot. Этот принцип применён здесь;
он не обещает одинаковый snapshot для последующего экспорта или списка.
`X-Audit-Observed-At` — время подготовки ответа после чтения, не timestamp
начала PostgreSQL snapshot и не distributed trace времени исполнения.

CSV UTF-8 с BOM, разделитель `;`, CRLF, все ячейки quoted. Столбцы: время UTC,
нормализованный результат, action, user UUID/system, ресурс, IP и ID события.
Произвольные payloads/meta и user_agent не включаются. Начальные `=`, `+`, `-`, `@`
после начальных символов, которые Python `str.lstrip()` считает пробельными,
нейтрализуются апострофом. Это не гарантия обработки всех управляющих символов
и всех способов интерпретации формул табличными программами. Ответ `no-store`,
`nosniff`, с фиксированным безопасным filename.

| Заголовок | Значение |
| --- | --- |
| `X-Audit-Rows` | Число строк событий в файле, без заголовка CSV |
| `X-Audit-Limit` | Применённый cap |
| `X-Audit-Truncated` | `true`, если существуют другие подходящие строки |
| `X-Audit-Observed-At` | Время подготовки UTC |

**При truncation остальные события не включены.** UI явно сообщает об этом.
Автоматического продолжения/cursor нет: сузьте диапазон времени или фильтры и
повторите выгрузку. Пакеты пересекающихся диапазонов нельзя объявлять уникальным
полным архивом; ID события позволяет отдельно устранить дубликаты. Неограниченный
архив, retention job и подписанный chain of custody этим изменением не реализованы.

## Поведение интерфейса

Форма хранит черновик отдельно от применённых фильтров. Нажатие «Применить»
проверяет UUID/диапазон/DSL, возвращает page1, закрывает старый инспектор и
отменяет предыдущий экспорт. Ввод времени явно **UTC**, включая секунды и
миллисекунды native input; часовой пояс ПК не меняет передаваемый timestamp.
Даты строк форматируются в часовом поясе браузера.

**Фильтры** раскрывает поля формы, а **Сбросить** очищает и черновик, и
применённые условия. **Обновить** повторно читает список; при ошибке доступна
кнопка **Повторить запрос**, а ошибка не означает, что событий нет. Интерфейс
запрашивает по 100 записей; кнопки страниц отключены во время загрузки и на
границах. Клик по строке, Enter или пробел открывает детали уже полученного
события. Инспектор показывает основные поля и только выбранные метаданные
`status`, `http_status`, `duration_ms`, `request_id`, `trace_id`, если они есть;
он не выполняет операцию повторно и не является полным просмотром payload.

CSV использует применённые условия. Текущий черновик не меняет уже отправленный
запрос. Экспорт единственный, отменяемый; повторный клик не запускает второй.
Кнопка экспорта отключена при загрузке или ошибке списка, отсутствии данных,
нулевом total и во время экспорта; нулевой total — результат конкретного запроса,
а не гарантия отсутствия новых событий впоследствии. HTML/error response, отсутствующие
или некорректные receipt headers, размер больше 16 MiB, отмена/смена session не
превращаются в успешную загрузку. После подтверждённого ответа UI передаёт файл
браузеру: сохранение файла на диск браузером этим сигналом не доказано.

Query key и lifetime формы/инспектора/экспорта привязаны к actor/org/role/session.
Поздний ответ после смены identity игнорируется; уход со страницы отменяет запрос.
Refetch списка каждые 30 секунд только в активной вкладке сохраняется.

## Ограничения приёмки

Поиск literal substrings использует SQL ILIKE, не отдельный полнотекстовый индекс.
Проверки ограничивают число условий/длину и количество возвращаемых строк, но не
доказывают latency на миллионах событий. Большой объём требует отдельного EXPLAIN,
нагрузочного теста и планирования индексов. Фикс не меняет best-effort background
audit writer: потеря события при DB/process crash остаётся отдельным outbox gate.
Свежая визуальная приёмка Sphere, browser download и клавиатурные сценарии в живом
браузере остаются OPEN по ранее полученной URL policy; запрет не обходится.
