# VPN в Web: подключение, профили и инфраструктура

[Каталог](../README.md) · [VPN-профили и API](VPN-PROFILES.md) ·
[Результаты VPN-команд](VPN-CONTROL-OUTCOMES.md) · [Записанное состояние](CURRENT-STATE.md)

Руководство описывает исходный код `/vpn` в исследованной ветке, а не новую
проверку установленного интерфейса или сети. Уточните организацию, полномочия,
версию Web/API и область устройств своей среды. `vpn:read` нужен для чтения;
`vpn:write` — для проверки и сохранения профилей и назначения router peer;
`vpn:mass_operation` — для ротации и legacy kill switch. Перезагрузка устройства
проверяется отдельно через `device:write`. Сервер остаётся источником разрешений;
видимость кнопки и сообщение клиента не подтверждают фактического применения VPN.

По текущей матрице исходников `vpn:read` дан `viewer`, `device_manager` и трём
административным ролям, но не `script_runner`. `vpn:write` и
`vpn:mass_operation` даны `org_admin`, `org_owner` и `super_admin`; те же роли
открывают формы проверки и импорта в UI. Перезагрузка дополнительно доступна
`device_manager` по `device:write`. Фактические разрешения проверяет сервер.

В конфигурациях `.conf` могут быть приватные ключи. Не прикладывайте их к публичным
issues, скриншотам или логам. Если после команды потерян ответ, сначала проверяйте
состояние и сохранённые ID запроса, а не отправляйте новое намерение автоматически.

## Верхние кнопки: проверка и импорт одного профиля

Кнопки **«Проверить профиль»** и **«Импорт .conf»** доступны управляющим ролям
в исходном UI. Обе открывают похожую форму, но имеют разный результат:

1. Выберите файл `.conf` размером до 64 КиБ. Подсказка по структуре предлагает
   WireGuard/AmneziaWG и IPv6; это не итоговая серверная проверка. Для AWG
   укажите версию по данным провайдера.
2. Выберите политику IPv6 и область **«Выбранные приложения»** или **«Все
   приложения, кроме Sphere»**. Для первого режима укажите package ID, исключая
   Sphere; пустой список не принимается. Для второго проверьте ограничения
   устройства и режима в [контракте профилей](VPN-PROFILES.md).
3. В режиме проверки нажмите **«Проверить профиль»**. Сервер возвращает ошибки
   с кодами/строками или вердикт формата; запрос **не сохраняет** профиль и не
   подключает устройство. Успешный разбор не проверяет живой туннель, внешний IP,
   маршрутизацию UID или восстановление после сбоя.
4. В режиме импорта задайте название и при необходимости описание, затем нажмите
   **«Проверить и сохранить»**. При подтверждённой квитанции появляется версия
   сохранённой зашифрованной записи; VPN на устройстве от этого не включается.
   После проверки/попытки сохранения форма освобождает исходный файл: для новой
   проверки его потребуется выбрать заново.

Если сохранение завершилось неопределённо, форма показывает ID и кнопку
**«Проверить статус сохранения»**. Сохраните ID до закрытия и повторяйте проверку
статуса, не импорт. Отсутствие квитанции на данный момент не доказывает отмену
серверной операции. Для новой версии конфликт 409 требует перечитать каталог.

## Вкладка «Подключения»

Здесь читается состояние Android VPN-сервиса из `/vpn/runtime`. Поиск по имени,
выбор группы и страницы ограничивают область списка; **«Обновить»** запрашивает
её повторно. Опрос в исходном UI — каждые 5 секунд. «Устройств по фильтру»
относится к серверному результату; «свежих отчётов» — только к показанной странице.

Строка показывает связь устройства, фазу VPN и свежесть отчёта. Если отчёта нет,
он устарел или API недоступен, текущее состояние не подтверждено. Обновление
heartbeat Sphere само по себе не означает, что пришёл новый VPN-снимок. Диалог
**«Диагностика VPN»** открывает вкладки соединения и идентификаторов: время
снимка/получения, handshake, область приложений, агент, session/profile/request
и причину. **«Открыть устройство»** ведёт в его карточку; **«Готово»** закрывает
диалог.

Эта вкладка предназначена для наблюдения: в текущих подключённых компонентах
нет кнопок запуска, остановки или применения сохранённого профиля к Android VPN.
Смена вкладки, импорт профиля или назначение router peer не являются такими
командами. Старые файлы вкладок в `_tabs/` сами по себе не подтверждают наличие
этих действий на текущей странице.

RX/TX — счётчики всего туннеля, а отображаемая скорость — средняя между двумя
подходящими свежими снимками той же сессии, не мгновенная скорость приложения.
После сброса, смены сессии или отсутствия пары замеров скорость не показывается.
Handshake не подтверждает доступность игры, внешний IP или сохранение изоляции
при всех отказах. Проверяйте эти условия отдельным разрешённым испытанием.

## Вкладка «Профили»

Каталог поддерживает поиск по имени, **«Показывать архив»**, обновление и
переключение страниц по 10 записей. Неуспешное чтение не означает отсутствие профилей; во время
неподтверждённого списка действия с прежним снимком блокируются.

- **«Импорт профиля»** открывает описанную выше форму сохранения одной записи.
- **«Версии»** показывает постраничную историю без ключей. Старые версии не
  перезаписываются. Просмотр истории не возвращает конфигурацию в браузер.
- **«Новая версия»** доступна для активного профиля: выберите новый файл,
  подтвердите ожидаемую текущую revision и сохраните. При конфликте перечитайте
  каталог; новая версия не меняет сеть автоматически.
- **«Архивировать»** открывает подтверждение с именем и ожидаемой revision.
  Архивирование убирает запись из активного каталога и сохраняет историю; оно
  не разрывает уже работающий туннель. При неподтверждённом результате обновите
  каталог и проверьте состояние перед следующим действием.

### Импорт пакета

**«Импорт пакета»** выбирает до 100 отдельных `.conf`: каждый не больше 64 КиБ,
всего до 3 МиБ. ZIP и произвольные списки прокси этой формой не импортируются.
Пакет имеет общую область приложений и версию AWG; WG определяется по файлу,
IPv6 проверяется для каждого файла. Для выбранных приложений укажите 1–64 package ID.

1. Выберите файлы и параметры; нажмите **«Проверить пакет»**. Результаты по
   каждому файлу содержат ошибки и номера строк; **«Только ошибки»** помогает
   их найти. Проверка не сохраняет и не применяет конфигурацию.
2. **«Сохранить профили»** доступно после успешной проверки всех файлов. Сервер
   сохраняет пакет одной транзакцией; это не выдача профилей Android-устройствам.
3. Если результат сохранения неизвестен, раскройте **«ID запросов для
   восстановления результата»**, сохраните их и нажмите **«Проверить статус
   пакета»**. Ненаблюдаемая квитанция не доказывает отмену: повторите именно
   проверку статуса позже. Закрытие окна не гарантирует отмену серверной записи.

При подтверждённом отклонении исправьте причину и заново выберите файлы. Размер
JSON запроса отдельно ограничен 4 МиБ; детали протокола и устойчивого повтора —
в [VPN profiles](VPN-PROFILES.md).

## Вкладка «Инфраструктура»

Это адресный пул и router peers, а не журнал Android VPN. Поиск фильтрует
полученные карточки локально. Карточки показывают назначенный IP, состояние и
время handshake; роутер здесь не предоставляет счётчики трафика peer, координаты
или замеры задержки. Данные пула и peer запрашиваются отдельно: ошибка одного
источника не доказывает состояние другого. Обратите внимание на предупреждение
об ошибке peers: показанные счётчики не следует считать свежим подтверждением.

- **«Назначить peer»** открывает выбор устройства без уже указанного peer и
  отправляет назначение router. Проверенная квитанция содержит device ID, peer ID
  и назначенный адрес. Она не доказывает доставку конфигурации на APK или handshake.
  При неизвестном ответе текущий диалог блокирует повтор, но после его закрытия
  и открытия заново селектор проверяет наличие устройства в полученном списке
  peers, а не отдельно сохранённый `unknown`. Если обновлённый список ещё не
  отражает назначение, повторное нажатие может снова стать доступным. Сначала
  отдельно сверяйте назначение и состояние router; доступная кнопка не доказывает,
  что предыдущая попытка не произошла.
- На карточке **«Логи»** ведут к журналу устройства; **«Перезагрузка»** открывает
  подтверждение и после результата требует отдельной проверки нового heartbeat.
- **«Параметры»** показывает выбранный peer и позволяет подготовить **«Сменить
  адрес»** или **Kill Switch**. Ротация сначала отзывает прежний peer и затем
  назначает новый; при ошибке сеть может остаться без прежнего адреса.
- **«Политики»** открывает состояние пула и кнопки **Kill Switch ON (ALL)** и
  **OFF**. Они формируют цели из назначенных peers, а не только из результатов
  текстового поиска. Перед подтверждением проверьте полный список UUID в диалоге:
  ограничение команды — до 500 уникальных устройств. Не подтверждайте операцию,
  если фактическая область не соответствует намерению.

Диалог операции перечитывает каталог, требует явного подтверждения влияния и
показывает результат отдельно для каждой цели. `configured` описывает изменение
router, `submitted` — принятие отправителем, `not_sent` — явный отказ отправителя принять команду,
`unsupported` — отсутствие совместимого пути, `unknown` — неустановленный исход.
Ни один из них сам по себе не подтверждает выполнение на Android. Интерфейс может
предложить повтор только для `not_sent` после нового подтверждения; для `unknown`
нужна сверка peer и устройства, а не автоматический повтор. Это блокирование
относится к текущей сессии страницы, не является долговечным server journal.

В изученном коде route подключает [EventPublisher](../../backend/services/vpn/event_publisher.py)
с `supports_killswitch = false`; этот legacy путь возвращает `unsupported` без
отправки. Наличие кнопки не доказывает работающий Android kill switch. В отдельном
legacy Android manager вызовы подключения и переподключения ограждены проверкой
провайдера; это не равнозначно приёмке app-scoped реализации. Подробности и
классификация результатов — [VPN control outcomes](VPN-CONTROL-OUTCOMES.md).

## Вкладка «Политика трафика»

Это поясняющая схема предполагаемого разделения трафика приложений и канала
управления Sphere. Здесь нет кнопки применения или проверки пути. Выбор политики
в форме профиля описывает намерение; реальный маршрут, DNS/IPv6, поведение при
отказе и после перезагрузки требуют отдельной проверки конкретного устройства.

Также `GET /api/v1/vpn/health` в исследованном [router](../../backend/api/v1/vpn/router.py)
возвращает статический статус `ok`; он не проверяет живой peer, Android или
внешнюю сеть. Используйте отдельные наблюдения и измерения по цели проверки.
