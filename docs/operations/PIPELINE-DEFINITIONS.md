## Открытие и происхождение данных

На `/orchestration` во вкладке Pipelines нажмите «Определение и управление».
Карточка читает `GET /api/v1/pipelines/{pipeline_id}`; строка каталога не считается
достаточным baseline для записи. Проверяются ID, организация, версия, временные
метки и структура ответа. Ключ запроса включает организацию, пользователя, роль
и поколение сессии. При смене этой области карточка закрывается.

Показаны все поля определения: имя, описание, теги, автор/организация, даты UTC,
активность, версия, общий таймаут, входная схема и каждый шаг с параметрами,
таймаутом, повторами и переходами. Название и JSON переносятся; длинные блоки
ограничены прокруткой. Обзор и подтверждение используют редактирование секретов
для известных имён ключей. Это не классификатор всех произвольных секретов.

Запрос обновляется каждые 15 секунд в активной вкладке. Это периодический снимок,
а не подписка на изменение каждого поля. Ошибка чтения скрывает недостоверный
снимок и запрещает запись. Viewer имеет только просмотр. Запись доступна ролям
device_manager, org_admin, org_owner и super_admin; окончательное разрешение
проверяет backend, а не видимость кнопки.

## Редактирование

1. Дождитесь успешного чтения. Нажмите «Редактировать определение».
2. Измените имя, описание, теги JSON, входную схему JSON, таймаут или шаги JSON.
   Пустое описание явно очищает поле. Неизменённое поле не отправляется в PATCH.
3. Нажмите «Проверить изменения». До этого шага запись не отправляется.
4. Проверьте ID, исходную версию, `updated_at` и перечень изменённых полей.
5. Нажмите «Подтвердить запись». Отправляется PATCH с `expected_updated_at`
   исходного определения. Карточка проверяет ответ, запрошенные значения,
   сохранённые поля и ожидаемый номер версии; HTTP 200 сам по себе недостаточен.

Редактор JSON содержит исходные параметры: доступ предоставляется явным
переходом в редактирование. Не включайте секреты в снимки экрана. Сравнение
перед записью их скрывает для известных ключей.

Черновик не перезаписывается фоновым чтением. Если серверное `updated_at`
изменилось, сохранение блокируется. Есть явное подтверждение отказа от черновика;
автоматическое объединение конфликтующих определений не выполняется. Закрытие
грязной формы тоже требует решения о черновике.

## Включение и выключение

Кнопка в каталоге сначала загружает полное определение и открывает подтверждение.
Она отправляет желаемое состояние, а не команду «инвертировать что-нибудь»:

```http
POST /api/v1/pipelines/{id}/toggle?active=false&expected_updated_at=2026-10-03T00%3A00%3A00Z
```

`active` обязателен. Отключение запрещает новые запуски, но не отменяет queued,
running, waiting или paused задания. Для остановки используется отдельный
workflow управления запуском. Повтор установки уже имеющегося значения не
выделяет новую версию и не меняет timestamp без изменения состояния.

DELETE этого ресурса исторически означает мягкую деактивацию, а не уничтожение
определения. Он поддерживает тот же optional timestamp condition. Карточка
использует явное включение/выключение, не предлагает ложное физическое удаление.

## Проверки определения и границы совместимости

| Поле / правило | Контракт |
| --- | --- |
| Имя | 1–255 символов |
| Шаги | 1–100; ID уникальны, длина 1–128 |
| Тип шага | execute_script, condition, action, delay, parallel, wait_for_event, n8n_workflow, loop, sub_pipeline |
| Переходы | Существующий ID шага или null; циклы допускаются |
| Таймаут шага | 1000–3600000 мс |
| Повторы шага | 0–10 |
| Общий таймаут | 10000–259200000 мс |
| Теги | До 20 строк |
| PATCH null | Допустим для очистки description; прочие изменяемые поля нужно опустить для сохранения значения |
| Версия | Увеличивается только при фактическом изменении steps; идентичный массив не выделяет версию |
| Неизвестные поля PATCH | 422, вместо молчаливого игнорирования |

HTTP API проверяет базовую структуру/типы и связи. Он не доказывает семантическую
правильность `params` каждого обработчика, доступность referenced scripts,
интеграций или устройств. Это отдельная проверка конкретного исполнения.

`input_schema` хранится как описание и сейчас **не валидирует** `input_params`
при запуске. Общий `max_retries` хранится в шаблоне, но executor не реализует по
нему повтор всей цепочки; рабочие повторы берутся из каждого шага. Карточка
показывает это ограничение и не предлагает настройку общего повтора как работающую
функцию. Старые определения с неверными шагами можно просмотреть; исправление
должно пройти новый контракт.

## Действующие запуски и конкуренция

Снимок шагов сохраняется в `PipelineRun.steps_snapshot`. Однако recovery worker
пока читает общий таймаут из шаблона. Поэтому изменение steps, input_schema,
global_timeout_ms или max_retries при наличии любого queued/running/waiting/paused
запуска отклоняется целиком с 409. Даже сопутствующее изменение имени не будет
частично сохранено. Metadata-only edit и деактивация допустимы и не меняют запуск.

Доступ к определению сериализуется до commit: writers берут PostgreSQL
`FOR UPDATE NOWAIT`, admission одиночного/массового запуска — `FOR SHARE NOWAIT`.
Конкурирующая запись/допуск получает 409. ORM identity перечитывается под
блокировкой. Tenant predicate и non-owner RLS сохраняются.

`expected_updated_at` остаётся optional для совместимости старых API-клиентов.
Новый веб всегда отправляет условие при изменении определения/активности.
Клиент, который сознательно не передаёт условие, не получает защиту от устаревшего
baseline, хотя блокировки и защита действующих запусков сохраняются.

Для разрешения правки параметров под работающим запуском потребуется отдельная
миграция всех runtime settings в immutable run snapshot и проверка восстановления
старых запусков. В этом этапе такая миграция не выполнялась.

## Ошибки и неизвестный исход

| Результат | Действие |
| --- | --- |
| 403 | Проверить права; черновик сохраняется |
| 404 | Перечитать каталог и принадлежность ресурса |
| 409 | Перечитать состояние; при active runs закончить/отменить их отдельно; подтвердить заново |
| 422 | Проверить JSON и контракт; чтение состояния необходимо перед новым подтверждением |
| Timeout/5xx/неверный receipt | Запись могла состояться; повтор блокируется до явного чтения |

Карточка не повторяет PATCH/POST автоматически. Двойной клик не отправляет вторую
мутацию. Закрытие, изменение черновика и refetch блокируются на время отправки.
После неизвестного исхода свежее чтение снимает блокировку, но не делает replay:
оператор сопоставляет текущее определение с намерением и подтверждает заново.

## Что подтверждено

21 UI regressions, полный frontend 101 suites/867 tests, types и production build;
120 связанных PostgreSQL cases; 35 cases внутри нового production image;
Ruff 0.15.2 и mypy по 224 backend modules. Отдельный конечный live API canary
создал только своё определение, проверил изменения/активацию/409/422 и оставил
его выключенным. Он не создавал PipelineRun и не отправлял Android-команды.

Свежая browser visual/keyboard/mobile приёмка остаётся
`OPEN_URL_POLICY_BLOCKED`. Проверки компонентов и API не заменяют её. Stream
FPS/input latency, общий OTA rollout и 20–30-device combined acceptance этим
этапом не подтверждаются.
