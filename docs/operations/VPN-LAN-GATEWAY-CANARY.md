# Локальный шлюз AWG2: ограниченный canary

Это дополнительный диагностический путь для одного Android-устройства.
Встроенный VPN остаётся в APK; внешний Python-процесс пересылает только
зашифрованные UDP-датаграммы между частной LAN и заданным сервером AWG.
Он не заменяет production executor, VPN-сервер или управляющее соединение Sphere.

## Когда использовать

На PH030 прямой WAN-путь давал handshake без рабочего HTTPS. После исправления
upstream у провайдера тот же клиент заработал в независимом userspace probe на
ПК, затем на Android через LAN-шлюз. Это локализует различие путей, но не
доказывает конкретную причину в DPI, роутере или эмуляторе.
Итоговая квитанция: [PH030 AWG2](../audits/2026-10-23/PH030-AWG2-LAN-GATEWAY-CANARY.md).

Шлюз использует текущую маршрутизацию ПК, включая уже работающий на нём VPN.
Он не устанавливает адаптер, не меняет маршруты или брандмауэр Windows.
Выключение ПК, изменение его сети или завершение аренды останавливает этот путь.
Наличие шлюза не означает, что прямой Android → WAN путь исправлен.

## Запуск и остановка

Исходник: [tools/vpn_lan_relay.py](../../tools/vpn_lan_relay.py).
Нужен Python 3.10+ без сторонних пакетов. Пример с адресами-заполнителями:

```powershell
python tools/vpn_lan_relay.py `
  --bind 192.168.1.20 --port 57886 --allowed-lan 192.168.1.0/24 `
  --upstream 203.0.113.5:57401 --h1 12345 --s1 32 `
  --seconds 900 --packets-per-second 2000 `
  --state C:/private-canary/state.json --stop-file C:/private-canary/STOP
```

Каталог состояния должен существовать, STOP — отсутствовать. Для фона в Windows
использовать `Start-Process -WindowStyle Hidden`; сохранить PID, SHA исходника,
намерение запуска и срок завершения в приватной квитанции. Секретные ключи
шлюзу не передаются. `upstream` брать из конфигурации именно выданного peer,
а не из прежнего профиля или адреса API. H1/S1 должны соответствовать реально
применённым серверным параметрам AWG2. После изменения параметров сервис может
продолжать выдавать старый текст клиентского конфига: требуется сверка readback.

В адресной ревизии Android-профиля Endpoint заменяется на LAN-адрес шлюза.
Ключи и остальные согласованные параметры сохраняются. Ревизия доставляется
штатно в зашифрованном виде. Не запускать второй клиент с тем же ключом
одновременно с Android для сравнительного теста.

Для остановки создать указанный STOP-файл и проверить состояние `stopped`.
Без STOP процесс завершится как `expired`: по умолчанию через 900 с,
предельная аренда — 86400 с. Продления, службы автозапуска и автоматического
подхвата другим ПК нет. Сначала подтвердить независимый Android guard:
остановка шлюза сама по себе не устанавливает kill switch.

## Ограничения и наблюдаемость

- Bind только на конкретный частный IPv4; разрешённая подсеть не шире /24.
- Первый LAN endpoint выбирается по длине handshake и публичному H1; затем
  закрепляется IP. Смена порта того же IP требует такого же маркера.
  **Это не аутентификация клиента шлюзом**: криптографическая проверка остаётся
  на удалённом AWG-сервере. Недоверенная общая LAN для этого canary не подходит.
- Upstream фиксирован; произвольной переадресации и HTTP-прокси нет.
- Датаграмма не больше 3072 байт, отдельный token bucket для каждого направления.
  Предельные настройки CLI — 10000 пакетов/с, для PH030 выбрано 2000.
- State содержит состояние, срок аренды, число пересылок/ошибок/отказов.
  Адреса клиентов, ключи и содержимое пакетов не журналируются.
- Проверять также свежесть обновления, существование записанного процесса
  и принадлежность UDP listener. При внешнем завершении процесса последний
  файл может остаться `running`: это не состояние живого шлюза.
- Счётчики пересылок и handshake не доказывают наличие интернета: отдельно
  проверять HTTPS по IP, DNS, внешний IP приложения и сохранность Sphere.
- Режим рассчитан на AWG2 со скалярным H1 и S1. Совместимость с AWG3.1,
  диапазонами заголовков и новыми механизмами padding здесь не заявляется.

23 октября при отдельной диагностике RAM обнаружен остановившийся собственный
gateway. Адресно восстановлен один listener с прежним исходником; управляющая
сессия и native PID Android сохранились. Причина остановки не установлена.
[Квитанция восстановления](../audits/2026-10-23/PH030-AWG2-GATEWAY-RECOVERY.json)
подтверждает трафик/handshake, но не заменяет прежнюю HTTPS-проверку новой.

## Условия расширения

Перед постоянной эксплуатацией нужны аутентифицированная регистрация клиента,
владение/аренда ресурса, управляемое восстановление, наблюдение со стороны
Sphere, политика истечения и потери шлюза, ограничения нагрузки и отдельная
приёмка смены сети. Для независимого от ПК варианта нужен рабочий прямой
WAN-путь либо поддерживаемый выделенный шлюз. Миграция сервера на AWG3.1 —
отдельная операция с проверкой совместимости обоих концов, а не смена подписи
версии Android-библиотеки.

Официальные источники: [версии AmneziaWG](https://docs.amnezia.org/documentation/amnezia-wg/),
[разбор отсутствия трафика](https://docs.amnezia.org/troubleshooting/self-hosted-amneziawg-not-working/).
Переустановка протокола удаляет пользователей на сервере; в этом canary она
не выполнялась. [Контракт провайдера](../design/WG-ROUTER-PROVIDER-INTEGRATION.md).
