# Ручная запись маршрута в вебе

Срез24 октября2026: APK1.2.90/10290 **собрана локально и установлена только PH011**;
SHA-256 установленного пакета проверен независимо. Три нативных контакта проверены на launcher/debug fixture, затем реальная игровая
browser-запись6026/6026кадров за190,215с с параллельным3D preview прошла SHA/decode/COMPLETE/CLOSED. Игровой маршрут,
автономное повторение и единая 3D-карта этим не подтверждены. Первоначальный блок
по RAM снят после восстановления ресурсов. [История проверок](../audits/2026-10-24/WEB-TEACHING-CONTACTS.md).

## Рабочее место

В полной карточке устройства: **Записать маршрут**. Альтернативно открыть
`/stream/DEVICE_UUID?teach=1` из страницы потока. Режим заменяет обычный renderer,
не создаёт второй видеопоток поверх него. Нужны права `stream:read` и
`stream:control`, разрешённый shared direct input и современный браузер с
WebRTC Encoded Transform, OPFS, WebCodecs для просмотра. Localhost/HTTPS должны
предоставлять secure context. Несовместимый браузер не переключается незаметно
на запись canvas худшего качества.

Подключение потока — отдельное явное действие. Capture-only WebSocket поддерживает
жизненный цикл захвата; видео и ввод идут по одному существующему авторизованному
WebRTC peer. Приём медиаданных по этому WebSocket считается ошибкой. Указан
выбранный тип ICE-пути, а не обещан host/direct при любой сетевой конфигурации.
Автоматического переподключения или восстановления старых удержаний в этом
режиме нет; оператор заново проверяет экран и начинает новый материал.

1. Войти в игру обычным способом и найти воспроизводимое начальное место.
   Статичный экран после AFK не считается игровым миром. При отключении полностью
   закрыть и открыть игру; между подключениями к игровому серверу≥20с.
2. Для качественного master рекомендуется1920×1080,320DPI и100% render в игре;
   цель60FPS. До принятого APK/UI не нужно менять эмулятор ради неготового прогона.
   Кнопка **Качество → LAN60FPS** задаёт предел кодека для всех зрителей данного
   устройства. Она не меняет Android resolution/DPI или внутренний render игры.
3. Подключить поток: экран автоматически показывается перед проверкой свежих кадров.
   Для ходьбы выбрать **Центр стика**, нажать на его центр; выбрать
   **Кнопка действия**, нажать на игровую кнопку. Эти калибровочные клики не
   отправляются Android. Радиус измеряется в процентах короткой стороны экрана.
   Начальные значения — пример, а не проверенный профиль конкретной игры.
4. Для подготовки игры нажать **Включить управление** — WASD/мышь/пробел работают
   без создания видеозаписи. Щёлкнуть по игровому экрану для фокуса. Перед началом
   записи отпустить клавиши и мышь: прежний владелец ввода должен подтвердить CLOSED.
   Указать название, предел 2/5/10 минут и нажать **Записать маршрут**. Подтверждаются
   `contact_protocol=1`, native READY и новый ключевой кадр SPS/PPS/IDR.
   Только после этого включаются игровые клавиши.
5. Держать фокус на видимом экране: WASD — аналоговый стик; Shift —40% амплитуды;
   ЛКМ+движение — отдельный контакт камеры; пробел — третий контакт на выбранной
   кнопке. Первое DOWN стика устанавливает центр, далее MOVE меняет направление
   без повторных DOWN/UP. Для игрового двойного нажатия оператор нажимает пробел
   дважды; произвольные LDPlayer macros не исполняются.
6. **Остановить / Escape** освобождает весь ввод и финализирует файлы. При потере
   фокуса/видимости, устаревшем кадре или ошибке остановка происходит автоматически,
   материал остаётся неполным. Новый проход требует нового подключения.

### Транспорт и скрытый HUD

В схеме **Транспорт** сначала сядьте в машину/скутер с видимыми кнопками игры.
Укажите четыре точки: газ, тормоз/назад, левый и правый руль. Калибровка не
отправляет нажатия в игру; проверенные точки отмечаются поверх видео. Без всех
четырёх точек управление заблокировано; после смены разрешения их нужно указать
заново. Профиль сейчас хранится в состоянии страницы и в записанном manifest,
перезагрузка страницы не восстанавливает его из аккаунта.

W/S используют контакт 0, A/D — контакт 1: газ и руль удерживаются независимо,
повтор клавиши не создаёт новые DOWN/UP. Одновременные противоположные клавиши
дают нейтральное состояние. Мышь и дополнительная кнопка Space используют контакт
2 по очереди; Space в этом режиме требует отдельной калибровки. Это профиль
экранных кнопок, а не готовый универсальный драйвер транспорта любой игры.

После проверки управления можно скрыть HUD в игре, если это не меняет раскладку
и игра продолжает принимать касания в прежних точках. Флажок **HUD скрыт в игре**
сохраняет только декларацию оператора. Он не вырезает HUD, надписи или NPC из raw
видео. Панель записи закреплена сверху; средний FPS вычисляется из записанных
кадров и media duration, а не из целевого значения кодека.

Неожиданный native CLOSED выключает управление и завершает запись с причиной
`native_closed_unexpectedly`; страница не оставляет внешне активные мёртвые клавиши.
Остановка с зажатой клавишей сохраняет native CANCEL uptime и список удерживаемых
контактов в CLOSED, без выдуманного UP. Неподтверждённые события остаются причиной
неполного материала; повтор закрытия не превращает UNKNOWN в успех.

## Что сохраняется

Явно начатая запись создаёт папку в OPFS этого browser origin:

| Файл | Содержание |
|---|---|
| `video.h264` | Полученные H264 AnnexB access units до декодера, без повторного кодирования |
| `frames.jsonl` | Offset/size/SHA-256 каждого access unit, исходный RTP timestamp, относительные90k ticks и часы получения worker |
| `inputs.jsonl` | Реально submitted события, соответствующие APPLIED/ALIVE и подтверждение CLOSED; последовательность, контакт, координаты, часы браузера и Android uptime |
| `manifest.json` | Capture binding, профиль касаний, размеры/хеши индексов, ограничения, статус и причина неполноты |
| `COMPLETE` | SHA-256 manifest; создаётся последним только при доказанном закрытии без неразрешённых событий |

Предел по умолчанию10минут/2GiB/36000кадров; можно выбрать2минуты/512MiB или
5минут/2GiB. Предел завершает приём видео и просит страницу освободить ввод:
COMPLETE всё равно требует CLOSED и полный журнал подтверждений. Ошибка диска
или неопределённый ввод остаются неполнотой.40000записей/8MiB журнала; очередь≤32операций
и8MiB, отдельный access unit≤2MiB; до20материалов. До старта файлы не создаются.
Нет бесконечного RAM Blob и автоматической серверной видеотеки. Локальная библиотека разделена по идентификаторам организации/аккаунта; токены
в имена папок не включаются. Хранилище привязано к браузеру/origin,
**не синхронизировано между браузерами или с сервером аккаунта**. При смене адреса/браузера
библиотека другая; очистка данных браузера может её удалить. Экспортировать ценные
материалы до очистки; удаление в этой панели окончательное для выбранной локальной
папки. Незавершённые папки тоже видны как прерванные материалы.

Получение кадра worker, RTP90k и Android uptime — разные временные шкалы.
Полного соответствия Android capture→browser/model здесь нет. APPLIED означает
подтверждение нативного dispatcher, не доказательство визуального игрового эффекта.
Частота в manifest не считается60FPS по одному целевому параметру; измерять
реальные межкадровые интервалы по индексу. Условный localhost также не означает0мс.

## Просмотр и последующая обработка

Панель **Записанные проходы** проверяет COMPLETE/manifest и SHA-256 индексов.
Ползунок выбирает кадр; WebCodecs декодирует его от ближайшего IDR и проверяет
хеши прочитанных access units. Рядом показываются нативные подтверждения того же
интервала часов браузера. Это покадровый2D debug viewer; не LiDAR, не готовая
метрическая3D карта.

**Сохранить пакет в папку** открывает системный выбор каталога в поддерживающем
браузере (Chrome/Edge). Для каждого экспорта создаётся новая уникальная подпапка;
существующая не перезаписывается. Видео читается access units до 2 MiB, исходные
SHA проверяются, затем сохранённое видео целиком проверяется повторным чтением
такими же частями. Индексы и manifest также проверяются; COMPLETE пишется последним.
Нет многогигабайтного RAM Blob. При отмене/ошибке исходник остаётся в OPFS,
папка без COMPLETE считается неполной. Во время экспорта новое управление и
запись заблокированы. Отдельные файлы доступны в раскрываемом блоке диагностики.
Выбор папки требует жеста пользователя; браузер без этого API предлагает
скачивание отдельных файлов. Приватный OPFS не является резервной копией.

Browser schema `sphere-browser-teaching-v2` добавляет выбранные бюджеты, точную
длительность и причину штатного лимита. Viewer читает v1/v2. Каждые300кадров
запрашивается IDR; обещание отправить ключевой кадр не заменяет проверку байтов.
Поиск кадра читает файл порциями с очередью декодера≤8, прежнего запрета после
600кадров нет. Browser schema явно отличается от worker0.8.0 bundle.
Прямой импорт нового формата в `motor_worker.teach compile`, автоматический
реплей и автономное повторение пока **не реализованы**. Удержания и завершение
проверены на Android debug fixture; следующий допуск — игровой человеческий проход,
независимый low-render повтор, затем общий importer/route compiler.
Успешная запись не доказывает локализацию, объезд динамических объектов или arrival.

## Локальная живая 3D-панель

На этой же странице отдельная кнопка **Подключить 3D-просмотр**. Подключать её
до включения управления/записи и дождаться сцены: холодный запуск viewer не
совмещается с активным нативным вводом. После прогрева viewer остаётся доступным
во время записи. Встроенный viewer использует `localhost:3331`, основной клиент —
`127.0.0.1:3015`; разные sites позволяют Chromium разделить renderer-процессы.
Переход фокуса в viewer без удержаний не равен уходу из приложения; реальный blur,
удерживаемый ввод или stale/ACK timeout по-прежнему останавливают запись.
Точные причины: `contact_video_stale`, `contact_channel_closed`,
`contact_ack_timeout`, `contact_ready_timeout`; пороги250/500/6000мс не ослаблены. Для текущего pilot
нужен localhost на компьютере с GPU и явно запущенный обработчик:

```powershell
.local-pilot/motor-amd-venv/Scripts/python.exe -m scripts.pilot.teaching_scene --assets .local-pilot/route-reconstruction-da3 --device cuda
```

Обработчик требует закреплённые DA3-SMALL weights/source и Rerun0.40.0; сам модели
не скачивает. Слушатели3330/3331/3332 привязаны только127.0.0.1, процесс viewer
запускается скрытым и принадлежит обработчику. Ctrl+C останавливает оба процесса.
Origin строго `http://127.0.0.1:3015`, один владелец с временным ключом, тело≤512KiB,
параллельный запрос отвергается без очереди. Сессия≤15минут (включая прогрев перед
полной 10-минутной записью), idle≤20с. Истечение требует нового явного подключения. Это
локальный pilot, не многопользовательский production service или удалённый endpoint.

Панель берёт свежий уменьшенный JPEG из уже декодированного прямого видео: нового
WebRTC peer нет. Один запрос одновременно, следующая выборка через1с после ответа.
Файлы кадров не создаются; Rerun хранит ограниченный RAM history (server64MB,
viewer128MB). Отказ геометрии не переключает транспорт и не управляет Android.
Две последние позиции реконструируются заново: цвета/точки/камеры настоящие,
но между окнами нет глобального выравнивания, loop closure или метрического масштаба.
Фиксированная маска краёв HUD/центра персонажа не является semantic dynamic mask.
Два исходных ракурса выводятся отдельно как плоские 2D-изображения; облако точек
показывается в некалиброванных единицах. Сохранённый пакет содержит видео и ввод,
но не экспорт временной Rerun-сцены и не сшитую карту.

На RX9070 offline проверка двух сохранённых игровых ракурсов дала4266точек;
три inference:1098/474/32мс после холодного запуска. Полный HTTP round trip был
1203–2344мс, включая resource guard и подготовку. Это **не задержка моторного ИИ**
и не доказательство 5Hz 3D. Для навигации scene preview пока не допускается.

## Источники выбранного browser capture

Оригинальные encoded frames доступны через
[WebRTC Encoded Transforms](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Using_Encoded_Transforms).
[Metadata](https://developer.mozilla.org/en-US/docs/Web/API/RTCEncodedVideoFrame/getMetadata)
разделяет RTP timestamp и доступные receiver times. Метод
[sendKeyFrameRequest](https://developer.mozilla.org/en-US/docs/Web/API/RTCRtpScriptTransformer/sendKeyFrameRequest)
не гарантирует фактическую отправку IDR при исполнении promise, поэтому запись
проверяет наличие SPS/PPS/IDR в реальных байтах. Реализация требует H264 AnnexB и
доступных width/height/rtpTimestamp; SPS/IDR должен подтверждать размер. Chromium delta0×0 наследует только уже
подтверждённую геометрию при том же SSRC; смена явных размеров/источника — отказ.
