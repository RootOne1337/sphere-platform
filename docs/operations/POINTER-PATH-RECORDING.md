# Запись непрерывной траектории

Поставка APK 1.2.82 / Android исходник `e3a34b2e`, веб/API `15ce2b62`. Проверки и установленные пакеты связаны в [отчёте серии жестов](../audits/2026-10-16/POINTER-TIMELINE82-DELIVERY.md). Это ограниченная приёмка, не общий SLA. Предыдущая [поставка APK81](../audits/2026-10-16/POINTER-PATH81-DELIVERY.md) сохраняет собственные результаты и ограничения.

## Поведение в Studio

Одно нажатие, все движения и удержания до отпускания создают одно действие `pointer_path`. Изгиб, возврат и остановка внутри жеста не превращаются в дополнительные ноды. Отдельная положительная пауза между завершёнными действиями переносится как `sleep`, если включена настройка сохранения пауз (до 60 секунд).

Траектория хранит локальное монотонное время отправки из браузера. Нативные подтверждения DOWN и UP относятся к границам жеста. Они не подтверждают исполнение каждого промежуточного MOVE: транспорт может объединять движения. Это запись предложенной клиентом траектории, а не измерение идентичности двух исполнений Android.

В инспекторе ноды отображаются путь, количество точек, длительность и шкала времени. Передвижение шкалы показывает точку записи и ничего не отправляет устройству. Точки и время доступны в JSON шага.

## Формат

```json
{
  "type": "pointer_path",
  "path": {
    "schema_version": 1,
    "frame_width": 960,
    "frame_height": 540,
    "points": [
      { "t_ms": 0, "action": 0, "x": 100, "y": 300 },
      { "t_ms": 2000, "action": 2, "x": 300, "y": 200 },
      { "t_ms": 4500, "action": 2, "x": 100, "y": 300 },
      { "t_ms": 6000, "action": 1, "x": 100, "y": 300 }
    ]
  }
}
```

Первые две секунды палец остаётся в начальной точке, затем перемещается в указанную точку. Он удерживается до следующей точки, возвращается и отпускается на шестой секунде. Запись не добавляет интерполяцию: реально записанный плавный жест содержит промежуточные MOVE с их временем.

Ограничения одного жеста: 2–4096 точек, до 60 секунд и 256 KiB компактного JSON, кадр до 16384×16384. Только целые неотрицательные числа; координаты строго внутри кадра. Первая точка — DOWN (`0`) в нулевой момент, последняя — UP (`1`), остальные — MOVE (`2`). Время не убывает. Неизвестные поля внутри `path` и точек отклоняются. Лимит записи Studio — 200 завершённых действий. Переполнение не создаёт усечённую траекторию.

Отдельно действует лимит исходника Studio 512 KiB, включая форматирование и остальные ноды. Он может сработать раньше лимита точек одного жеста: большой граф не будет молча усечён. Несколько длинных траекторий требуют отдельных сценариев либо последующего компактного формата хранения.

## Исполнение и остановка

Задание получает общую эксклюзивную аренду ввода Android. Перед открытием собственного native helper исполнитель дожидается FIFO-подтверждения предыдущих shell-команд. Простого `flush()` недостаточно. Ручное управление других клиентов приостанавливается прежним механизмом APK80; медиа-соединения сохраняются.

После native READY используется одно абсолютное расписание Android: ожидание следующей точки не начинается заново после каждого ACK. В APK82 последовательные `pointer_path` и `sleep` используют один task-scoped native helper. Пауза начинается от запланированного UP предыдущего жеста; startup, ACK и служебная обработка DAG не прибавляются к каждой следующей паузе. Каждому новому жесту соответствует новый `downTime`. Heartbeat поддерживает аренду и в промежутке без нажатия, не добавляя MOVE. Любое другое действие завершает текущую серию перед использованием другого адаптера ввода; следующая траектория начинает новое расписание. Удержание поддерживается heartbeat; `downTime` сохраняется до UP. Координаты масштабируются из записанного кадра в текущую геометрию, ориентация должна совпадать. Смена геометрии прерывает путь.

Отмена, потеря подтверждения, неизвестная запись в pipe и отставание расписания более чем на 100 мс прерывают жест. Просроченные точки не отправляются накопленным рывком. Закрытие helper должно подтвердить отпускание; неизвестный cleanup блокирует новый ввод. Частичный жест не допускает автоматического retry или перехода `on_failure` к новым побочным действиям. При паузе во время пути или его timed gap helper закрывается и серия прерывается; продолжение с середины не имитируется. Пауза между нодами — явная граница расписания: idle helper закрывается до ожидания resume. Завершение, отмена и ошибка задания всегда закрывают helper до возврата ручного управления.

Счётчики результата: `points_applied`, `duration_ms`, `max_schedule_lateness_ms`, `timeline_offset_ms`, `start_lateness_ms`, `helper_reused`. `timeline_offset_ms` — запланированное начало жеста от READY общей серии. `helper_reused` показывает повторное использование pipe; `start_lateness_ms` — опоздание DOWN относительно этого начала. Отставание измеряется перед отправкой в native pipe и не является полной задержкой Android/видео. Ошибка содержит фиксированную причину и число попыток отправки точек; координаты и текст не нужны в операционных логах.

Общий диспетчер задач отклоняет траекторию на APK ниже 1.2.81 или при неизвестной версии до отправки задания. Обычные старые `tap`/`swipe` сохраняют прежнюю семантику.

## Что ещё требует приёмки

Проверки с искусственными часами доказывают порядок DOWN/MOVE/UP, удержание, возврат, отсутствие накопления ACK-задержек и cleanup при отмене. Они не доказывают точность под нагрузкой реального эмулятора. Конечные проверки на PH011 и PH030 покрыли две записанные траектории, отдельную паузу, общий native helper и повтор с сохранением direct media peers. На PH011 дополнительно проверены отмена при удержании и отмена в промежутке между жестами, с возвратом manual READY. Другие топологии и нагрузка требуют отдельной проверки.

В APK81 у каждого path-узла был собственный helper. APK82 добавляет общее расписание последовательных жестов и пауз; другие действия и явная пауза между нодами остаются границами серии. Измерения конкретных запусков приведены в отчёте. Отдельно остаются бюджет джиттера под нагрузкой, мультитач, XPath/пиксель/изображение как дополнительное свидетельство, запись игровой клавиатуры и сравнение результатов приложения. Детерминированная траектория не гарантирует одинаковое состояние игры при повторном запуске.
