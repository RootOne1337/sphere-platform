# Запись непрерывной траектории

Поставка APK 1.2.81 / Android исходник `bf4e4045`, веб/API `15ce2b62`. На PH011 выполнена конечная проверка записи, повтора и отмены; [результат и установленные пакеты](../audits/2026-10-16/POINTER-PATH81-DELIVERY.md). Это ограниченная приёмка, не общий SLA.

## Поведение в Studio

Одно нажатие, все движения и удержания до отпускания создают одно действие `pointer_path`. Изгиб, возврат и остановка внутри жеста не превращаются в дополнительные ноды. Отдельная положительная пауза между завершёнными действиями переносится как `sleep`, если включена настройка сохранения пауз (до 60 секунд).

Траектория хранит локальное монотонное время отправки из браузера. Нативные подтверждения DOWN и UP относятся к границам жеста. Они не подтверждают исполнение каждого промежуточного MOVE: транспорт может объединять движения. Это запись предложенной клиентом траектории, а не измерение идентичности двух исполнений Android.

В инспекторе ноды отображаются путь, количество точек, длительность и шкала времени. Передвижение шкалы показывает точку записи и ничего не отправляет устройству. Точки и время доступны в JSON шага.

## Формат

```json
{
  "type": "pointer_path",
  "path": {
    "schema_version": 1,
    "frame_width": 960,
    "frame_height": 540,
    "points": [
      { "t_ms": 0, "action": 0, "x": 100, "y": 300 },
      { "t_ms": 2000, "action": 2, "x": 300, "y": 200 },
      { "t_ms": 4500, "action": 2, "x": 100, "y": 300 },
      { "t_ms": 6000, "action": 1, "x": 100, "y": 300 }
    ]
  }
}
```

Первые две секунды палец остаётся в начальной точке, затем перемещается в указанную точку. Он удерживается до следующей точки, возвращается и отпускается на шестой секунде. Запись не добавляет интерполяцию: реально записанный плавный жест содержит промежуточные MOVE с их временем.

Ограничения одного жеста: 2–4096 точек, до 60 секунд и 256 KiB компактного JSON, кадр до 16384×16384. Только целые неотрицательные числа; координаты строго внутри кадра. Первая точка — DOWN (`0`) в нулевой момент, последняя — UP (`1`), остальные — MOVE (`2`). Время не убывает. Неизвестные поля внутри `path` и точек отклоняются. Лимит записи Studio — 200 завершённых действий. Переполнение не создаёт усечённую траекторию.

Отдельно действует лимит исходника Studio 512 KiB, включая форматирование и остальные ноды. Он может сработать раньше лимита точек одного жеста: большой граф не будет молча усечён. Несколько длинных траекторий требуют отдельных сценариев либо последующего компактного формата хранения.

## Исполнение и остановка

Задание получает общую эксклюзивную аренду ввода Android. Перед открытием собственного native helper исполнитель дожидается FIFO-подтверждения предыдущих shell-команд. Простого `flush()` недостаточно. Ручное управление других клиентов приостанавливается прежним механизмом APK80; медиа-соединения сохраняются.

После native READY используется одно абсолютное расписание Android: ожидание следующей точки не начинается заново после каждого ACK. Удержание поддерживается heartbeat; `downTime` сохраняется до UP. Координаты масштабируются из записанного кадра в текущую геометрию, ориентация должна совпадать. Смена геометрии прерывает путь.

Отмена, потеря подтверждения, неизвестная запись в pipe и отставание расписания более чем на 100 мс прерывают жест. Просроченные точки не отправляются накопленным рывком. Закрытие helper должно подтвердить отпускание; неизвестный cleanup блокирует новый ввод. Частичный жест не допускает автоматического retry или перехода `on_failure` к новым побочным действиям. При паузе задания удерживаемый палец отпускается и путь прерывается; продолжение с середины не имитируется.

Счётчики результата: `points_applied`, `duration_ms`, `max_schedule_lateness_ms`. Последний измеряется перед отправкой точки в native pipe, не является полной задержкой Android/видео. Ошибка содержит фиксированную причину и число попыток отправки точек; координаты и текст не нужны в операционных логах.

Общий диспетчер задач отклоняет траекторию на APK ниже 1.2.81 или при неизвестной версии до отправки задания. Обычные старые `tap`/`swipe` сохраняют прежнюю семантику.

## Что ещё требует приёмки

Проверки с искусственными часами доказывают порядок DOWN/MOVE/UP, удержание, возврат, отсутствие накопления ACK-задержек и cleanup при отмене. Они не доказывают точность под нагрузкой реального эмулятора. Конечные проверки на PH011 покрыли запись медленного жеста в браузере, перенос одной нодой, повтор на Android, отмену и сохранение прямого видео. Другие топологии и нагрузка требуют отдельной проверки.

У каждого path-узла пока собственный native helper. Его startup/cleanup добавляют время между отдельными жестами. Поэтому точность пауз между несколькими нодами нельзя приравнивать к точности расписания внутри одного жеста. Отдельно остаются task-scoped переиспользование helper, измеренный бюджет джиттера, мультитач, XPath/пиксель/изображение как дополнительное свидетельство и сравнение результатов приложения. Детерминированная траектория не гарантирует одинаковое состояние игры при повторном запуске.
