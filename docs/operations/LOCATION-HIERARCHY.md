## Модель данных

Локация принадлежит одной организации. Она описывает физическую или логическую
площадку и может иметь одного родителя из этой же организации. Несколько
уровней образуют путь, например «Площадка / Этаж / Комната».

Устройство может одновременно входить в несколько локаций. Поэтому сумма
счётчиков карточек не является количеством уникальных устройств в парке.
`total_devices` и `online_devices` относятся к прямым назначениям, без
рекурсивного суммирования дочерних локаций. Online здесь означает сохранённый
`Device.last_status == online`; это не независимая проверка socket/heartbeat
и не сумма `online + busy` из Fleet Matrix.

Координаты вводятся вручную в десятичных градусах. API не выводит их из IP,
адреса, Android GPS или туннеля. Карта, внешний геокодер и интеграция с платным
провайдером этим изменением не добавлены.

## Поля

| Поле | Ограничение | Очищение при PUT |
|---|---|---|
| `name` | Непустое после trim, до 255 символов; уникально внутри организации | `null` запрещён |
| `description` | До 1000 символов | `null` |
| `address` | До 500 символов | `null` |
| `color` | `#RRGGBB` | `null` |
| `latitude` | Конечное число от −90 до 90 включительно | `null` |
| `longitude` | Конечное число от −180 до 180 включительно | `null` |
| `parent_location_id` | UUID собственной доступной локации или корень | `null` |
| `expected_updated_at` | Необязательная timezone-aware дата из просмотренного ответа | Условие записи, не сохраняемое поле |

Отсутствующее поле при PUT сохраняет прежнее значение. Явный `null` очищает
nullable поле. Ноль является настоящей координатой; он не означает отсутствие.
Широта и долгота nullable независимо: частично заполненная старая запись
остаётся редактируемой. В карточке незаданное значение показано как «—».
Для десятичного ввода UI использует точку, без скрытого преобразования строки
`0x10`, `NaN` или `Infinity`. Неизвестное поле запроса отклоняется с `422`.
Старые клиенты могут по-прежнему передать пустую строку в description/address;
новый UI использует `null` и посылает только фактически изменённые поля.

## HTTP-контракты

Базовый путь: `/api/v1`.

| Метод / путь | Разрешение | Результат |
|---|---|---|
| GET `/locations` | `device:read` | Полный список организации с прямыми счётчиками |
| GET `/locations/{id}` | `device:read` | Собственная локация со счётчиками, `created_at`, `updated_at` |
| POST `/locations` | `device:write` | `201` и созданная локация |
| PUT `/locations/{id}` | `device:write` | `200` и подтверждённое состояние |
| DELETE `/locations/{id}` | `device:delete` | `204`; optional query `expected_updated_at` |
| POST `/locations/{id}/devices` | `device:write` | Аддитивное назначение; число фактически добавленных |
| DELETE `/locations/{id}/devices` | `device:write` | Снятие конкретных назначений; число фактически удалённых |

POST/DELETE memberships используют JSON `{"device_ids":["<UUID>"]}`, 1–500
строк. Их прежняя семантика сохранена: неподходящие UUID и отсутствующие либо
чужие устройства пропускаются; это не обещание all-or-nothing batch admission.
Назначение не удаляет другие локации устройства. Другие страницы назначения
сохраняют свои отдельные workflows.

Новый UI допускает редактирование для device_manager/org_admin/org_owner/
super_admin; удаление — только для org_admin/org_owner/super_admin. Viewer и
script_runner видят данные без этих кнопок. Сервер самостоятельно проверяет
права; скрытие кнопки не является защитой API.

## Иерархия и конкурентная запись

Родитель не может быть самим объектом или его потомком. Нельзя унаследовать
уже повреждённую цепочку: цикл либо недоступный предок отклоняются.
Очищение родителя разрешено и может разорвать старую некорректную цепочку.
UI исключает себя, потомков и некорректные цепочки из вариантов родителя.
Сервер повторяет проверку независимо от UI.

Все writers LocationService используют отдельный transaction-scoped advisory
lock организации. `pg_try_advisory_xact_lock` не ждёт занятую транзакцию:
конкурирующая запись получает `409`. Блокировка живёт до commit/rollback.
Другие организации и иерархия групп используют другие ключи. Это важно для
двух одновременных встречных reparent: блокировка только одной строки не
предотвратила бы общий цикл.

Сервис проверяет ownership, свежую ancestry, условие версии и уникальность
имени до изменения ORM объекта. Все отклонённые запросы оставляют поля
неизменными. Прямые сторонние SQL writers не получают этот сервисный lock;
такие writes не входят в поддерживаемый контракт. Схема БД не изменялась.

Новый UI всегда передаёт `expected_updated_at` при PUT и DELETE. Если дата
устарела, API отклоняет операцию с `409`; проверка выполняется под tenant fence.
Условие остаётся optional для совместимости со старыми клиентами. Поэтому
старый клиент без условия не получает гарантию защиты собственного черновика
от чужого изменения, хотя проверка иерархии остаётся обязательной.

## Что подтверждает интерфейс

Каталог и owned detail перечитываются раз в 15 секунд при открытой странице.
Это polling, а не push уведомление о каждой SQL записи. Во время failed read,
неподтверждённого snapshot, фонового чтения или чужого изменения Save недоступен.
Ключи query/dialog включают организацию, пользователя, роль и session version.
Смена сессии скрывает прежний черновик; поздняя запись не становится новым успехом.

Сохранение проверяет статус HTTP, ID, организацию, поля и даты в ответе API.
Счётчики не заменяются локальными догадками. При ошибке черновик сохраняется.
Неизвестный сетевой исход не повторяется автоматически: сначала оператор
перечитывает состояние и сверяет результат. Повторная запись блокируется.
Перечитывание/закрытие dirty формы требует явного согласия отбросить черновик.

## Удаление

Перед DELETE диалог получает owned detail и объясняет последствия:

- удаляются локация и её прямые M2M назначения;
- устройства сохраняются;
- непосредственные дочерние локации становятся корневыми;
- назначения дочерних локаций сохраняются.

В диалоге показаны дети из последнего проверенного каталога. Условие даты
проверяет ревизию самой удаляемой локации, а не immutable snapshot всех её
membership/children. Последняя серверная структура применяется при commit;
это не транзакционный preview всего парка.

## Приёмка и ограничения

F26 принят на уровне source, component tests, PostgreSQL/RLS, production image
и конечного live API canary. Это не завершённая production приёмка продукта.
Свежие visual/keyboard/mobile checks остаются открытыми из-за ранее полученного
запрета URL-policy браузера. Исторические screenshots не переименованы в свежие.
Нагрузочная приёмка больших каталогов, доступная карта и массовые actions не
добавлены. Android APK, OTA каталог, Tuna и public frontend этим batch не менялись.
