## Итог повторного запуска 20 сентября

`night-20260920-001` завершился **FAILED** в 06:37 по Екатеринбургу после
**3 ч 33 мин 28 с**, не достигнув плановых восьми часов. Backend `eacf692`,
frontend `03b161e`, оба APK 1.2.7 / 10207 не обновлялись во время наблюдения.

106 циклов, 212 batch DAG + 11 pipeline DAG, 22 pipeline controls и 2 130 RPC.
Все сохранённые task/pipeline receipts независимо сверены с API; активных
остаточных задач нет. PID и crash buffers обоих APK прежние. Один отдельный
WS disconnect второго APK восстановился примерно за 2,51 с. В цикле 107
не запустился второй стрим: helper остановился на ожидании SPS/PPS/IDR до
отправки нового batch. Новый длительный helper автоматически не запускается.

[Итог, root cause, AUD-125 и ограничения](../audits/2026-09-05/STREAM-START-DELIVERY.md) ·
[Terminal evidence](../audits/2026-09-05/evidence/soak-20260920-terminal.json).
Два дефекта командного пути воспроизведены; исправление прошло 105 связанных
тестов, но повторные восемь часов ещё не приняты.

После завершения наблюдения установлен backend `8a6b30e`: отдельные шесть парных
запусков стрима после простоя прошли с прежними PID/crash buffers. Это ограниченная
проверка исправления; исходный `night-20260920-001` остаётся FAILED.

Текущий backend `85fb1ea` дополнительно исправляет одновременные просмотры одного
устройства ([AUD-126](../audits/2026-09-05/STREAM-MULTI-VIEWER.md)). Runner теперь
требует новые кадры во всех окнах при overlap и после закрытия extra-viewer,
используя безопасное открытие/закрытие шторки через Sphere. Старые 52 overlap
events подтверждают начальную готовность дополнительных сокетов, но не
непрерывность видео исходных. 22 harness tests и ограниченная native-проверка
нового helper прошли; новой полной ночи пока нет.
[AUD-127 и доказательства](../audits/2026-09-05/SOAK-VIEWER-MOTION.md).

Предварительный 128-секундный прогон ранее прошёл: 30 RPC, три native DAG,
pause/resume/cancel, видео и освобождение projection. Он не заменяет ночь.
[Исторический стартовый checkpoint](../audits/2026-09-05/evidence/soak-20260920-start.json).
Старый SIGABRT `media.codec` первого эмулятора присутствовал до запуска;
terminal crash buffer побайтно совпал с baseline, это не новое падение Sphere.

Периодический контроль этой завершённой ночи больше не нужен. Постоянную
automation владельца следует сохранить с исходным еженедельным расписанием;
результат её восстановления проверяется отдельно от результата теста.
На финальной проверке инструмент Codex сообщал об update, но сохранял временный
prompt и 40-минутный интервал. Возврат к среде 05:15 пока **не подтверждён**;
automation сохранена ACTIVE, не удалена. Это отдельная проблема управления
расписанием, не работающий soak: завершённый запуск повторно не опрашивается.

## Что проверяется

Harness [android_soak.py](../../scripts/pilot/android_soak.py) выполняет настоящие
HTTPS-запросы, batch admission, SQL task lifecycle, Android DAG и WSS-видео.
[Сценарий](../../scripts/pilot/android-safe-soak.json) содержит 14 узлов, 13 на
успешном пути: HOME, открытие/закрытие шторки уведомлений, паузы, переменные,
инкремент, условный переход, echo + assertion, чтение версии Android.

Один цикл длится около двух минут. Волны чередуют размеры подачи 1 и 2 на двух
устройствах; это не ограничение max-in-flight и не гарантия последовательного
исполнения (ночью 31/39 пар с wave-size 1 пересекались). WSS-зрители работают минимум 75 секунд, затем
закрываются. Каждый четвёртый цикл добавляет второго зрителя. Проверяются SPS,
PPS, IDR, корректность длины кадров и новые кадры при движении интерфейса.
Автоматического декодирования видео этим harness нет; декодирование в браузере
проверено отдельно. Низкий FPS неподвижного экрана не считается ошибкой.

После каждого batch проверяются сохранённые ответы APK: device/version IDs,
terminal status, точный порядок 13 шагов, отсутствие дубликатов, success каждого
узла и ожидаемый echo. Перед новой волной не должно быть активной задачи на этих
устройствах. Проверяются PID, online, задержки команд, PSS, CPU ticks и наличие
проекции. CPU ticks — исходные счётчики процесса, не вычисленный процент CPU.

Если private config содержит `pipeline_id`, в первом и каждом десятом цикле
исполняется проверенный pipeline `delay → execute_script → delay`: первое
устройство проходит pause на границе шага → resume → native DAG → completion;
второе — cancel во время delay, после которого native шаг не должен стартовать.
Проверяются точные step logs и native task result. Это не проверка мгновенной
остановки уже выполняющегося Android-узла и не раннего конкурентного resume.

## Ограничения и остановка

- Только явно перечисленные устройства и закреплённая версия проверенного DAG.
- Игры, настройки, сеть Android, пакеты, данные приложений и firmware не меняются.
- APK запускает действия через собственный root executor; ADB используется только
  для чтения аварийного журнала/PID/projection при завершении. ADB install/launch нет.
- Прогон конечный: по умолчанию 8 часов, максимум 12. Последний начатый цикл может
  завершиться позже планового времени приблизительно на две минуты.
- Низкое свободное место (<1 GB), PSS APK >=350,000 KiB, новый PID, ошибочный
  результат или потеря транспорта останавливают новую нагрузку. Это stop budgets
  данного теста, не заявленные ресурсные нормы продукта.
- Изменяющие запросы не повторяются при неизвестном исходе. Наличие HTTP 200 само
  по себе не считается успешным действием; итог DAG сверяется отдельно.
- Закрываются только собственные WSS-зрители. При открытом просмотре владельца
  активная projection после закрытия наших viewers допустима и записывается.
- Для одного private config допускается один процесс (exclusive lock). Lock после
  аварийного завершения требует проверки PID, автоматического takeover нет.
- На Windows helper работает без консольного окна. Пока он запущен, process-scoped
  execution state предотвращает idle sleep; постоянный план питания не меняется.

Для мягкой остановки создайте файл `STOP` в каталоге прогона. Текущая безопасная
операция завершится; новые циклы не начнутся. Аварийный выход пытается отменить
незапущенные задачи только своего batch; выполняющийся DAG ограничен 45 секундами.

## Воспроизведение и evidence

Private JSON config задаёт `script_id`, `version_id`, `devices` (id, optional serial),
`package`, `credentials` (путь к login JSON), `signed_manifest`, `public_key`,
`key_id`, `installation_id`, `minimum_config_version`, optional `adb`.
Для периодических control drills задаётся также `pipeline_id` проверенной цепочки.
Перед передачей credentials проверяются подпись discovery и принадлежность
маршрута установке. Авторизация обновляется каждые 20 минут; source URL повторно
берётся из подписанного локального manifest, обновляемого publisher.

```powershell
python -m scripts.pilot.android_soak --config .local-pilot/overnight-config.json --output .local-pilot/soak/UNIQUE-RUN --seconds 28800
```

`--output` должен быть новым каталогом. В нём находятся:

| Файл | Назначение |
| --- | --- |
| `status.json` | Последнее состояние, время, PID helper, прогресс, причина остановки |
| `summary.json` | Компактный итог, p50/p95 задержек, память по фазам, инциденты |
| `events.jsonl` | Время/цикл/batch/task, задержки, кадры и ресурсные samples |
| `task-<uuid>.json` | Сохранённый native результат с per-node logs |
| `pipeline-<uuid>.json` | Pause/resume/cancel evidence, task ID и step logs |
| `memory-*.txt` | Исходные снимки dumpsys meminfo |
| `diagnostic-*.txt` | Ограниченный crash buffer, PID и projection после завершения |
| `STOP` | Запрос мягкой остановки |

После AUD-117 событие `failed` и `status.json.failure_detail` сохраняют класс,
OS codes и расположение исключения без private текста и locals. У исходного
`night-20260914-001` этих полей нет: старую причину задним числом не восстанавливаем.

Сырые evidence и credentials остаются в игнорируемой `.local-pilot/`; публично
публикуется только проверенная сводка. Наличие старых записей SIGSEGV не означает
новый crash: учитываются время и PID, crash buffer не очищается.

Свежая сводка уже работающего прогона:

```powershell
python -m scripts.pilot.summarize_soak .local-pilot/soak/UNIQUE-RUN
```

Незавершённая строка JSONL учитывается отдельно; `running` не превращается в
`passed`. Исходные события сохраняются для анализа конкретного интервала.

Это прогон двух реальных устройств и основного task/stream пути. VPN, OTA/reboot,
нативный отказ сети, Redis/PostgreSQL faults, n8n, UI-ввод/поиск элементов и
fleet capacity требуют отдельных приёмок. Включённые pipeline controls проверяют
границу шага; early concurrent resume и остановка выполняющегося APK-узла требуют
отдельных сценариев.
