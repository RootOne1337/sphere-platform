# Студия маршрутов: запись, ориентиры и просмотр

Состояние реализации: 28 октября 2026. Студия открывается из карточки устройства
или по адресу `/stream/<device-id>?teach=1`.
На локальном вебе 3015 установлен `sphere-route-local:walk-pilot-20261028-v2`;
автоматическое открытие схемы `fuflo228` проверено в браузере с этой записью.

## Обычный порядок работы

1. Откройте «1 · Запись», подключите поток и выберите способ управления.
   Если играете в LDPlayer, включите «Управляю в эмуляторе · только видео».
   Внешние нажатия в журнал Sphere не попадают.
2. Настройте качество исходной записи и нажмите «Записать маршрут».
   Профиль 30/60 FPS задаёт цель; фактические интервалы кадров измеряются по
   записи. После остановки дождитесь завершения сохранения.
3. Откройте «2 · Сцена» и выберите проход в библиотеке. Для новой записи
   нажмите «Подготовить ориентиры»: эта команда строит камеры и точки без
   длительного плотного рендера и затем запускает подготовку карты.
   Выбор существующей записи сам по себе не запускает повторную реконструкцию.
4. У обработанной записи схема связана с исходным видео. Нажмите на камеру
   мышью или выберите её клавишами Tab/Enter, либо двигайте ползунок ракурсов.
   Рядом отображается соответствующий кадр сохранённого H.264. Ползунок времени
   видео позволяет просматривать и кадры между восстановленными камерами.
5. В «3 · Направление» выберите «Наблюдать без ввода» для показа линии либо
   отдельный «Пеший тест со стиком» для ограниченного живого эксперимента.
   Порядок калибровки и запуска: [пеший пилот](WALK-ROUTE-PILOT.md).
   Сам выбор видео не запускает движение. Повтор A → B в игре ещё не принят.

## Готовая улучшенная схема

Если к заданию прикреплена дополнительная проверенная геометрия, студия
запрашивает её автоматически после выбора записи. JSON вручную выбирать не
нужно. При нескольких схемах доступен переключатель. Основная попытка и
дополнительная схема сохраняются отдельно; 3D-сцена основной попытки не
подменяется новой геометрией.

Для `fuflo228` основная попытка содержит 54 камеры и 8 462 точки. К этому же
заданию прикреплён эксперимент `denseviews-123-v1`: 123 камеры и 22 014 точек.
У обоих результатов тот же источник; все 123 времени улучшенной схемы
проверены по журналу видео. Поэтому новая форма пути отличается от прежней.
На участке около 29–33 секунд остаются предупреждения о качестве оценённых
поз. Улучшенная схема не является проверенной картой дороги.

Ручной импорт оставлен в раскрываемом блоке «Открыть геометрию из файла» как
дополнительный инструмент. Его данные хранятся в памяти страницы.

## Что означают схема и выбранный кадр

- Точки на линии — восстановленные положения камеры; жёлтые точки — признаки
  сцены. Признаки не классифицированы как здания, дорога или препятствия.
- PCA — плоская проекция для просмотра. Координаты не являются метрами;
  положение персонажа относительно камеры отдельно не откалибровано.
- Переход по камере разрешён только при точном совпадении её времени с индексом
  видео и SHA-256 исходного манифеста с источником реконструкции.
- Между соседними камерами с интервалом больше секунды линия не соединяется.
  При перемотке видео подсвечивается ближайшая известная камера с указанием
  разницы времени; новая поза между камерами не интерполируется.
- «Больше точек» повышает лимит отображения с 3 000 до 24 000 существующих
  признаков. Это не повторное восстановление и не создание новых ориентиров.
- При перемотке прежний кадр очищается до декодирования нового; ошибку
  декодера следует устранить, прежде чем оценивать совпадение по изображению.

## Где хранятся данные

Библиотека видео находится в хранилище браузера и разделена по аккаунту.
Открытие другого браузера, профиля или адреса может показать другую библиотеку.
Сохранённые задания реконструкции находятся на ПК в
`.local-pilot/reconstruction-jobs/<job-id>/`. Их доступ защищён ключом задания,
сохранённым рядом с записью. Этот ключ не следует публиковать.

Дополнительная схема лежит в `alternatives/<id>/geometry.json`; квитанция
`receipt.json` связывает SHA исходного манифеста и байтов геометрии. API
`GET /jobs/<id>/geometry-alternatives` и `GET /jobs/<id>/geometry-alternatives/<id>`
проверяет существующий ключ задания. Повреждённая или чужая схема не используется.
Эти методы только читают данные и не запускают обработку.

## Если результата нет или цифры отличаются

Проверьте состояние локального обработчика, выбранный проход и попытку
реконструкции. Старая попытка и улучшенная схема могут содержать разное число
камер. Если видны 54 камеры вместо 123 для `fuflo228`, проверьте установку
актуального веба и обработчика, затем обновите страницу и выберите запись
снова. Повторно запускать рендер для чтения сохранённой схемы не требуется.

Ошибки качества камер, неохваченные интервалы, недостаточные ресурсы и потеря
связи отображаются отдельно. Восстановление файла или красивый график не
подтверждают безопасное автоматическое управление. Подробности экспериментов:
[проверка полного сценария](../audits/2026-10-28/ROUTE-END-TO-END-STATUS.md),
[независимый проход](../audits/2026-10-28/SEQUENCE-CROSS-CAPTURE-CHECK.md).
