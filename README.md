# Sphere Platform

**Единое рабочее пространство для управления Android-устройствами и эмуляторами:**
каталог парка, экран и ручное управление, сценарии, задания и наблюдаемость.
Репозиторий объединяет Web-интерфейс, backend, Android- и PC-агенты, контракты и
эксплуатационные инструкции.

## Для чего нужна платформа

Sphere помогает оператору работать с устройствами как с управляемым парком:
найти нужную группу, открыть экран устройства, подготовить сценарий и проследить
его выполнение. Сервер хранит данные и управляет доставкой команд; агент на
Android выполняет допустимые операции и сообщает результаты.

| Возможность | Что можно делать | Подробнее |
| --- | --- | --- |
| **Парк устройств** | Просматривать устройства, группы, локации и доступное состояние. | [Каталог](docs/operations/DEVICE-CATALOG.md) · [группы](docs/operations/GROUP-HIERARCHY.md) |
| **Экран и управление** | Смотреть поток, открыть карточку устройства и использовать доступные элементы ввода. | [Устройства и потоки](docs/operations/DEVICE-STREAM-GUIDE.md) |
| **Сценарии и задания** | Создавать графы в Script Studio, сохранять версии, запускать задания и изучать результаты. | [Script Studio](docs/operations/SCRIPT-STUDIO.md) · [задания](docs/operations/TASKS-AND-ORCHESTRATION.md) |
| **Оркестрация** | Настраивать pipeline, расписания и связанные события. | [Задания и оркестрация](docs/operations/TASKS-AND-ORCHESTRATION.md) |
| **VPN и интеграции** | Управлять каталогом VPN-профилей и изучать доступные интеграционные контракты. | [VPN](docs/operations/VPN-WEB-GUIDE.md) · [n8n: доставка и повторы](docs/operations/N8N-INTEGRATION.md) |
| **Исследование маршрутов** | Записывать действия и работать с экспериментальными инструментами обучения и навигации. | [Teaching](docs/operations/TEACHING-WEB.md) · [Route Studio](docs/operations/ROUTE-STUDIO.md) |

Доступность действий зависит от роли, версии агента и состояния конкретной
установки. Принятие команды сервером, ответ агента и фактический результат на
устройстве — разные события; проверяйте их по соответствующему руководству.
Экспериментальные и проектные возможности имеют отдельные условия применения.

## Архитектура

```mermaid
flowchart LR
    Browser[Браузер / Web UI] --> API[Backend API]
    API --> DB[(PostgreSQL)]
    API --> Redis[(Redis)]
    API <-->|Команды и результаты| Android[Android Agent]
    API <-->|Управление рабочей станцией| PC[PC Agent]
    Browser <-.->|Видео и ввод при доступном маршруте| Android
```

Схема показывает основные связи, а не точную топологию развёрнутого стенда.
Например, наличие direct-транспорта в исходниках не подтверждает, что прямой
маршрут доступен или включён в конкретной сети. Подробности:
[архитектура](docs/architecture.md), [протокол подключения Android](docs/architecture/ANDROID-CONNECTION-PROTOCOL.md)
и [архитектурные решения](docs/adr/README.md).

## Начало работы

Для переустановки Windows или переноса на SSD используйте
[руководство по запуску и восстановлению](docs/operations/migration-2026-11-02/README.md).
Там описаны автоматическая пустая установка, закрытый экспорт данных и отдельный
импорт прежних баз, маршрутов и настроек. Код и private данные хранятся раздельно.

Выберите сценарий до запуска: **новый изолированный стенд**, **разработка** или
работа с уже существующей установкой. Их конфигурация, порты и данные могут
отличаться.

### Новый изолированный стенд на Windows

1. Подготовьте Git, работающий Docker Desktop с Linux containers и PowerShell
   5.1 или новее. Нужен Compose 2.24.4 или новее и минимум 20 GiB свободного
   места для сборки; Python и Node для сервера устанавливаются внутри образов.
2. Склонируйте репозиторий и выберите нужную ветку или revision:

   ```powershell
   git clone --branch codex/enterprise-audit-20260905 --single-branch https://github.com/RootOne1337/sphere-platform.git
   cd sphere-platform
   ```

3. Создайте новый изолированный стенд и первого администратора:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/migration/new-install.ps1 -Mode New -AdminEmail owner@example.com
   ```

   Замените email на свой. Launcher создаёт отдельные тома и случайные секреты,
   применяет миграции и проверяет API login. Пароль находится в приватном
   `admin.env`, путь выводится в конце. Повторный запуск `New` создаёт ещё один
   стенд; управление уже созданным и импорт старых данных описаны в
   [руководстве переноса](docs/operations/migration-2026-11-02/README.md).
4. Откройте `http://127.0.0.1:28080/login`. Затем отдельно
   подтвердите подключение нужного агента, конечный результат тестового задания и
   получение кадра. Health endpoint не заменяет эту проверку.

Проверка production-развёртывания дополнительно включает роли и права базы,
резервное копирование, сетевой доступ, TLS и фактическую установку агентов.
[Startup](docs/operations/STARTUP.md) · [Deployment](docs/deployment.md) ·
[Runbooks](docs/runbooks/README.md)

### Разработка и документация

Основные версии CI: Python 3.12 для backend и PC Agent, Node.js 24 для frontend,
JDK 17 и Android SDK для Android. Точные команды и настройка тестовой среды —
в [руководстве разработчика](docs/development.md); вклад и review — в
[CONTRIBUTING](CONTRIBUTING.md).

Ниже — автономные проверки документации из корня checkout; они не запускают
устройства или сервисы:

```bash
python -m scripts.check_documentation_status
python -m unittest discover -s tests -p 'test_documentation*.py'
```

Проверки контролируют инвентарь, часть ссылок и другие ограниченные контракты,
но не устанавливают достоверность каждого утверждения. Чтобы найти документы,
которые стоит пересмотреть после изменения кода, используйте
[процесс обновления](docs/operations/DOCUMENTATION-WORKFLOW.md).
